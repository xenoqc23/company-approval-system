# Xenosys 사내결재시스템

**NAS 설치용 구성과 PC 검토 실행을 함께 제공합니다.** NAS는 Docker/Gunicorn/전용 MariaDB로 운영하며 샘플 직원·문서 없이 시작합니다. 프로그램 업데이트 시 DB·설정·백업은 별도 보관됩니다. 아래 PC 실행은 기존 SQLite 검토용입니다.

- NAS 설치: [처음 읽기](NAS_처음읽기.md) · [설치·업데이트·백업·복구 안내](docs/NAS_INSTALL.md)
- 배포 구성: [Docker 설정](deploy/nas/compose.yml) · [NAS 명령](deploy/nas/nas.sh)
- 실제 NAS 설치·HTTPS·예약 백업·사용자 PC 인수 점검은 설치 안내에 따라 별도로 진행합니다.

기존 Streamlit `app.py`, `approval_data.csv`는 이전 자료입니다. 새 시안은 `manage.py`로 실행하며 기존 CSV를 사용하지 않습니다.

## PC 검토 실행

**NAS 연동 전 최신 검토본은 `setup.bat`·`run.bat` 방식으로 실행합니다.**
[최신 Windows 실행용 ZIP](https://github.com/xenoqc23/company-approval-system/archive/refs/heads/prototype/pc-demo-20261008.zip)을 내려받아 모두 압축을 풀어 주세요.
처음에는 [START_HERE.txt](START_HERE.txt), 기존 프로그램 업데이트는 [UPDATE_WINDOWS.txt](UPDATE_WINDOWS.txt)를 따릅니다.
Windows에서는 Python 설치 후 `setup.bat`으로 설치하고 `run.bat`으로 실행합니다.

다른 Windows PC로 프로그램과 데이터를 복사해 시연할 때는 [MOVE_TO_OTHER_PC.txt](MOVE_TO_OTHER_PC.txt)를 따릅니다. 복사한 `.venv`는 제거하고 새 PC에서 다시 설치하며, 기존 계정·기안을 유지하려면 `var`를 함께 복사합니다.
실행 도우미는 NAS 설정을 사용하지 않고 본인 PC의 테스트 DB로 실행합니다.
Mac/Linux에서는 `python3 launcher.py setup`, `python3 launcher.py run`을 사용합니다.

Python 3.10 이상에서 저장소 폴더로 이동한 뒤 실행합니다.

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-prototype.txt
.venv/bin/python manage.py migrate
.venv/bin/python manage.py seed_demo
.venv/bin/python manage.py runserver 0.0.0.0:8000
```

`seed_demo`는 초기 비밀번호를 숨김 입력으로 받습니다. 직원 8명과 문서 9건을 만들고, 기존 계정이 있으면 데이터를 추가하거나 초기화하지 않습니다. 서버를 실행한 PC의 브라우저에서 8000번 포트에 접속합니다. 다른 사내 PC에서 볼 때는 서버 PC의 사내 IP와 8000번 포트를 사용합니다.

현재 클라우드 시안은 사용자 요청의 초기 비밀번호로 준비했습니다. `admin`은 처음 로그인하면 비밀번호를 변경해야 합니다. 예시 직원은 같은 초기 비밀번호를 사용합니다. 이 가상 계정과 개발 서버는 화면 검토용이며 실운영 계정으로 사용하지 않습니다.

| 아이디 | 가상 직원 | 역할 |
| --- | --- | --- |
| employee | 이서연 / 개발팀 대리 | 일반 직원·기안자 |
| reviewer | 김민준 / 개발팀 팀장 | 예시 기안의 검토자 |
| approver | 박지훈 / 전략기획팀 이사 | 예시 기안의 최종 승인자 |
| accounting | 정유진 / 인사팀 과장 | 연차 관리·최종 문서 조회·구매/발주 처리 |
| admin | 관리자 | 가입 승인·부서/직급·개별 업무 권한·전체 문서·시안 백업 |
| quality / production / sales | 품질팀 / 생산팀 / 영업팀 예시 직원 | 일반 직원 |

직급이나 부서는 업무 권한을 자동으로 부여하지 않습니다. 새 결재선의 검토자·승인자는 admin 계정 및 admin 권한 계정을 제외한 주임 이상 활성 직원만 지정합니다. 부서 선택 후 해당 부서의 직원을 선택하며, 서버에서도 같은 조건을 검사합니다. 기안자가 이 조건을 만족하면 본인 지정도 가능합니다. 기존 제출 문서의 담당자와 이력은 유지합니다.

## 구현한 흐름

- 휴가원·사무용품: 기안자 → 검토자 → 최종 승인자. 본인 또는 동일인 지정도 두 번의 처리가 필요합니다.
- 생산 재고 요청: 요청자 → 검토 완료 → 발주 담당자의 발주 처리 → 지정 수령자의 입고 확인. 최종 승인자·단가·총가격은 없습니다. 생산 재고 요청함에서 검토/발주/입고 상태를 확인합니다.
- 임시저장·이어쓰기, 제출 후 수정 금지, 검토 전 기안자 삭제, 반려함, 반려/취소 문서 복사 재기안.
- 연차 날짜 범위, 반차·외출 시간 선택, 주말 제외, 시간 중복 차단. 연차 1일·반차 0.5일·외출 0.25일입니다. 공휴일·대체공휴일은 직원 일정에 표시하며, 휴가 차감 계산에서는 토·일만 제외합니다.
- 최종 승인 때 차감하고 최종 승인자 취소 때 원래 연도의 실제 차감량을 복원합니다. 잔여가 음수여도 제출할 수 있습니다. 입사일을 기준으로 매년 1월 1일 총연차를 자동 산정합니다. 이월은 없으며 기존 차감과 수동 수정은 보존합니다.
- 경리가 총/사용/잔여 연차를 사유와 함께 수정하고 이력을 보관합니다. 연차규정 표와 원문을 조회·수정할 수 있습니다. 예외 규정은 안내이며 연차 면제 등 별도 자동 처리 기능은 아닙니다.
- 사무용품 구매는 기안당 품목 1개, 수량×단가(소수점 2자리), 구매 링크를 사용합니다. 생산 재고 요청은 품목·수량만 입력합니다. 두 문서 모두 긴급도와 선택 사유/필요 날짜를 사용합니다.
- 사무용품은 결재완료 → 구매 → 배송완료, 생산 재고는 검토완료 → 발주대기 → 입고대기 → 입고완료입니다. 구매·발주 처리 권한을 받은 직원은 별도의 전체 경리 조회 권한 없이도 검토가 끝난 재고 요청을 볼 수 있습니다.
- 생산 재고는 검토를 완료한 본인만 검토 완료를 취소할 수 있습니다. 취소 후 후속 발주/입고 처리는 중단됩니다.
- 권한별 메뉴와 서버 검사, 가입 승인 대기, 초기/임시 비밀번호 변경, 비활성 직원 제외, 미처리 결재 담당자 재지정.
- 회원가입·비밀번호 변경은 숫자만으로도 4자 이상이면 허용합니다. 직원은 내 계정에서 현재 비밀번호 확인 후 본인의 비밀번호만 변경하며 로그인 상태는 유지됩니다.
- 관리자 직원 관리는 미분류 계정 및 6개 부서별 탭으로 구분합니다. 처음 가입한 계정은 관리자 확인·저장 전까지 미분류로 표시하고, 저장 후 부서별로 이동합니다. 이미 분류된 직원의 가입 승인을 해제해도 미분류로 이동하지 않습니다.
- 경리 최종 승인 문서함은 전체·휴가원·구매요청서·생산 재고 요청 탭으로 나누고 처음에는 전체를 표시합니다. 각 탭의 검색·날짜 필터를 유지하며, 취소 문서는 조회할 수 없습니다. 생산 재고 탭에는 검토 완료된 요청을 표시합니다.
- 문서 상세에서 검토확인·승인확인을 누르면 저장 성공 후 완료 팝업을 표시합니다. 확인된 단계는 초록색 체크 표시로 강조하고 본인이 처리한 단계에는 내가 확인함과 확인 완료 표시를 남깁니다. 취소한 단계는 검토취소·승인취소로 표시하고 중복 클릭을 막습니다.
- 시스템 알림함·읽음 처리·현재 조회 권한 검사, 변경 이력, 검색과 종류/상태/날짜/물품 상태 필터. 부서 선택은 직원별 연차 관리에 제공합니다.
- SQLite 시안 DB의 관리자 수동 백업·복원과 실패 알림. 과거 버전 백업은 별도 복사본을 현재 스키마로 준비한 뒤 복원합니다. 복원 전에 현재 DB도 자동 백업합니다.

연도별 연차 기록은 기존 차감과 복원을 추적하기 위한 것입니다. 경리는 연도별 값을 직접 입력합니다. 삭제는 일반 목록에서 숨기고 관리자와 변경 이력에는 남기는 방식입니다. 외부 쇼핑몰의 링크는 예시 주소입니다.

## 테스트

```bash
.venv/bin/python manage.py check
.venv/bin/python manage.py test workflow
```

테스트는 별도 임시 DB에서 진행합니다. 최종 승인/취소의 중복 처리, 권한 우회, 연도 경계 복원, 중복 시간, 자기 결재, 문서 수정/삭제 제한, 취소 문서의 경리 접근, 수령자 제한, 재기안, 수동 연차 수정, 가입 승인, 초기 비밀번호 변경, CSRF 및 화면 렌더링을 확인합니다.

## MariaDB 연결 준비

실제 NAS 구축·기존 DB 연결은 아직 수행하지 않았습니다. 새 프로젝트 전용 DB를 준비한 뒤 호환 버전을 확인하고 아래 환경변수를 설정할 수 있습니다. 비밀번호를 소스에 저장하지 않습니다. 환경변수 파일은 자동으로 로드되지 않으므로 실행 환경에서 주입해야 합니다.

```bash
.venv/bin/python -m pip install -r requirements-mariadb.txt
```

| 환경변수 | 용도 |
| --- | --- |
| DB_ENGINE=mariadb | MariaDB 사용 |
| DB_NAME, DB_USER, DB_PASSWORD | 프로젝트 DB 및 전용 계정 |
| DB_HOST, DB_PORT | NAS DB 주소, 기본 포트 3306 |
| DJANGO_SECRET_KEY | 운영 전용 무작위 비밀키 |
| DJANGO_DEBUG=0 | 운영 오류 상세 표시 끄기 |
| DJANGO_ALLOWED_HOSTS | 실제 사내 접속 호스트, 쉼표 구분 |
| APPROVAL_DATA_DIR | 로컬 데이터·시안 백업 폴더, 기본 `var` |

MariaDB 드라이버에는 서버의 MariaDB/MySQL 개발 라이브러리가 필요할 수 있습니다. 이 설정의 실제 NAS 연결, 동시 처리와 복구는 운영 전 별도로 검증해야 합니다. 시안의 SQLite 백업 버튼은 MariaDB 백업을 실행하지 않습니다.

## 다음 운영 작업

NAS에서는 개발 서버 대신 운영용 웹 서버와 정적 파일 처리가 필요합니다. 사내 접속 주소·HTTPS·비밀키·실제 직원 계정도 별도로 구성합니다. 합의한 매일 백업 30개 / 월간 백업 12개 보관 및 NAS 외부 사본은 NAS 작업 스케줄러에 연결해야 하며 이번 시안에는 스케줄러가 포함되지 않습니다. 운영 복구는 서비스 중지 후 복구·확인·재시작 절차로 검증합니다.

입사일이 입력된 직원은 실행 또는 새 연도 첫 접속 시 연차를 자동 갱신합니다. NAS에서 시간에 맞춰 실행하려면 작업 스케줄러에 `manage.py sync_annual_grants`를 매일 등록합니다. 같은 연도에 다시 실행해도 총연차의 수동 수정값이나 사용연차를 덮어쓰지 않습니다.

현재 시안에는 파일 첨부와 외부 메일·메신저 알림을 넣지 않았습니다. 화면·업무 흐름 검토 후 필요한 수정과 운영 연결을 진행하면 됩니다.

## 이번 시안 업데이트

본문은 14.5px, 입력 글자는 14px로 처음 화면과 확대 화면의 중간 크기로 조정하고 진한 글자색을 유지했습니다. 일반 직원도 생산 재고 요청함에서 본인과 관련된 요청을 볼 수 있습니다. 발주 담당자는 관리자 화면의 구매·발주 처리 권한으로 지정합니다.

기존 생산 재고 문서 중 검토가 기록된 최종승인대기 문서는 업데이트 시 발주대기로 전환됩니다. 기존 승인·발주 이력과 문서번호는 보관하며, 전환 내역은 시스템 변경 이력에 남습니다. 설치 도우미는 DB 갱신 전에 기존 DB를 var/backups에 백업합니다. 이전 업무 흐름으로 되돌릴 경우 그 백업으로 복구해야 합니다.

Windows에서 기존 프로그램을 업데이트하는 방법은 UPDATE_WINDOWS.txt에 있습니다.

부서 필터는 직원별 연차 관리에만 표시하며 일반 문서함에서는 제거했습니다. 직원·결재자·수령자·문서 목록은 직급이 높은 순서로 정렬하며, 같은 직급은 이름순으로 표시합니다. 문서 목록에서 같은 기안자의 문서는 최신순으로 표시하고 처리 이력은 시간순을 유지합니다.

경리의 최종 승인 문서함 → 구매요청서에는 체크박스와 선택 문서 엑셀 다운로드가 있습니다. 현재 표시된 문서 중 선택한 것만 성명·품명·수량·단가·총가격·신청사유 6개 항목으로 내려받습니다. 단가와 총가격은 숫자 셀이며, 제품명과 사유는 수식으로 실행되지 않도록 텍스트로 저장합니다. 서버에서 경리 조회 권한, 사무·사내용품 종류, 최종 승인 상태를 재확인하며 취소되었거나 유효하지 않은 문서가 포함된 요청은 전체 거절합니다. 다운로드는 구매·배송 상태를 바꾸지 않고 변경 이력에 남습니다. 엑셀 라이브러리 openpyxl은 setup.bat에서 설치됩니다.

최종 승인 문서함은 전체 탭을 기본으로 열고 휴가원·구매요청서·생산 재고 요청을 함께 표시합니다. 처음 메뉴를 열 때 확인하지 않은 문서가 있는 탭은 주황색 배경으로 강조합니다. 종류별 탭을 열면 그 종류만 확인하고 전체 탭을 열면 모든 종류를 확인합니다. 확인 시점은 AccountingReadState에 계정별로 저장하여 다시 로그인해도 유지합니다. 화면이 보이는 동안 15초마다 탭의 건수와 새 문서 표시를 갱신하며 자동 조회는 확인 처리하지 않습니다. 새로 최종 승인되거나 검토가 완료된 생산 재고 요청은 다시 강조하며 취소 문서는 제외합니다. 구매요청서 엑셀의 단가·총가격은 #,##0 형식으로 표시하고 원본 숫자는 유지합니다. 업데이트 설치 도우미는 DB 백업 후 새 확인 상태 테이블을 추가합니다.

알림함과 대시보드 최근 알림은 기안자 성명 - 직급 - 문서 종류 - 처리 상태로 표시합니다. 알림 생성 시점의 성명·직급·종류와 이벤트 상태를 별도 저장하여 직원 정보나 문서의 현재 상태가 바뀌어도 이전 알림을 유지합니다. 검토 요청은 검토대기, 검토 완료 후 기안자에게는 검토완료, 최종 승인자에게는 승인대기, 승인 후에는 승인완료로 표시합니다. 기안자와 승인자가 같으면 검토완료 · 승인대기를 한 알림에 표시합니다. 생산 재고 검토는 검토완료로 표시하고, 사무용품 구매·수령은 배송중·배송완료, 생산 재고 발주·수령은 입고대기·입고완료로 표시합니다. 반려·취소 사유는 별도 줄로 표시합니다. 기존 알림의 성명·직급은 변환 시점에 확인 가능한 직원 정보를 사용합니다. 마이그레이션 0006은 기존 메시지에서 이벤트를 판별해 형식을 변환하며 원문·날짜·읽음 여부를 보존합니다. 판별할 수 없는 메시지와 문서 없는 시스템 알림은 원문을 유지합니다.

경리 알림 범위는 최종 승인 문서 조회(view_accounting) 권한을 기준으로 적용합니다. 경리는 본인 휴가원·사무용품 구매 기안의 진행 알림을 유지하고, 다른 직원의 휴가원·구매요청서에서는 승인완료·배송완료만 표시합니다. 생산 재고는 경리 본인 기안을 포함해 모든 단계의 알림을 제외합니다. 다른 직원의 대기·배송중·입고대기·취소 알림은 발송하지 않습니다. 기존 알림은 삭제하지 않고 같은 조건으로 알림함·대시보드·미확인 건수·읽음 처리 대상에서 제외합니다. 다른 직원의 문서가 취소되면 이전 완료 알림도 표시하지 않습니다. 경리 권한이 없는 직원과 별도의 발주 담당자 알림 범위는 유지합니다.

직원별 연차 관리의 엑셀 다운로드는 현재 선택한 연도·부서의 승인된 계정들을 직급순으로 내보냅니다. 연도·성명·부서·직급·총연차·사용연차·잔여연차를 저장하며 소수 연차와 음수 잔여를 보존합니다. 직원 이름의 수식 문자는 텍스트로 저장합니다. manage_leave 권한이 서버에서 강제되고 다운로드는 POST/CSRF 보호와 변경 이력 기록을 사용합니다. 직원 이름을 누르면 선택 연도의 승인된 휴가와 전체 신청 이력(임시저장·삭제 제외)을 조회합니다. 휴가 날짜·시간·종류·해당 연도의 차감·결재 상태를 표시하며 취소·반려·대기는 차감 합계에서 제외합니다. 연도를 넘긴 승인 휴가는 저장된 allocations에서 해당 연도만 표시합니다. 전체 문서를 볼 권한이 없어도 연차 관리 권한으로 날짜·종류·차감 이력은 조회할 수 있으며 문서 상세 링크는 별도의 기존 조회 권한이 있을 때만 표시합니다. 연도별 수동 수정 이력은 실제 사용 날짜와 구분하며 사용연차 현황과 문서 합계가 다를 수 있음을 안내합니다. 기안 없는 휴가의 실제 날짜를 새로 추정하지 않습니다.

## 결재 진행 상태 — 여러 기안 선택

홈의 결재 진행 상태에 **진행 중 N건**과 **확인할 기안 선택** 목록을 추가했습니다. 진행 중은 검토대기·최종승인대기 기안 수입니다. 목록은 진행 중과 처리 완료·종료 두 그룹으로 구분하며 휴가 날짜/품명, 상태, 문서번호를 함께 표시합니다. 본인의 임시저장·삭제 문서는 목록에서 제외합니다.

선택 즉시 해당 문서의 결재 단계와 상세보기 링크가 바뀝니다. 최근 문서 종류 탭을 눌러도 선택을 유지합니다. 진행 중인 기안이 없으면 0건으로 표시하고 최신 기안을 기본으로 보여줍니다. 타인 문서나 유효하지 않은 번호를 지정하면 본인의 기본 기안으로 돌아갑니다.

검증: 홈 기능 시험 15건 통과. 실제 브라우저에서 여러 문서 전환, 선택 유지, 1080/1280/1366/1440/1920px 배치를 확인했습니다.

## NAS 연동 전 최종 PC 검토본 — 전결·규정 관리

[Windows 실행용 ZIP](https://github.com/xenoqc23/company-approval-system/archive/refs/heads/prototype/pc-demo-20261008.zip)을 모두 압축 해제하고 기존 방식대로 **setup.bat → run.bat**을 실행합니다. 기존 사용자는 [UPDATE_WINDOWS.txt](UPDATE_WINDOWS.txt) 순서로 업데이트하며 **var와 .venv를 유지**합니다. setup은 DB를 백업하고 마이그레이션 0009를 적용합니다. 기존 계정·문서를 초기화하지 않습니다.

- 홈의 결재 진행 상태는 **진행 중인 본인 기안만** 선택할 수 있습니다. 0건이면 안내만 표시합니다.
- **규정 관리 → 전결규정**에서 경리·admin이 문서·금액·직급별 경로를 설정하고 미리보기로 확인합니다. 사용 중인 규정의 조건이 겹치면 저장하지 않습니다.
- 초기 사용 규정: **구매 10만원 이하 → 승인만 / 주임~부장**, **부장 휴가원 → 검토 생략**. 기안자≤검토자≤승인자 조건과 기존 자격도 함께 적용하며, 자격을 충족하면 본인 승인도 가능합니다. 제출과 승인은 별도 동작입니다.
- 검토 생략 문서는 승인 전 기안자가 삭제할 수 있습니다. 휴가원은 최종 승인 시 차감하고 최종 승인자 취소 시 원래 차감을 복원합니다. 이미 제출한 기존 문서는 기존 경로를 유지합니다.
- **규정 관리 → 연차규정·경조사비·장기근속 포상**은 경리가 편집합니다. admin 기본 권한은 전결규정 편집이며, 일반 직원은 직원복지에서 조회합니다.
- 연차규정은 **적용 시작 연도**별로 관리하며 직원 안내와 총연차 자동산정에 같은 일수표를 사용합니다. 규정 저장만으로 기존 직원의 올해 총연차를 덮어쓰지 않습니다.
- **직원별 연차 관리 → 총연차 재계산**에서 변경 전후를 확인하고 직원을 선택해 적용합니다. 기존 값은 보존하며 수동값 대체 확인이 필요합니다. 최신 사용연차와 공용연차를 유지합니다.
- 입사일 미등록자는 자동산정 대기로 표시합니다. 공용연차는 **입사일 당일 이후의 휴무만** 차감하고, 입사일 저장·정정 시 등록 휴무를 재확인합니다. 같은 휴무를 중복 차감하지 않습니다.
- 공용연차와 승인된 개인 휴가의 겹침을 안내합니다. 개인 휴가를 자동 취소하지 않으며 기존 최종 승인자의 취소 절차를 사용합니다.

**미확정 규칙:** 10만원 초과~100만원 이하 규정 예시는 ‘사용 안 함’ 상태입니다. 직급 범위를 확인한 뒤 사용하세요. 미등록 구간은 기존 기본 경로를 유지합니다. 100만원 초과 전결 및 적격 승인자 부재 시의 별도 예외 처리는 보류 상태이며 임의의 대체 승인자를 지정하지 않습니다.

검증: 기능 시험 **111건** 통과, Chromium **90개 화면/너비 조합** 및 실제 두 단계/세 단계 결재·선택 재계산·공용연차 복원 확인. 기존 DB 복사본과 실제 설치 도우미 업데이트에서 **8개 업무/계정 테이블의 기존 열 값 보존**을 확인했습니다. 실행 도우미는 Linux에서 확인했으며 실제 Windows PC와 NAS/MariaDB 실운영은 별도 검증 대상입니다.
