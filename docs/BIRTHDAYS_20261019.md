# 생일자와 종무식 포상 안내

직원복지의 첫 탭을 생일자로 추가한다. 이번 달이 기본이며 다음 달 바로가기와
연도·1~12월 직접 조회를 제공한다. 표시 날짜는 조회하는 양력 달을 기준으로 정렬한다.
양력·음력 원본 월·일만 보관하고 출생연도·나이는 수집하지 않는다.
승인·재직·부서 확정 직원만 표시하며 admin·최고관리자 계정은 제외한다.

당일 생일자는 ‘오늘 생일’로 강조한다. 모든 직원의 홈 제목 옆에 생일자 이름과
축하 문구·케이크 SVG를 표시하며, 대상이 없는 날에는 카드를 표시하지 않는다.
동명이인·동일 날짜 여러 인원도 각각 직원 정보로 조회한다.

가입 신청에는 생일 기준·월·일을 필수로 추가하되 기존 가입 승인 절차는 유지한다.
기존 직원은 임의 생일을 채우지 않고 미등록으로 둔다.
연차 관리 담당자는 직원별 연차 관리의 ‘입사일·생일·연차 관리’에서 생일만 저장·정정·제거한다.
미등록 직원 목록과 입력 화면 바로가기는 해당 담당자에게만 제공한다.
POST·CSRF·서버 권한 검사를 적용하며 Profile을 잠그고 생일 필드만 저장한다.
수정 이력에는 양력·음력 구분과 원래 월·일을 기록한다.

## 한국 음력

`korean-lunar-calendar==0.4.0`을 이미지에 포함하고 외부 API 없이 변환한다.
매 조회 연도에 다시 계산하며, 양력 1~2월에 들어오는 전년도 음력 12월도 함께 확인한다.
입력한 음력 윤달이 없는 해에는 같은 평달, 30일이 없는 달에는 29일을 사용한다.
이는 사용자가 확인한 처리 방식이다. 원래 월·일과 윤달 여부는 유지한다.
지원하는 양력 조회 범위는 1001~2050년이며 범위 밖 조회에는 안내한다.
양력 2월 29일은 윤년에 해당 날짜가 있을 때 표시한다.
날짜 변환 결과는 입력값·음력 연도별로 캐시하지만 직원 정보는 캐시에 넣지 않는다.

참조 검증 날짜: 음력 2026-01-01→양력2026-02-17,
2026-09-09→2026-10-19, 2025윤6월1일→2025-07-25,
2026윤6월 생일→평달2026-07-14,
2026음력2월30일→그달29일인2026-04-16,
2025음력12월1일→2026-01-19.

## 종무식 포상

장기근속 대상자는 실제 입사기념일로 계속 산정한다. ‘구분’을 ‘포상 안내’로 바꾸고
올해·향후 연도에는 ‘연말 종무식 포상 예정’, 과거 조회에는 ‘연말 종무식 일괄 포상’으로 표시한다.
대상일 도래 여부를 실제 지급 완료 여부로 해석하지 않는다. 대상자·포상표는 변경하지 않는다.

## NAS 패치와 보존

0015는 Profile에 필드 네 개와 생일 유효성 제약을 추가할 뿐 기존 데이터를 갱신하지 않는다.
출생연도 필드나 예시 생일 데이터, 결재·연차 변경은 포함하지 않는다.
누적 NAS ZIP에는 이전 공통 규정 및 입사연도별 연차 산정 소스·마이그레이션도 포함한다.
이미 반영된 마이그레이션은 재실행하지 않는다. 선행 0011이 필요하다.
0014가 미반영이면 기존에 요청·승인한 입사연도별 산정도 한 번 적용된다.
0014는 수동 총연차·기존 사용·과거 연도 잔액을 보존한다.
기존 NAS .env·DB·직원 정보는 패키지에 포함하지 않는다.
소스 백업과 기존 nas.sh의 이전 이미지 DB 백업이 끝난 뒤 변경을 적용한다.

검증: Django 전체221개(일반 DB209통과/행잠금12건건너뜀), MariaDB10.11.14 전체221통과,
설치 스크립트7개 통과, 실제 브라우저320/390/768/1366px에서
회원가입 입력·담당자의 양력/음력 저장·오늘 표시·복수 이름 축하·월별 필터·미등록 권한·포상 안내 검증.
실제0014→0015 이행 테스트로 기존 직원·암호·연차·사용내역·문서·규정·이력의 보존을 확인했다.
