# 공통 전결규정과 이력을 보존하는 삭제

규정관리의 문서 종류에 **모든 문서**를 추가하고 새 규정의 기본값으로 설정합니다.
하나의 공통 규정으로 휴가원·사무/사내용품 구매·생산 재고의 결재 담당자와 과장급 이상에게 허용한 검토 생략·본인 전결을 관리합니다.

기존 문서별 규정은 자동으로 공통 규정으로 바꾸지 않습니다. 직원별 → 부서별 → 직급별 → 회사 기본 우선순위를 유지하며, 같은 대상 우선순위에서는 해당 문서별 규정이 공통 규정보다 우선합니다. 같은 문서 범위·대상 우선순위에서 조건이 겹치면 저장과 실제 제출을 차단합니다.

공통 규정의 금액 조건은 구매요청서에만 적용합니다. 휴가·재고는 금액 조건 없이 해당 대상 규정을 사용하므로, 같은 대상에 공통 규정을 금액 구간만 달리하여 중복 등록할 수 없습니다.

## 생산 재고의 공통 결재

사용자가 생산 재고에도 공통 검토·승인 및 간소결재 적용을 선택했습니다.

| 공통 규정의 결재방식 | 새 재고 문서의 순서 |
| --- | --- |
| 규정 기본 | 기안 → 검토 → 최종 승인 → 발주 → 입고 |
| 검토 생략 | 기안 → 최종 승인 → 발주 → 입고 |
| 본인 전결 | 제출 시 본인 전결 완료 → 발주 → 입고 |

규정 기본 경로에 검토 생략이 설정되어 있으면 해당 기본 경로를 따릅니다.
과장급 이상 자격과 문서·대상·금액별 명시적 허용 조건은 기존 간소결재 기능과 동일합니다.
기안 화면·서버 검증·미결 집계·담당자 알림·홈 진행 상태·상세 진행 단계·재고 결재대기 목록을 같은 경로로 연결했습니다.
회계 권한이 있는 직원도 새 공통 재고의 담당자로 지정되면 해당 결재 알림을 볼 수 있습니다.

이미 제출된 재고 문서는 저장된 경로를 유지합니다. 기존 검토만으로 완료되던 재고 문서에 최종 승인을 소급 추가하지 않습니다.
새 공통 경로는 제출 당시 스냅샷에 보관하므로 이후 규정 수정·삭제에도 진행 중인 문서의 경로를 바꾸지 않습니다.
공통 규정이 적용되지 않는 재고 문서는 기존 검토 → 발주 경로를 사용합니다.

## 전결규정 삭제

전결규정 목록의 **삭제**를 누르고 확인하면 목록과 새 기안 적용 대상에서 제외합니다.
규정 내용·직원 연결·삭제자·삭제 시각·삭제 전 내용·변경 버전을 보관합니다.
이미 제출한 문서는 기존 규정 스냅샷으로 계속 처리합니다. 다른 창에서 열어 둔 삭제 규정을 다시 저장하여 되살릴 수 없습니다.

규정관리 권한이 있는 직원만 삭제할 수 있습니다. POST·CSRF 검증과 확인창을 적용하며 GET으로 삭제하지 않습니다.
규정 변경·삭제·제출은 기존 규정 잠금으로 직렬화합니다.

## 반려 문서 삭제

본인이 기안한 반려 문서의 상세 화면에서 **기안 삭제**를 누르면 일반 목록·반려함에서 제외합니다.
문서 원본·반려 사유·결재 이력·삭제 기록을 보관하며 연차 잔액을 변경하지 않습니다.
다른 직원의 문서나 최종 결재가 완료된 문서에 대한 삭제 권한을 추가하지 않습니다.
기존 임시저장·검토대기 및 검토 생략 문서의 승인 전 삭제 조건은 유지합니다.

## NAS 적용

ZIP을 File Station **/docker/company-approval**에 업로드하고 **여기에 압축 풀기**를 선택합니다.
Windows PowerShell에서 실행합니다.

```powershell
ssh -t admin@192.168.1.46 "sudo sh /volume1/docker/company-approval/xenosys-common-rules-20261019/APPLY_COMMON_RULES.sh"
```

마지막 **COMMON_RULES_READY** 확인 후 PC·휴대폰 사이트를 새로고침합니다.
규정관리에서 **모든 문서**를 선택하고 대상·담당자·간소결재 허용과 **규정 사용**을 지정해 저장합니다.
기존 문서별 규정이 우선 적용되는 경우 해당 규정을 수정·사용 해제·삭제하여 정리할 수 있습니다.

ZIP은 이전 간소결재 0012와 이번 0013을 포함합니다. 기존 소스를 `.common-rules-backup.*`에 보관하고 기존 NAS 업데이트 절차로 이전 이미지에서 DB 백업을 완료한 후 필요한 마이그레이션·웹 전환을 수행합니다.
0013은 삭제 기록 필드와 문서 범위 선택지를 추가하며 기존 규정 종류·권한·문서 경로·잔액을 일괄 변경하지 않습니다.
연차 산정 코드·과거 연차 변경 마이그레이션·.env·암호·실제 DB는 ZIP에 포함하지 않습니다.
웹 접속이 잠시 중단되며 실패 시 READY를 표시하지 않고 보관본을 남깁니다. 오류 후 app/data 삭제·재설치·임의 DB 복원을 하지 않습니다.
실제 NAS에는 사용자가 위 명령을 실행한 후 적용됩니다.

## 검증

- SQLite 전체 202개: 190개 통과, 실제 DB 행 잠금 전용 12개 제외.
- 별도 MariaDB 10.11.14: 전체 202개 통과.
- 0012→0013 실제 마이그레이션에서 기존 문서별 규정·간소결재 권한·문서 스냅샷·연차 및 사용내역·정책·이력 보존 검증.
- 공통 규정 3종 적용, 범위 우선순위·금액 경계, 재고 정상/검토 생략/본인 전결과 발주 차단·승인·입고, 회계 역할 담당자 알림 검증.
- 규정 삭제의 권한·CSRF·반복 요청·이력·직원 연결 보존·이전 수정창 재저장 차단, 규정 삭제와 전결 제출의 실제 동시 처리 검증.
- 휴가·구매·재고의 검토/승인 단계 반려 및 본인 삭제, 타인 삭제·완료 문서 삭제 거부와 잔액/반려 사유 보존 검증.
- 설치기 7개 안전성 검증: 허용 파일만 복사·원본/데이터 보존, 손상 업로드, 진행 중 작업, 선행 기능/스키마 누락, DB 백업 지원, 실패 처리.
- Chromium 320·390·768·1366px: 실제 규정 생성·공통 3종 미리보기·재고 경로·전결·규정 삭제 확인창·삭제 후 기존 문서 결재·반려 문서 삭제·가로 넘침/JS/정적 파일 오류 없음.

가상 계정과 분리된 테스트 DB만 사용했으며 실제 NAS 데이터에 접근하거나 가져오지 않았습니다.
