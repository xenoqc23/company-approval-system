# 연차 엑셀: 공용연차와 간단 사용내역

직원별 연차 관리의 기존 ‘엑셀 다운로드’를 확장했다.

- `2026년 연차 현황`처럼 선택 연도에 해당하는 첫 시트에 **공용연차** 일수와 **사용내역** 열을 추가한다.
- `인원별 연차표`에도 **사용내역**을 추가하고, 기존 ‘공통사용연차’ 제목을 ‘공용연차’로 통일한다.
- 사용내역 예: `10/16(연차), 10/9(공용연차), 9/1(반차), 8/28(외출)`.
- 오전·오후반차는 ‘반차’로 표시한다. 여러 날의 연차는 주말을 제외한 사용 날짜별로 표시한다.
- 결재 완료 휴가, 취소하지 않은 경리 직접 등록, 활성 공용연차 차감을 합친다.
- 조회 연도에 해당하는 사용 날짜만 최근 날짜 순으로 표시한다. 부서 필터도 기존대로 적용한다.
- 이미 차감된 사용 예정 휴가도 포함한다. 취소·반려·검토/승인 대기·임시저장·삭제 건은 제외한다.
- 날짜를 알 수 없는 기존 잔액 정정으로 사용내역을 만들지 않는다. 정정분 때문에 합계와 차이가 날 수 있다.
- 사유·시간·결재자·등록자 등은 사용내역에 넣지 않는다. 내역이 없으면 ‘—’로 표시한다.
- 셀 자동 줄바꿈·행 높이 조정, 공용연차 소수 일수 서식, 필터와 첫 행 고정을 적용한다.
- 직원별로 조회하지 않고 문서·직접 등록·공용연차 내역을 각각 한 번씩 조회한다.

기존 연차 산정 기준과 잔액 계산은 유지한다. 엑셀 생성이 연차 값을 바꾸지 않는다.

## NAS 업데이트

묶음: `releases/xenosys-leave-excel-20261016.zip`.
직전의 연차 사용 직접 등록 기능과 신규 테이블 마이그레이션도 포함한다.
직접 등록 ZIP 적용 여부와 관계없이 이 묶음을 한 번 적용하면 된다.
직접 등록이 이미 적용된 NAS에서는 해당 마이그레이션을 다시 수행하지 않는다.

1. File Station의 `/docker/company-approval`에 ZIP을 업로드하고 ‘여기에 압축 풀기’를 선택한다.
2. Windows PowerShell에서 실행한다.

```powershell
ssh -t admin@192.168.1.46 "sudo sh /volume1/docker/company-approval/xenosys-leave-excel-20261016/APPLY_LEAVE_EXCEL.sh"
```

3. `LEAVE_EXCEL_READY` 확인 후 사이트를 새로고침하고 연도·부서를 선택해 엑셀을 내려받는다.

업데이트는 런타임 파일 14개만 복사한다. 기존 소스 백업·체크섬 검증을 수행하고,
기존 `nas.sh update`가 DB 백업·필요한 마이그레이션·웹 이미지 전환을 처리한다.
기존 `.env`, 비밀번호, HTTPS 설정, 연차 산정 코드는 교체하지 않는다.

## 검증

- Django 전체 156개 실행: 147개 통과, MariaDB 전용 9개 건너뜀.
- 신규 엑셀 시험 5개를 MariaDB 10.11.14에서도 모두 통과했다.
- 실제 다운로드 응답의 XLSX를 다시 열어 두 시트의 열·숫자·사용내역·줄바꿈·필터·첫 행 고정 확인.
- 여러 날/연도 경계/주말 제외, 오전·오후반차 통일, 경리 직접 등록과 취소, 공용연차 활성/취소 필터 확인.
- 연도·부서·직원 범위, 비휴가 문서 제외, 기존 정정으로 날짜를 만들지 않는 동작 확인.
- 엑셀 생성 전후 연차 DB 값 보존, 비공개 사유 제외, 직원 수와 무관한 3개 조회 확인.
- 새 NAS 묶음 3개 시험: 결합 파일/이전 소스 백업/설정·산정 코드 보존,
  손상 파일·진행 중인 복구 거절, 실패 시 완료 표시 차단과 백업 보존.
- `check`, `makemigrations --check --dry-run`, `git diff --check` 통과.

운영 NAS의 이번 적용은 별도이며, 실제 직원 데이터는 검증에 사용하지 않았다.
