사내결재시스템 전체 기능 · 검토자 중심 최종 로컬 테스트

폴더: xenosys-local-final-20261023
주소: http://127.0.0.1:18141/
로그인: admin / 설치할 때 직접 정한 테스트 비밀번호

기존 사내결재시스템 전체 기능과 구매요청 기능을 유지하고, 누적 수정 사항과 마지막 직관성·편의성 요청을 반영했습니다. 실제 NAS에는 접속하거나 업데이트하지 않았습니다.

PC 실행

1. Python 3.10 이상이 설치된 PC에서 ZIP 전체를 새 폴더에 풉니다. 이전 테스트 폴더에 덮어쓰지 마세요.
2. SETUP_LOCAL_FULL.bat 실행 → 가상 직원 공통 테스트 비밀번호를 직접 정합니다.
3. RUN_LOCAL_FULL.bat 실행 → admin으로 로그인합니다.
4. 상단 역할 전환으로 기안자·검토자·승인자·담당 이사·구매 담당자·대표를 테스트합니다.
5. 종료는 실행 창에서 Ctrl+C입니다. 초기화는 실행 종료 후 RESET_LOCAL_FULL.bat입니다.

새 설치는 가상 직원 12명, 표시 역할 10개, 문서 0건으로 시작합니다. 이전 테스트와 포트·쿠키·데이터·백업을 분리했습니다. 데이터는 이 폴더의 var/full-nas-test-v3/purchase-test에만 저장됩니다. 실제 직원 정보·DB·첨부·.env·비밀번호·비밀키는 포함하지 않습니다.

기안자와 검토자

- 휴가원과 새 구매요청에서 기안자는 검토자만 지정합니다. 승인자는 미리 선택하지 않습니다.
- 요청 버튼은 검토 요청으로 통일했습니다. 검토자는 승인완료 또는 승인자에게 전달을 선택합니다.
- 승인완료 권한이 없는 검토자는 승인자에게 전달만 사용할 수 있습니다. 전달을 선택하면 승인자 부서·직원 선택란이 나타납니다.
- 검토자 본인과 기안자는 상위 승인자로 선택할 수 없습니다. 본인 문서 승인도 금지합니다.
- 구매요청의 검토자 승인완료는 내부 승인완료입니다. 이후 구매확인·구매 담당자 요청·대표 최종 결재는 반드시 거칩니다.
- 휴가원의 승인완료 가능한 검토자는 휴가원 규정에서 지정합니다. 구매요청의 승인완료 가능한 검토자는 구매 규정의 해당 직원 체크로 지정합니다. 직급만으로 자동 부여하지 않습니다.
- 직원 권한은 현재 설정으로 확인합니다. 권한을 해제한 검토자는 승인완료할 수 없고 적격 승인자에게 전달할 수 있습니다.
- 새 휴가원은 기존 고급 단계별 옵션과 관계없이 검토자가 다음 단계를 결정합니다. 기존 제출 문서는 저장된 결재 경로로 유지합니다.
- 기존 구매요청 중 승인자가 이미 지정된 제출 문서는 기존 순서로 처리합니다. 새 요청부터 검토자가 승인자를 결정합니다.

요청 방식

- 휴가원 과장·팀장·부장·이사: 검토 요청 / 대표 결재 요청. 대표 결재는 해당 규정에서 허용하고 결재 가능한 대표가 지정된 경우 선택합니다.
- 구매요청 과장·팀장·부장·이사: 검토 요청 / 구매담당자에게 요청. 직접 요청도 개발팀은 개발 이사, 그 외 부서는 생산 이사의 구매확인을 거칩니다.
- 같은 이사가 내부 승인을 완료하고 구매확인도 맡으면 한 번에 처리합니다.
- 담당 이사 본인의 직접 구매요청은 구매 담당자에게 전달하며, 대표 최종 결재는 계속 필요합니다. 본인이 확인·승인한 기록을 만들지 않습니다.

간단해진 화면

- 휴가원은 날짜를 입력하면 차감 일수와 승인 후 예상 잔여 연차를 확인합니다. 실제 차감은 최종 승인 때 합니다.
- 구매요청은 품목·구매처·수량·단가·총액·구매사유·첨부를 먼저 보여줍니다. 필요일·사용 부서·보관 위치·구매 링크 등은 추가 정보에 모았습니다.
- 검토 화면도 구매 판단에 필요한 내용을 먼저 보여줍니다. 비어 있는 추가 항목을 길게 나열하지 않습니다.
- 역할에 맞는 지금 할 일을 안내하고, 처리 후에는 누구에게 전달했는지 또는 무엇이 완료됐는지 표시합니다.
- 대표는 품목별 구매처 / 수량 / 단가 / 총액 / 구매사유를 항목별로 확인합니다.
- 대표의 품목 결정은 승인 / 반려 / 보류 세 버튼입니다. 미선택 품목은 선택 필요로 표시하고 자동 승인하지 않습니다.
- 반려를 선택하면 반려 사유, 보류를 선택하면 보류 사유만 입력합니다. 전체 승인 선택 후 예외 품목만 변경할 수 있습니다.
- 대표용 구매 화면과 공통 문서 목록에서는 수령 현황을 숨겼습니다. 구매 담당자와 기안자의 수령 기능은 유지합니다.

규정 관리

- 휴가원 규정은 여러 개 등록하고 목록에서 규정명 / 적용 대상 / 요청 방식 / 사용 중·사용 안 함 / 수정을 확인합니다.
- 목록에서 사용 여부를 전환할 수 있습니다. 다른 창에서 변경된 상태로 다시 누르면 새로고침을 안내합니다.
- 같은 우선순위에서 적용 대상이 겹치는 규정을 함께 켤 수 없습니다. 직원별 → 부서별 → 직급별 → 기본 순서와 기존 중복 검사를 유지합니다.
- 규정을 꺼도 이미 제출된 문서의 경로·처리 이력과 연차 기록을 바꾸지 않습니다. 현재 직원의 처리 권한은 별도로 확인합니다.
- 검토자 승인완료 권한, 부서·직원 예외, 고정 결재선, 승인자의 대표 추가 결재 일수 기준은 상세 설정에 유지합니다.
- 구매확인 담당자 링크를 누르면 직원 권한관리 상단의 담당자 설정이 바로 펼쳐집니다.
- 규정 사용·사용 안 함과 변경 권한은 기존 관리자·연차 관리 권한에 따라 제한합니다.

앞선 수정 사항도 유지

- 대표의 구매승인 대기는 기존 미결 건수·결재함에 포함하고, 처리 후 내 승인 내역에서 확인합니다. 별도 대표 구매요청함 메뉴는 표시하지 않습니다.
- 결재함·내 문서함·내 승인 내역은 전체 / 휴가원 / 구매요청 / 생산 재고 탭으로 분류합니다.
- 구매 담당자는 구매요청함에서 확인된 품목 선택·요청·보류·완료를 관리합니다. 완료 탭은 수령까지 끝난 품목을 모읍니다.
- 구매 목록에서는 문서번호를 숨기고 기안자·구매처를 표시합니다. 원본·내부 관리용 번호는 보존합니다.
- 대표 승인 이후 품목의 결재완료 상태는 유지하고, 기안자·구매 담당자에게 수령 대기 / 수령 완료를 별도로 표시합니다.
- 물품을 모두 받으면 수령 완료를 한 번 누릅니다. 수령 수량 입력·부분 수령 집계는 표시하지 않습니다. 사용·보관 위치와 메모는 남길 수 있습니다.
- 기안자 알림은 누가 검토했는지, 누가 승인했는지, 대표 최종 결재완료를 중심으로 보냅니다. 반려·보완 요청·보류 알림은 유지하고 내부 취합·구매확인 알림은 반복하지 않습니다.
- 휴가원·구매요청의 본인 전결 선택은 제거했습니다. 이미 처리된 기존 문서·승인 이력은 보존합니다.
- 금액 증가 재승인, 보류 후 재요청, 첨부 권한, 유사 구매 안내, 원본·과거 승인 금액 보존, 엑셀, 단순 수령 확인은 유지합니다.
- 휴가원·생산 재고·연차 관리·최종문서 정정·알림·일정·복지·직원 권한·백업 등 기존 기능은 유지합니다.
- 브라우저를 닫았을 때 웹 푸시는 기존 합의대로 보류합니다.

추천 테스트 순서

1. 그 외 부서 기안자: 구매요청 작성 → 검토자 선택 → 검토 요청.
2. 검토자: 승인자에게 전달 → 승인자 지정 → 전달. 승인자는 승인완료.
3. 다른 요청에서는 권한 있는 검토자가 승인완료를 눌러 내부 승인을 끝냅니다.
4. 생산팀 이사: 구매 확인함에서 구매 내용 확인.
5. 구매 담당자: 구매요청함에서 확인된 품목을 선택해 대표에게 요청.
6. 대표: 기존 결재함에서 요청을 열고 품목별 승인·반려·보류 선택 → 결과 확정 → 내 승인 내역.
7. 기안자: 내 문서함에서 결재완료 확인 → 물품을 모두 받으면 수령 완료.
8. 휴가원 기안 → 검토자의 승인완료 또는 승인자 전달 → 연차 차감 확인.
9. 관리자: 휴가원 규정 추가·수정·사용 전환, 구매 규정의 승인완료 가능한 검토자 지정.

검증과 실제 NAS 적용 범위

SQLite 통합 52건과 MariaDB 10.11 통합·동시 처리 64건을 통과했습니다. 기존 workflow 호환 검사 319건 중 298건 통과·환경별 21건을 건너뛰었습니다. Chromium에서 전체 구매 흐름, 검토자 두 처리 방식, 휴가원 미리보기·승인, 대표 세 결정 버튼·조건부 사유, 규정 사용 전환·복수 규정, 알림·권한·첨부·엑셀, 320~2560px 화면을 확인했습니다.

가상 기존 DB 업그레이드에서 계정·비밀번호·권한·연차·기존 구매문서·규정·알림·이력이 그대로 유지됐습니다. 구매 검토자 승인완료 권한은 빈 상태로 추가하므로 실제 NAS 직원에게 자동 부여되지 않습니다. 관리자가 대상 직원을 지정해야 합니다.

동일 소스의 NAS 도구를 포함하지만 실제 NAS에는 적용하지 않았습니다. 운영에서 가상 계정 생성·역할 전환은 차단합니다. 기존 DB 및 견적서·증빙파일 백업·복구를 유지합니다.

Windows BAT의 명령·CRLF를 검사했고 실제 실행·브라우저 검증은 Linux Python/Chromium과 MariaDB에서 수행했습니다. 실제 Windows PC 실행 검증은 남아 있습니다. examples 폴더에는 가상 직원 화면 예시만 포함합니다.
