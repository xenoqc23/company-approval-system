# 검토자 중심 최종 로컬 테스트 · 2026-10-23

사용자의 마지막 요청을 반영했다: 복수 휴가 규정의 사용/사용 안 함 목록과 전환, 기안자는 검토자만 지정, 검토자의 승인완료/상위 승인자 전달, 대표의 품목별 사실 정보와 세 결정 버튼, 역할별 필수 행동·조건부 입력·간단한 작성 화면. 실제 NAS에는 접속·배포하지 않았다.

- SQLite 통합 52건 통과. 새 요청의 미리 지정된 승인자 무시, 검토 권한 위조·자기 전달 차단, 지명 권한의 즉시 반영, 이사 승인+구매확인 합침, 대표 최종 승인 별도 유지, 구 제출 경로 보존, 규정 전환의 충돌·권한·CSRF·버전 검사, 세 결정 버튼·사유 검증·선택 보존, 기존 전체 기능과 비공개 첨부·백업 등을 포함한다.
- MariaDB 10.11에서 통합 및 동시 처리 64건 통과. 검토자의 승인완료와 승인자 전달 경쟁도 한 번만 커밋한다. 기존 중복 승인·취합·확인·수령 및 금액 변경 경쟁 검사를 유지한다.
- 기존 workflow 호환 검사 319건: 298건 통과, 환경별 21건 건너뜀.
- Chromium 구매 6개 경로: 일반 검토→검토자가 승인자 지정→승인, 부서별 직접 요청, 이사 승인 시 구매확인 합침, 이사 본인 직접 구매요청, 독립 검토자의 도착 팝업, 대표 품목별 승인/반려/보류, 공통 미결·승인 내역, 첨부 권한·엑셀·수령 완료·완료 탭·규정 권한을 확인했다.
- 추가 Chromium 사용 흐름: 권한 있는 검토자가 내부 승인완료→구매확인→취합→대표 최종 승인. 단가·총액·구매사유가 구분되고 대표 화면에 수령 현황이 없는지 확인했다. 라디오 미선택 상태, 반려/보류의 조건부 사유와 승인 전환 시 사유 숨김을 확인했다.
- 휴가원 입력의 연차 1일/예상 잔여 15일, 검토자만 선택, 승인완료/전달의 접힌 입력, 검토자 승인 시 실제 1일 차감, 규정 껐다 켠 뒤 기존 승인·연차 이력 유지 확인.
- 복수 규정 목록에서 사용 중 1/사용 안 함 1을 확인했다. 규정의 중복 사용 및 구 버전 전환은 서버에서 차단한다.
- 역할별로 허용된 실제 페이지에서 320/390/768/1440/2560px 가로 넘침·JS 오류 없음. 기존 홈·관리·휴가·재고·복지·연차·규정 메뉴를 유지했다.
- 별도 가상 기존 DB를 workflow 0020부터 최신 스키마로 업그레이드했다. 기존 4개 구매 상태·계정/비밀번호·권한·잔여연차·공통 규정 버전·알림·감사 기록이 동일하고 새 구매 정책은 비활성으로 준비됐다. 0009의 검토자 승인완료 명단은 비어 있으며 직원에게 자동으로 부여하지 않는다.

권한은 현재 지명된 적격 검토자에게만 허용한다. 제출 당시 경로는 route.reviewer_decides로 구분하여 기존 구매문서의 선택된 승인자를 변경하지 않는다. 신규 휴가원은 검토자 중심 경로를 사용하며, 기존 제출 문서의 스냅샷·연차·처리 기록은 변조하지 않는다.

ZIP은 새로운 이름 xenosys-local-final-20261023, 포트 18141, full-nas-test-v3/purchase-test, 별도 쿠키를 사용한다. 가상 문서가 없는 초기 설치로 배포하며 실제 데이터·비밀키·비밀번호·.env를 포함하지 않는다. Windows BAT는 명령/CRLF만 확인했으며 실제 Windows 실행은 아직 수행하지 않았다.

최종 배포 확인: 실제 ZIP을 별도 폴더에 풀어 마이그레이션·가상 계정 설치·check를 실행했다. 가상 직원 12명, 문서 0건, 휴가 규정 1개와 명시적인 가상 검토 권한을 확인했다. ZIP에서 실행한 앱에서 로그인, 10개 역할, 기존 관리 메뉴 16개 경로, 검토자만 지정·적격 검토자의 내부 승인완료, 간단한 구매 정보, 휴가원의 검토 요청 버튼과 두 요청 방식, 반응형과 자산을 다시 확인했다. ZIP 파일·체크섬·격리·초기화 보호 검사 4건도 통과했다. 마지막 구매 상세 정리에는 관련 UI 검사 23건을 추가 실행해 통과했다.
