사내결재시스템 전체 기능 + 새 구매요청 · NAS 동일 소스 로컬 테스트

폴더: xenosys-local-full-20261023
로컬 주소: http://127.0.0.1:18121/
로그인: admin / 설치할 때 직접 정한 테스트 비밀번호

이번 파일은 기능을 줄인 구매 전용 시안이 아닙니다. 기존 사내결재시스템 전체와 새 구매요청이 같은 프로그램 안에서 동작합니다. NAS 운영 모드에서도 같은 화면·결재·권한·알림·백업 코드를 사용합니다. 실제 NAS에 업데이트하거나 연결하지 않았습니다.

1. PC 실행

- Python 3.10 이상을 설치합니다. 다른 컴퓨터에서도 처음에는 Python이 필요합니다.
- ZIP 전체를 새로운 폴더에 압축 해제합니다. 이전 테스트 폴더에 덮어쓰지 마세요.
- SETUP_LOCAL_FULL.bat 실행: 필요한 패키지를 설치하고 테스트 공통 비밀번호를 직접 정합니다.
- RUN_LOCAL_FULL.bat 실행 → admin으로 로그인합니다.
- 상단 역할 전환으로 기안자·검토자·승인자·부서별 이사·구매 담당자·대표를 테스트합니다.
- 관리자 이름은 실제 NAS와 같은 admin입니다. 대표 지정·대표 결재 설정도 기존 권한대로 테스트할 수 있습니다.
- 실행 창을 열어 두고 사용하며, 종료는 실행 창에서 Ctrl+C입니다.
- 초기화는 실행 창 종료 후 RESET_LOCAL_FULL.bat을 실행합니다. 이 폴더의 가상 계정·문서·파일만 초기화합니다.
- 새 폴더는 문서 0건에서 시작합니다. 가상 직원·연차·테스트용 권한만 준비합니다.
- 이전 파일과 포트·쿠키·DB·백업 폴더를 분리했습니다. DB는 var/full-nas-test/purchase-test에 저장됩니다.

2. 기존 기능 전체 유지

- 기존 홈, 잔여연차 강조, 휴가원·구매요청·생산 재고 기안, 기존 결재함과 내 문서함
- 임시저장, 내 승인 내역, 반려·취소·삭제 문서 보관, 복사 재작성, 문서 검색
- 직원 일정, 회사 휴무, 직원복지, 생일·기념일 표시 및 기존 공개 범위
- 직원별 연차 관리, 수동 사용내역, 최종 휴가원 정정과 차감량 조정, 연차 내역·엑셀
- 기존 최종 승인 문서함, 문서별 미확인 표시, 기존 구매·재고 엑셀과 후속 처리
- 직원 가입·승인, 부서·직급·권한 관리, 관리자 비밀번호 처리, 회사 대표 지정·조회·결재 설정
- 연차·경조사·장기근속 규정, 기존 공통·직원별·부서별 전결규정과 상세 경로 미리보기
- 기존 알림함·화면 도착 팝업·미결·완료 미확인 건수, 백업·복구

권한에 따른 메뉴 공개는 원래처럼 유지합니다. 직원에게 관리 메뉴를 공개하는 방식으로 합치지 않았습니다. 가상 관리자에는 전체 관리 메뉴를 확인할 수 있는 권한을 준비했습니다.

브라우저를 닫았을 때 웹 푸시는 앞서 보류한 상태를 유지합니다. 일반 화면 알림과 팝업은 동작합니다.

3. 새 구매요청

- 기존 구매요청 바로가기에서 구매처·품목·수량·금액·구매사유·링크·견적서를 작성합니다.
- 결재선은 기존처럼 부서 → 검토자, 부서 → 승인자를 고릅니다. 자격·직급 조건을 충족하는 다른 부서 결재자도 선택할 수 있습니다.
- 검토 요청은 검토자 → 승인자 순서로 진행합니다. 과장급 이상 중 규정에서 허용한 직급은 구매담당자에게 요청도 선택할 수 있습니다.
- 직접 요청을 선택하면 내부 검토·승인 선택란을 숨기고 해당 경로 안내만 보여줍니다. 검토 요청 안내와 본인 전결 안내가 동시에 표시되지 않습니다.
- 구매확인 담당자는 내부 결재자와 별도로 요청 부서에 따라 정합니다. 개발팀 → 개발팀 이사, 그 외 부서 → 생산팀 이사입니다.
- 최종 승인자가 해당 구매확인 담당자와 같으면 한 번에 승인·확인을 처리합니다.
- 담당 이사 본인의 직접 요청은 구매 담당자에게 바로 전달할 수 있으며, 본인이 확인한 기록을 만들지 않습니다. 대표 구매승인은 계속 필요합니다.
- 구매 담당자는 구매요청함에서 요청할 품목 / 보낸 요청 / 보류를 확인합니다.
- 확인된 여러 품목을 선택해 대표에게 구매요청합니다. 요청 부서·요청자·품목·구매처·수량·금액·구매사유·원본 문서를 함께 확인합니다.
- 대표는 품목별 승인·반려·보류를 결정할 수 있습니다. 전체 승인 선택 후 예외 품목만 바꾸는 것도 가능합니다.
- 대표 승인 후 별도의 구매 담당자 결제 확인을 기다리지 않고 기안자에게 구매 승인완료를 알립니다.
- 받은 수량을 나누어 등록할 수 있습니다. 구매 담당자의 요청서에도 일부 수령·수령 완료, 등록자와 시간이 표시됩니다.
- 보완 요청, 보류 후 다시 요청, 금액 증가 시 재승인, 과거 승인·금액 보존, 첨부파일 권한을 유지합니다.
- 기안자·일반 검토·승인자는 간단한 진행상황을 확인하고, 상세 구매 진행·증빙은 구매 업무 참여자만 확인합니다.
- 기존 기록부터 배송·수령 완료 기록까지 유사 품목 안내에 포함합니다. 기밀 구매는 제외하며 다른 문서 원문·가격은 공개하지 않습니다.

4. 규정과 권한

- 직원·권한 관리에서 구매확인 담당자, 구매 담당자, 구매승인 대표를 지정합니다.
- 규정 관리 첫 화면에서 휴가원 / 구매요청 / 생산 재고 / 연차·복지 기준을 구분합니다.
- 기존 전결규정 전체 메뉴에서 원래의 공통·부서·직원별 규정과 고정 결재선·미리보기를 계속 이용합니다. 기존 공통 규정을 숨기거나 수정 불가능하게 하지 않습니다.
- 새 구매요청의 경로는 구매요청 규정에서 별도로 설정합니다. 기존 공통 규정은 기존 문서·휴가원·생산 재고의 원래 적용 범위를 유지합니다.
- 저장한 구매 경로는 새로 제출하는 문서부터 적용합니다. 이미 진행 중인 문서의 담당자·예외 경로는 유지합니다.
- 원래 직원 카드의 연차 관리·기존 최종문서 조회·생산 재고 발주 권한도 그대로 유지합니다.

5. 기존 데이터가 있는 NAS에 적용할 때의 동작

이번 ZIP으로 실제 NAS 업데이트를 실행하지 않았습니다. deploy/nas에는 동일 소스의 기존 설치·업데이트 도구를 함께 제공합니다. 우선 PC에서 전체 기능을 검토하세요.

- 새 모듈은 NAS Docker 이미지에도 포함됩니다. 로컬 전용으로만 켜지는 조건을 제거했습니다.
- 기존 계정·비밀번호·권한·연차·규정·기존 구매문서·진행 상태·알림·이력을 초기화하지 않습니다.
- 기존 구매문서를 새 절차로 자동 전환하지 않습니다. 기존 문서는 원래 화면과 경로로 조회·처리합니다.
- 새 구매요청용 담당자나 권한을 직원 이름으로 추측해 자동 부여하지 않습니다. 최초 업데이트 시 새 구매 규정은 꺼진 상태로 준비합니다.
- 실제 적용 후 관리자가 직원·권한 관리에서 담당자를 지정하고 구매 규정을 켭니다. 설정이 끝나기 전에는 새 구매요청 화면에 설정 안내를 표시합니다.
- 기존 구매문서를 복사해 재작성하면 새 양식으로 내용을 가져와 구매처와 결재선을 확인합니다.
- NAS에서는 가상 계정 생성·역할 전환을 사용할 수 없습니다. 가상 데이터는 로컬용 별도 DB에서만 생성합니다.

6. 백업과 테스트 결과

- 새 구매요청의 DB뿐 아니라 견적서·증빙 첨부파일도 백업 ZIP에 포함합니다.
- 첨부파일 목록·크기·체크섬·경로를 확인한 뒤 복구합니다. 기존 DB 전용 백업도 계속 읽을 수 있습니다.
- 운영 NAS 복구는 원래대로 웹 서비스를 중지한 뒤 오프라인 절차로 진행하며, 복구 직전 안전 백업을 만듭니다.
- 실제 테스트는 가상 데이터로 수행했습니다: 기존 데이터 업데이트 보존, 로컬 SQLite DB+파일 복구, 운영 Docker+MariaDB 구매 흐름과 DB+파일 복구, 40개 통합·동시 처리 검사.
- 가상 직원 화면 예시는 examples 폴더에 있습니다. 실제 직원 정보·DB·.env·비밀번호·비밀키는 배포하지 않습니다.
- Windows BAT의 명령·줄바꿈을 검사했고, 실행과 브라우저 검증은 Linux Python/Chromium 및 NAS 운영 모드 Docker/MariaDB에서 수행했습니다.
