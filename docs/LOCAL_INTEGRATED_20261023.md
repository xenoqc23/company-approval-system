새 폴더: xenosys-local-integrated-20261023
접속 주소: http://127.0.0.1:18117/
NAS 업데이트용 파일이 아닙니다. 기존 NAS·직원 데이터·이전 테스트 폴더를 사용하지 않습니다.

1. 실행

- Windows에 Python 3.10 이상이 필요합니다. 다른 PC에서도 처음에는 Python을 설치해야 합니다.
- ZIP을 새 폴더에 전부 압축 해제하세요. 이전 테스트 폴더에 덮어쓰지 마세요.
- SETUP_LOCAL_INTEGRATED.bat 실행: 처음 한 번 인터넷으로 실행 패키지를 설치하고 가상 계정의 공통 비밀번호를 직접 정합니다.
- RUN_LOCAL_INTEGRATED.bat 실행: 브라우저가 열리면 p_admin / 직접 정한 비밀번호로 로그인합니다.
- 상단 '역할 전환'에서 필요한 가상 직원을 선택하고 전환을 누르세요. 계정마다 비밀번호를 다시 입력할 필요가 없습니다.
- 실행 중에는 검은 실행 창을 열어 두세요. 종료는 실행 창에서 Ctrl+C를 누릅니다.
- 실행 준비를 다시 하면 이 폴더의 기존 가상 문서는 유지하고 설치 전 DB 백업을 만듭니다.
- 완전히 비우려면 실행 창을 닫고 RESET_LOCAL_INTEGRATED.bat을 실행하세요. 이 통합 테스트의 가상 데이터만 비웁니다.
- 이전 테스트와 DB 경로·쿠키·접속 포트가 다릅니다. 18117 포트를 다른 프로그램이 쓰면 해당 실행 창을 먼저 종료하세요.
- DB는 var/integrated-test/purchase-test 폴더입니다. 다른 데이터 폴더·.env·실제 직원 자료를 복사하지 마세요.

2. 이번 통합본의 화면

- 원래 홈·연차 현황·직원 일정·복지·휴가원·생산 재고 화면을 유지합니다.
- 홈에서 구매 요청을 누르면 새 구매요청서를 작성합니다.
- 내 문서함·결재함·완료 미확인 목록·검색·알림함에서 새 구매요청도 함께 확인합니다.
- 구매 관리 메뉴는 구매확인 담당자의 '구매 확인함', 구매 담당자·대표의 '구매요청함'으로 구성합니다.
- '구매 모아보기'와 '구매보류함'은 별도 메뉴로 만들지 않습니다.
- 구매 담당자의 구매요청함 안에는 '요청할 품목 / 보낸 요청 / 보류'가 있습니다.
- 처리할 품목과 이미 보낸 요청을 구분해 중복 요청을 막습니다. '전체 요청'과 '작성 대기'를 같은 카드로 반복하지 않습니다.
- 구매 진행상태 검색은 핵심 상태로 묶고 중복된 '구매 승인완료' 항목을 제거했습니다.
- 원본 구매요청과 여러 품목을 묶은 구매요청서는 서로 연결되지만 별도 기록입니다. 품목 수와 문서 수는 각각 표시합니다.

3. 권한관리와 규정관리

직원·권한 관리:
- 위쪽 '구매 업무 담당자·권한'에서 개발팀 구매확인 담당자, 그 외 부서 담당자, 구매 담당자, 구매승인 대표를 지정합니다.
- 개발팀 담당자는 개발팀 이사, 그 외 부서 담당자는 생산팀 이사를 선택합니다.
- 진행 문서는 기존에 지정된 담당자를 유지합니다. 미처리·수령 대기 문서가 있는 구매 담당자 권한은 바로 해제할 수 없습니다.
- 기존 직원 카드의 최종문서 조회·생산재고 발주 권한은 새 구매요청 담당자 권한과 다릅니다. 화면의 설명을 확인하세요.
- 대표의 실제 결재 허용 권한이 꺼져 있으면 구매승인도 확정할 수 없습니다.

규정 관리:
- 처음 화면에서 휴가원 / 구매요청 / 생산 재고를 선택합니다. 연차 부여·복지 기준도 별도로 유지합니다.
- 휴가원: 적용 대상 → 검토·승인 직급과 전결 가능한 직원 → 과장급 이상 요청 방식 순서로 설정합니다.
- 구매요청: 직접 요청 가능한 직급 → 부서별 담당자 확인 → 중복 확인·이사 본인 요청 예외 → 경로 미리보기 순서입니다.
- 구매 담당자 이름은 규정 화면에 표시하지만 담당자 변경은 직원·권한 관리에서만 합니다.
- 휴가원 대표 결재 선택 일수를 변경해도 구매 금액 기준이나 생산 재고 결재 방식을 바꾸지 않습니다.
- 저장한 구매 경로는 새로 제출하는 요청부터 적용합니다. 기존 진행 문서의 구매확인 담당자·예외 규칙은 유지됩니다.
- 휴가원 검토자 전결 권한은 기존 시스템의 지정 직원 방식대로 운영합니다.

4. 구매요청 테스트 순서

가. 일반 직원 검토·승인 경로
- 그 외 부서 · 기안자(p_quality): 구매처·수량·금액·사유를 작성하고 검토자/승인자를 선택해 '검토 요청'.
- 그 외 부서 · 과장·검토자(p_quality_manager): 기존 결재함에서 검토 후 승인자에게 전달.
- 그 외 부서 · 승인자(p_quality_lead): 기존 결재함에서 내부 승인 완료.
- 생산팀 이사(p_prod_director): 구매 확인함에서 '구매 내용 확인'.
- 구매 담당자(p_finance): 구매요청함 → 요청할 품목에서 원하는 품목 선택 → 선택 품목으로 구매요청 → 사유 확인 후 대표님께 구매요청.
- 대표(p_ceo): 구매요청함에서 품목별 승인·반려·보류 → 선택한 결과 확정. 반려·보류에는 사유가 필요합니다.
- 기안자: 완료·미확인 알림 확인 → 물품을 실제 받은 뒤 '받은 수량 등록'.

나. 개발팀
- 개발팀 · 과장·기안자(p_dev_manager)는 검토 요청 또는 구매담당자에게 요청 중 선택합니다.
- 직접 요청도 개발팀 이사의 구매확인을 거칩니다. 생산팀 이사에게 개발팀 구매확인 업무가 섞이지 않습니다.
- 검토 경로에서 개발팀 이사가 최종 승인자와 구매확인 담당자를 겸하면 '승인하고 구매담당자에게 전달' 한 번으로 처리합니다.
- 담당 이사 본인의 직접 요청은 본인 확인 기록을 만들지 않고 구매 담당자에게 전달합니다. 대표 구매승인은 동일하게 필요합니다.
- 해당 예외를 규정에서 해제하면 다른 부서의 담당 이사가 대신 확인합니다.

다. 승인·수령
- 대표 구매승인이 확정되면 별도 구매 담당자의 결제 확인 없이 기안자에게 구매 승인완료를 알립니다.
- 승인·반려·보류는 품목별 결과입니다. 한 요청서의 일부만 승인할 수 있습니다.
- 예: 10개 중 6개를 받으면 일부 수령 6/10, 이후 4개를 더 등록하면 수령 완료 10/10입니다.
- 구매 담당자는 '보낸 요청'과 요청서 상세에서 받은 수량·등록자·시간, 승인된 품목 중 수령 완료 개수를 확인합니다.
- 반려·보류·재승인 대기 품목은 현재 수령 대상 집계에 포함하지 않습니다.
- 구매승인 후 금액 증가 시 대표 재승인이 필요합니다. 이전 요청의 승인 금액·결과는 보존합니다.
- 보류 품목은 보완 내용을 기록한 뒤 다시 요청합니다.
- 화면의 수령 현황은 문서를 다시 열거나 조회하면 최신 결과가 표시됩니다.
- 엑셀 다운로드는 구매요청서 상세의 버튼을 사용합니다. 구매사유·구매처·품목별 결정과 현재 수령 현황을 포함합니다.

5. 정보 표시·알림

- 기안자와 일반 검토·승인자는 원래 결재 경로와 간단한 구매 진행상황을 봅니다.
- 상세 구매 진행 현황과 구매 증빙파일은 지정 구매업무 참여자에게만 보입니다.
- 구매요청 입력 중 유사 품목은 기존 구매문서·생산 재고·새 구매요청의 과거 수령 내역까지 함께 검색합니다. 현재 재고 수량을 뜻하지 않습니다.
- 기밀 구매·취소·반려 내역은 유사 품목 안내에서 제외합니다. 다른 직원의 원문이나 금액을 공개하지 않습니다.
- 기존 알림함·화면 팝업·미확인 건수는 유지합니다. 새 구매요청 알림도 같은 알림함에 모입니다.
- 완료 미확인은 기안자가 문서를 열면 해제합니다. 알림 모두 읽음과 완료 확인은 별도입니다.
- 팝업 테스트는 기안자와 검토자를 다른 브라우저 또는 시크릿 창으로 동시에 로그인해서 확인하세요. 15초 간격으로 확인하며 활성 창에 표시합니다.
- 브라우저를 닫았을 때의 웹 푸시는 이번 테스트에서 사용하지 않습니다.

6. 기존 구매문서 보존

- 새 구매요청은 별도 구매 기록으로 저장하며 기존 문서번호·승인·배송 기록을 바꾸지 않습니다.
- 기존 구매문서는 기존 화면에서 조회·후속 처리합니다. 새 구매요청을 예전 구매 양식으로 제출하는 것은 막았습니다.
- 실제 NAS 데이터 이관이나 설치는 이번 ZIP에 포함하지 않습니다. 가상 데이터 통합 로컬 검증용입니다.
- 배포 파일에는 실제 직원 정보·DB·.env·비밀번호·푸시 비밀키가 들어 있지 않습니다.
