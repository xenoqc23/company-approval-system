# 새 구매요청 표시·엑셀 정리 검증

대상: xenosys-local-newrequests-20261026.zip. 이번 수정 범위는 새 요청 표시와 엑셀 세 열 제거이며, 대표 승인 버튼은 추가하지 않았다. 실제 NAS에는 적용하지 않았다.

- SQLite 통합 테스트 71건 통과: 새 요청 5건과 기존 결제·검토·문서함·권한·첨부·휴가원 관련 회귀 검사 포함.
- 전체 소스·자산·NAS 도구·쿠키·포트·초기화 범위·압축 해시 패키징 검사 4건 통과.
- Django check, makemigrations --check --dry-run, 알림 JavaScript 구문 검사 및 git diff 공백 검사 통과.
- 압축 해제본의 새 설치에서 가상 직원 12명·문서 0건과 v5 쿠키·데이터 분리를 확인.
- 기존 v4 가상 DB를 복사해 0010에서 0011로 올린 뒤 모든 기존 테이블의 모든 기존 열 값을 비교했다. 기존 요청·결제·반려·보류·수령 기록을 보존했다.

압축 해제본을 Chromium에서 실행하고 다음을 확인했다.

1. 홈·메뉴가 처음에는 새 요청 0건으로 숨겨지고, 경리가 요청을 올리면 페이지를 다시 열지 않고도 표시된다.
2. 품목이 2개인 요청도 새 요청 1건으로 계산하며, 두 번째 요청을 올리면 2건이 된다. 기존 미결은 0건이다.
3. 경리 조회·엑셀 다운로드와 대표 목록 조회만으로 새 표시가 사라지지 않는다.
4. 대표가 상세를 연 요청만 새 표시가 해제되며 홈·메뉴에도 갱신된다. 전체 목록에는 계속 남고 결제 대기 상태를 유지한다.
5. 대표에게 승인·결제 등록 버튼이 없고, 경리가 실제 결제 완료를 등록하는 기존 흐름을 유지한다.
6. 대표·경리의 실제 다운로드 엑셀을 읽어 10개 열, 정확한 가격·구매사유 값과 진행상황·처리 사유·수령 상태 열 제거를 확인했다.
7. 320·390·768·1440px 홈·목록·상세에서 가로 페이지 넘침이 없고 JavaScript 오류가 없다.

재현 스크립트: packaging/check_new_requests_local.py. 가상 seed_full_demo 환경과 loopback 주소에서만 사용한다.

실행 검증은 Linux Python/Django/Chromium에서 수행했다. Windows BAT 명령·CRLF는 검사했지만 실제 Windows PC 실행은 직접 검증하지 않았다. Python 3.10 이상과 첫 설치 시 의존 패키지 다운로드가 필요하다. 테스트 DB·비밀번호·.env·키는 ZIP에 포함하지 않는다.
