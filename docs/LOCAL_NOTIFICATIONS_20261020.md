# 알림 강화 · PC 로컬 테스트 안내

2026-10-20. NAS에는 적용하거나 접속하지 않았습니다. 이 테스트판은 각 PC의 별도 SQLite DB와 가상 직원을 사용합니다. 기존 NAS 직원·문서·연차·.env와 PC의 기존 var/prototype.sqlite3를 읽거나 수정하지 않습니다.

## Windows에서 실행

1. ZIP을 새 폴더에 압축 해제합니다. NAS app 폴더에 덮어쓰지 마세요.
2. Python 3.10 이상을 설치합니다. 처음 설치할 때 인터넷 연결이 필요합니다.
3. `SETUP_LOCAL_NOTIFICATIONS.bat`을 더블클릭합니다.
4. 가상 계정의 공통 초기 비밀번호를 직접 정해 입력합니다. 입력한 문자는 표시되지 않습니다.
5. 설치가 끝나면 `RUN_LOCAL_NOTIFICATIONS.bat`을 더블클릭합니다. PC 브라우저가 자동으로 열립니다.
6. 테스트 중에는 실행 창을 열어 둡니다. 브라우저 창만 닫아도 서버와 푸시 발송 프로그램은 계속 실행됩니다. 모두 종료하려면 실행 창에서 Ctrl+C를 누릅니다.

테스트 DB는 `var/notification-test/prototype.sqlite3`, 웹 푸시 비밀키는 같은 폴더의 `webpush-private.pem`입니다. 비밀키는 설치할 때 한 번 생성하고 재설치해도 유지합니다. 폴더를 공유하거나 GitHub에 올리지 마세요. 설치를 다시 실행하면 테스트 DB를 먼저 백업하며 계정을 덮어쓰지 않습니다.

Mac/Linux: `python3 local_notifications.py setup` 이후 `python3 local_notifications.py run`. `--port 18096`으로 다른 포트를 지정할 수 있습니다. 기존 launcher.py 설치·실행 방식은 유지합니다.

## 가상 계정

| 아이디 | 용도 |
|---|---|
| employee | 휴가원·구매요청서 기안 |
| reviewer | 검토, 전결, 상위 결재 요청 |
| approver | 최종 승인 |
| accounting | 경리, 최종 승인 문서함 |
| admin | 관리자; 첫 로그인 후 비밀번호 변경 |

모두 설치할 때 직접 정한 비밀번호를 사용합니다. 가상 직원명이며 실제 NAS 직원 계정과 관계없습니다. 동시에 비교하려면 Chrome·Edge 또는 서로 다른 브라우저 프로필을 사용하세요. 같은 프로필의 탭은 로그인 쿠키를 공유합니다. 시크릿 창은 웹 푸시 테스트용으로 사용하지 마세요.

## 화면에서 확인할 내용

1. reviewer로 로그인한 창을 켜 둡니다. employee의 다른 브라우저에서 휴가원이나 구매요청서를 제출하고 검토자를 지정합니다.
2. reviewer 화면에 최대 약 15초 내 도착 팝업과 결재함 미결 건수가 갱신됩니다. 화면을 다시 활성화하면 즉시 확인합니다. 숨겨진 탭에서는 화면 갱신을 쉬고 웹 푸시를 이용합니다.
3. 검토 문서를 읽으면 NEW·안 읽은 알림은 사라져도 미결은 유지됩니다. 전결·상위 전달·반려 등 실제 처리 후 미결에서 빠집니다.
4. 상위 결재 요청을 하면 선택한 approver에게 새 알림이 갑니다. 검토자 전결로 끝내면 바로 최종 승인됩니다.
5. 최종 승인되면 accounting 화면에 도착 팝업, 최종 승인 문서함의 주황 미확인 건수, 종류별 주황 탭과 NEW가 표시됩니다.
6. 탭을 눌러도 미확인은 유지됩니다. 해당 문서를 열어야 그 문서만 확인 처리됩니다. 확인 상태는 경리직원별로 따로 저장됩니다. 알림함의 ‘모두 읽음’은 최종 승인 문서의 개별 확인을 대신하지 않습니다.
7. 내 계정 → 알림 설정에서 도착 팝업과 알림음을 선택합니다. 알림음은 브라우저의 자동 재생 제한으로 화면에서 한 번 클릭한 후 사용할 수 있습니다. 기본은 꺼짐입니다.

## 브라우저 창을 닫은 상태의 실제 웹 푸시 테스트

1. Chrome 또는 Edge의 일반 창에서 로그인하고 내 계정 → ‘웹 푸시 켜기’를 누릅니다.
2. 브라우저의 알림 권한을 허용합니다. 주소창의 사이트 설정에서 차단되어 있다면 먼저 허용으로 바꿉니다.
3. ‘10초 후 테스트 알림’을 누르고 브라우저 창을 닫습니다. RUN 실행 창은 열어 두세요. 테스트는 30초에 한 번 요청할 수 있습니다.
4. 운영체제 알림 또는 알림 센터에서 ‘사내결재시스템 / 웹 푸시 테스트 알림입니다.’를 확인합니다.
5. 실제 기안 도착도 시험하려면 해당 계정의 창을 닫아 둔 채 다른 브라우저의 기안자로 새 문서를 제출합니다. 승인 완료 알림은 경리 계정에서 같은 방식으로 시험합니다.

중요한 구분:
- 브라우저 창을 닫아도 **브라우저의 백그라운드 기능과 OS 알림 서비스가 작동 중이면** 수신할 수 있습니다.
- 브라우저 강제 종료·백그라운드 실행 차단·PC 종료/절전·집중 지원/방해 금지·네트워크 차단 상태에서는 즉시 수신을 보장하지 않습니다.
- Chrome/Edge 설정의 백그라운드 실행과 Windows 설정 → 시스템 → 알림을 확인합니다.
- 웹 푸시는 브라우저에 따라 Google/ Microsoft/ Mozilla/ Apple의 푸시 서버를 거칩니다. 직원 이름·문서 내용은 전송하지 않고 일반 안내만 암호화해 전송합니다. 조직 네트워크에서 해당 브라우저의 푸시 서비스 연결이 가능해야 합니다.
- 자신의 PC localhost/127.0.0.1에서는 HTTP로 시험할 수 있습니다. 다른 PC·휴대폰에서 접속해 웹 푸시를 사용하려면 HTTPS가 필요합니다. 이 테스트 실행기는 자신의 PC에만 연결하도록 제한되어 있습니다.
- 로그아웃하면 해당 브라우저의 구독을 해제합니다. 다른 기기의 구독은 유지합니다. 계속 받으려면 로그인한 상태에서 창만 닫아 주세요. 재로그인 후 필요한 기기에서 다시 켭니다.
- 알림을 누르면 알림함으로 이동하며, 세션이 만료되었다면 로그인이 필요합니다.

## 구현 및 검증 범위

기존 Notice 알림함은 유지합니다. 15초 상태 조회, 도착 팝업, 선택 알림음, 미결/미확인 메뉴 숫자, 문서별 확인 기록을 추가했습니다. 기존 종류별 확인 기록은 이미 확인한 문서의 개별 기록으로 이전하므로 기존 확인 상태를 보존합니다. 재승인 시 승인 시각이 달라지면 다시 미확인으로 표시됩니다.

푸시는 결재 트랜잭션에서 대기열만 만들고 별도 `run_webpush` 프로세스가 발송합니다. 발송 오류로 기안·승인 요청이 막히지 않습니다. 재시도와 만료 구독 정리, 현재 수신 권한 재확인, 로그아웃 및 계정 전환 보호를 적용했습니다. Web Push는 최선의 전달 방식으로, 감사 기록·기존 알림함과 결재함이 업무 처리 기준입니다.

로컬 검증은 SQLite/MariaDB 회귀 검사, 실제 Chromium의 기안/전결/경리 알림 화면, 320/390/768/1366 폭, CSRF·권한·계정 전환·구독 해제, 암호화된 실제 Web Push 요청 형식을 포함합니다. Chromium 서비스워커에 테스트 이벤트를 주입해 해당 시스템 창이 닫힌 후 알림 표시를 확인했습니다. 브라우저 구독 설정 화면은 가상 구독으로 검증했습니다.

외부 브라우저 푸시 서비스를 거친 실제 PC 수신은 이 클라우드에서 검증하지 않았습니다. 위 10초 테스트로 사용자 PC에서 마지막 수신 확인을 해 주세요. 이 시험 결과만으로 실제 외부 전달을 검증했다고 표시하지 않습니다.

향후 NAS 적용 시 HTTPS 유지, VAPID 비밀키 보존, 실제 운영 연락처(WEBPUSH_CONTACT), 별도 푸시 발송 서비스의 자동 재시작 설정이 필요합니다. 현재 NAS 업데이트 파일이나 배포 작업은 포함하지 않았습니다.
