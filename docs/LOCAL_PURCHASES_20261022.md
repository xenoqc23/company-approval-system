XENOSYS 구매요청 로컬 테스트 · 화면·용어 간소화 (2026-10-22)

새 폴더: xenosys-local-purchase-simple-20261022
접속 주소: http://127.0.0.1:18113/purchase-lab/
이전 ZIP과 별도의 폴더·포트·로그인 쿠키를 사용하며 빈 가상 데이터로 시작합니다.
NAS에는 적용하지 않습니다. 실제 직원 정보·DB·.env·비밀번호·비밀키·업로드 자료는 포함하지 않았습니다.

이번에 정리한 화면
- 진행 중은 파란색, 검토·승인 대기는 주황색, 완료는 녹색, 반려는 붉은색, 취소는 회색입니다. 색상과 함께 상태 이름도 표시합니다.
- ‘내부 승인완료’와 ‘구매 승인완료’를 구분합니다. 대표님 구매승인 직후 기안자에게 완료 알림이 가며 별도 경리 확인은 없습니다.
- 기안자 목록: 진행상황 / 수령 현황 / 현재 담당. 구매 승인완료와 수령 대기·일부 수령·수령 완료를 따로 표시합니다.
- 문서 상단에는 ‘지금 할 일’을 안내하고 현재 단계의 주요 작업을 강조합니다.
- 반려·자료 보완 요청·금액 변경·취소는 ‘추가 작업’을 펼쳐 사용합니다. 변경 기록도 필요할 때 펼쳐 봅니다.
- ‘수령 확인’ 버튼은 ‘받은 수량 등록’으로 바꿨습니다. 수량을 자동 입력하지 않습니다. 실제 받은 수량을 직접 입력합니다.
  등록 전 이번에 받은 수량과 남은 수량을 다시 보여줍니다. 확인창에서 취소한 뒤 다시 등록할 수 있습니다.
- 담당자 홈에는 해당 역할의 ‘지금 처리할 요청’이 바로 표시됩니다. 대표 홈에는 개인 구매 현황을 표시하지 않습니다.

용어 안내
기존 구매요청승인완료함 → 구매 확인함
기존 구매 품목 확인 → 구매 내용 확인
기존 취합·보고 → 구매 모아보기
기존 취합·보고 담당자 → 구매 담당자
기존 선택 품목 요약·보고 → 선택 품목으로 구매요청
기존 재보고 준비 완료 → 다시 요청할 준비 완료
직원 권한관리의 ‘구매 확인 담당’은 기존 구매요청승인완료함과 같은 권한입니다.
권한과 기존 결재·구매 처리 방식은 유지합니다.

처음 실행
1. Python 3.10 이상이 필요합니다. ZIP을 새 폴더에 압축 해제합니다.
2. SETUP_LOCAL_PURCHASES.bat을 실행합니다. 최초 준비에는 인터넷 연결이 필요합니다.
3. 가상 계정 공통 비밀번호를 직접 정합니다. 입력하는 문자가 표시되지 않을 수 있습니다.
4. RUN_LOCAL_PURCHASES.bat을 실행합니다.
5. p_admin과 정한 비밀번호로 로그인합니다.
6. 상단 ‘역할별 테스트’에서 역할을 선택해 전환합니다.
실행 창은 열어 두세요. 종료하려면 실행 창에서 Ctrl+C를 누릅니다.

가상 역할 7개
기안자 p_quality / 검토자 p_quality_manager / 승인자 p_quality_lead
구매 확인 담당자 p_prod_director / 구매 담당자 p_finance
대표 p_ceo / 관리자 p_admin
비밀번호는 첫 준비 때 직접 정한 공통 비밀번호입니다.
기본 기안자는 검토자와 승인자를 모두 거칩니다. 두 역할에 같은 사람을 지정할 수 없습니다.

사용 순서
① 기안자: 구매요청서 작성 → 구매처·수량·단가·구매사유 입력 → 검토자·승인자를 확인하여 제출합니다.
② 검토자: ‘검토·승인할 요청’ → 문서 → ‘검토 완료 · 승인자에게 전달’.
③ 승인자: 문서 → ‘내부 승인 완료’.
④ 구매 확인 담당자: ‘구매 내용 확인’ → 문서 → ‘구매 내용 확인’. 구매 담당자에게 전달됩니다.
   자료가 부족하면 ‘추가 작업 → 자료 보완 요청’. 기안자가 사유·구매 링크·첨부자료를 보완합니다.
⑤ 구매 담당자: ‘모아서 구매요청’ → 품목 선택 → ‘선택 품목으로 구매요청’ → 내용 확인 → ‘대표님께 구매요청’.
   요청 부서·요청자·품목·구매처·수량·금액·구매사유·원본을 함께 확인합니다.
⑥ 대표: ‘구매승인 결정’ → 구매요청서 → 품목별 구매승인·구매반려·구매보류 → ‘선택한 결과 확정’.
   ‘전체 품목 승인으로 선택’한 뒤 예외 품목만 반려·보류로 바꿀 수 있습니다. 반려·보류 사유는 필수입니다.
   임시저장만으로는 승인이 확정되지 않습니다. 최종 확인창에서 품목별 건수·금액을 확인합니다.
⑦ 기안자: 구매 승인완료 알림 확인 → 실제로 물품을 받은 뒤 ‘받은 수량 등록’.
   10개 중 6개만 받았다면 6개만 등록합니다. 남은 4개를 받기 전까지 ‘일부 수령’으로 표시합니다.
   물품을 전부 받아야 수령 완료입니다. 구매승인은 실제 카드·은행 결제 내역을 기록하는 기능이 아닙니다.

함께 유지되는 기능
- 필요한 날짜·긴급 사유. 검토자 결재함에서는 긴급 요청을 우선 표시합니다.
- 부분 수령과 사용 부서·보관 위치. 받은 뒤 보관 위치를 수정할 수 있습니다.
- 유사 구매 안내: 받은 수량·사용 부서·보관 위치도 확인합니다. 수령 이력이며 현재 재고를 뜻하지 않습니다.
- 견적서·영수증 등 첨부파일. 파일당 최대 10MB, 문서당 10개. PDF·이미지·엑셀·워드·한글·텍스트.
- 보완 전후 내용·기존 내부 승인 이력을 유지합니다. 보완 화면에서는 승인받은 품목·수량·금액을 바꾸지 않습니다.
- 구매보류함: 보류 사유를 확인하고 보완 내용을 입력 → 다시 요청할 준비 완료 → 선택하여 새 구매요청.
- 승인 후 금액 변경: 구매 담당자 문서의 ‘추가 작업 → 수량·금액 변경’에서 처리합니다.
  총액 증가 시 대표님께 다시 구매요청해야 합니다. 재승인 전에는 받은 수량을 등록할 수 없습니다.
  금액 감소도 기록을 남기고 기존 승인은 유지합니다. 일부라도 수령했거나 이전 버전에서 실제 결제 완료로 기록한 품목은 변경하지 못합니다.
- 기존 대표 승인 보고서와 품목별 결정·금액은 덮어쓰지 않습니다.
- 홈 ‘구매 승인완료 · 미확인’ 건수는 문서를 열면 줄어듭니다. 목록만 보는 것으로는 확인 처리되지 않습니다.

공개 범위
기안자와 일반 검토·승인자는 기존 결재 경로와 간단한 상태만 봅니다.
구매 진행 현황과 구매 증빙은 해당 구매 처리 담당자만 봅니다. 별도 권한이 없는 관리자에게도 표시하지 않습니다.
원래 기안 첨부자료는 원문 조회 권한에 따라 받을 수 있습니다.
관리자 → 직원 권한관리 → ‘구매 확인 담당’으로 구매 내용 확인 권한을 지정합니다.
부서별·월별 구매 현황은 추가하지 않았습니다.

데이터를 비우고 새로 테스트하기
실행 창 종료(Ctrl+C) → RESET_LOCAL_PURCHASES.bat → 새 공통 비밀번호 지정 → RUN_LOCAL_PURCHASES.bat.
이 폴더의 가상 계정·규정·문서·첨부파일만 초기화합니다. 다른 폴더와 NAS 자료는 변경하지 않습니다.
가상 계정 외 직원 자료·일반 결재문서·연차 자료가 있으면 초기화를 중단합니다.
