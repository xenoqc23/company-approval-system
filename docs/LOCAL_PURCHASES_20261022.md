XENOSYS 구매요청 전용 로컬 테스트 (2026-10-22)

실행 방법
1. ZIP을 PC의 새 폴더에 압축 해제합니다. 기존 NAS 또는 기존 테스트 폴더를 덮어쓰지 않습니다.
2. Python 3.10 이상이 필요합니다. 처음에는 인터넷 연결이 필요합니다.
3. SETUP_LOCAL_PURCHASES.bat을 실행합니다.
4. 처음 설치할 때 가상 계정 공통 비밀번호를 직접 입력합니다. 입력 문자는 화면에 표시되지 않을 수 있습니다.
5. 설치 완료 후 RUN_LOCAL_PURCHASES.bat을 실행합니다. 브라우저가 자동으로 열립니다.
6. p_admin과 위에서 정한 비밀번호로 로그인합니다.
7. 화면 상단 ‘역할별 테스트’에서 계정을 선택하고 ‘이 계정으로 전환’을 누르세요.
8. 테스트 실행 창은 열어두고 사용합니다. 종료는 실행 창에서 Ctrl+C입니다.

이 ZIP은 NAS 업데이트가 아닙니다. PC 안에서만 실행되는 구매 전용 가상 테스트입니다.
구매요청·구매 규정·취합 구매허가·기안자 진행상황만 표시합니다.
실제 직원·비밀번호·생일·문서·연차·DB·.env·비밀키는 들어 있지 않습니다.
별도 var/purchase-test 데이터와 별도 브라우저 쿠키를 사용하며 NAS와 통신하지 않습니다.
다시 SETUP을 실행하면 구매 테스트 DB를 백업하고 기존 가상 계정 비밀번호·요청·규정을 보존합니다.
기존 직원이 있는 DB에는 가상 계정을 만들지 않습니다.

가상 계정 (비밀번호는 처음에 직접 정한 공통 비밀번호)
p_admin: 관리자 / 구매 규정 설정
p_dev: 개발팀 직원 / 구매요청 작성
p_dev_lead: 개발팀 팀장 / 중간 승인 경로 테스트
p_dev_director: 개발팀 이사 / 개발팀 요청 최종승인
p_quality: 품질팀 직원 / 검토·승인 후 생산팀 이사 경로
p_quality_manager: 품질팀 과장 / 검토 담당, 본인 요청은 이사에게 직접
p_quality_lead: 품질팀 팀장 / 중간 승인 담당
p_sales_manager: 영업팀 부장 / 생산팀 이사에게 직접 요청
p_prod_director: 생산팀 이사 / 개발팀 외 부서 최종승인
p_finance: 경리 / 품목 선택·취합·대표 보고·결제 확인
p_ceo: 대표 / 품목별 구매허가·불허·보류

권장 테스트 순서
A. 개발팀 경로
- p_dev로 ‘구매요청’을 작성합니다. 구매처·수량·금액·구매사유를 입력하세요. 구매 링크는 선택입니다.
- p_dev_director로 전환하고 ‘처리할 문서’에서 해당 요청을 엽니다.
- ‘부서 최종승인 · 경리 전달’을 누릅니다.
- p_finance의 ‘경리 취합’에 표시되는지 확인합니다. 이사 승인 전에는 경리에게 표시되지 않습니다.

B. 타 부서 일반 직원 경로
- p_quality로 구매요청을 작성합니다.
- 검토자: 가상품질과장, 중간 승인자: 가상품질팀장을 선택합니다.
- p_quality_manager 검토 → p_quality_lead 중간 승인 → p_prod_director 부서 최종승인 순서로 처리합니다.
- 개발팀 이사는 이 요청을 볼 수 없으며, 경리에게는 생산팀 이사 승인 후 표시됩니다.

C. 과장·팀장·부장 직접 요청
- p_quality_manager 또는 p_sales_manager로 작성합니다.
- 중간 검토자·승인자를 지정하지 않고 바로 생산팀 이사에게 요청합니다.
- 생산팀 이사가 ‘부서 최종승인 · 경리 전달’을 눌러야 경리가 취합할 수 있습니다.

D. 경리 취합과 대표 품목별 심사
- p_finance → 경리 취합에서 여러 품목을 체크합니다.
- ‘선택 품목 요약·보고’를 누르면 요청 부서·요청자·품목·구매처·수량·금액·구매사유를 확인할 수 있습니다.
- 원래 구매요청 문서 링크도 제공됩니다.
- 보고 제목·내용을 입력하고 ‘대표님께 구매허가 요청’을 누릅니다.
- p_ceo → 취합 구매허가에서 보고서를 엽니다.
- 각 품목을 구매허가·구매불허·보류로 따로 선택하세요. 불허·보류에는 사유가 필요합니다.
- ‘심사 내용 임시저장’만으로는 구매허가가 확정되지 않습니다.
- 모든 품목을 결정한 뒤 ‘품목별 결정 최종 확정’을 누릅니다.
- 허가 금액·불허 금액·보류 금액을 구분해 표시합니다.
- 보류 품목은 경리가 다시 선택하여 새 보고서로 재보고할 수 있습니다. 이전 결과는 남습니다.

E. 실제 결제와 수령
- 대표 구매허가가 난 품목만 ‘결제 완료 확인’을 할 수 있습니다.
- p_finance 또는 해당 대표가 실제 결제를 확인한 뒤 결제 확인 내용을 기록합니다.
- 이 기능은 결제 사실을 기록하며 카드·은행 결제를 실행하지 않습니다.
- 요청자가 물품을 받은 후 ‘물품 수령 완료’를 누릅니다.

기안자에게 보이는 진행상황
요청 작성 → 내부 검토·중간 승인(규정에 따라 생략) → 담당 이사 최종승인 → 경리 취합 → 대표 구매허가 → 실제 결제·수령
- 이사 승인 후: ‘부서 승인 완료 · 경리 취합 대기’. 아직 구매허가 전이라고 표시합니다.
- 경리 보고 후: ‘대표 구매허가 심사 중’과 취합 문서번호를 표시합니다.
- 대표 확정 후: 해당 품목의 ‘구매허가 완료 · 결제 대기 / 구매불허 / 구매보류’를 표시합니다.
- 반려·불허·보류 사유와 처리 담당자·일시가 이력에 남습니다.
- 요청자는 자기 품목과 결과를 확인합니다. 다른 부서 품목이 섞인 취합 문서 전체는 경리·담당 대표·관리자만 볼 수 있습니다.

보기 쉬운 구매 규정
p_admin → 구매 규정
① 개발팀 이사와 그 외 부서의 생산팀 이사를 지정합니다.
② 직급별로 ‘이사님에게 바로 요청 / 승인 → 이사님 / 검토 → 승인 → 이사님’을 선택합니다.
③ 경리 취합 담당자와 대표님을 지정합니다.
④ 변경 사유를 입력하고 저장합니다.
‘바로 요청’도 이사님의 최종승인은 반드시 거칩니다.
진행 중인 요청의 검토자·승인자·담당 이사는 유지하고, 새 요청부터 변경 경로를 적용합니다.
경리 담당자 권한 변경은 현재 취합 업무에 반영됩니다.

초기 규정
- 개발팀: 전 직급이 개발팀 이사에게 바로 요청하도록 시작합니다. 필요한 직급에는 중간 단계를 추가할 수 있습니다.
- 개발팀 외: 사원·주임·대리는 검토·승인, 과장·팀장·부장·이사는 생산팀 이사에게 직접 요청합니다.
- 고액이라고 자동으로 다른 결재 경로를 강제하지 않습니다. 이 테스트에서는 모든 품목이 경리 취합 후 대표 구매허가를 받습니다.

화면 예시는 examples 폴더에 있습니다. 모두 가상 직원·가상 품목으로 만든 화면입니다.

처럼 다른 포트로 실행할 수 있습니다.
