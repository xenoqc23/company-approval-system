XENOSYS 구매요청 로컬 테스트 · 내부 결재 / 구매 진행 분리 (2026-10-22)

이 파일은 NAS 업데이트가 아닙니다. 실제 직원 데이터·.env·비밀번호·비밀키 없이 PC의 별도 가상 데이터로 실행합니다.
기존 사내결재 로고·왼쪽 메뉴·홈·기안 양식을 사용하고 구매 테스트에 필요한 메뉴만 표시합니다.

처음 설치
1. ZIP을 PC의 새 폴더에 압축 해제합니다. Python 3.10 이상이 필요합니다.
2. SETUP_LOCAL_PURCHASES.bat을 실행합니다. 처음에는 인터넷 연결이 필요합니다.
3. 가상 계정 공통 비밀번호를 직접 정합니다. 입력 문자가 표시되지 않을 수 있습니다.
4. RUN_LOCAL_PURCHASES.bat을 실행합니다.
5. p_admin과 위에서 정한 비밀번호로 로그인합니다.
6. 상단 ‘역할별 테스트’에서 필요한 역할을 선택하고 ‘이 계정으로 전환’을 누릅니다.
7. 기본 접속 주소: http://127.0.0.1:18105/purchase-lab/
실행 창은 열어두세요. 종료는 실행 창에서 Ctrl+C입니다.

이전 구매 테스트 업데이트
1. 실행 중인 테스트 서버를 Ctrl+C로 종료합니다.
2. 새 ZIP을 임시 폴더에 풉니다.
3. xenosys-local-purchases-20261022 폴더 안의 파일·폴더를 기존 동명 테스트 폴더 안으로 복사하고 같은 파일을 덮어씁니다.
4. 기존 var 및 .venv 폴더는 삭제하지 마세요. ZIP에는 이 폴더들이 없습니다.
5. 기존 폴더에서 SETUP_LOCAL_PURCHASES.bat → RUN_LOCAL_PURCHASES.bat 순서로 실행합니다.
6. 예전 화면이 남아 있으면 Ctrl+F5로 새로고침합니다.
설치 시 기존 로컬 DB를 자동 백업합니다. 기존 가상 계정·비밀번호·문서·기존 결재 담당자·규정을 초기화하지 않습니다.
과거 테스트에서 이미 보고 중이거나 구매허가가 난 문서는 기존 담당자가 이어서 처리할 수 있습니다.
과거 미처리 승인완료 문서는 구매 품목 확인을 거쳐야 새 보고에 포함할 수 있습니다.
새 내부 결재 경로는 새 문서부터 적용합니다. 이전 테스트 계정은 삭제하지 않고 역할 선택 목록만 줄였습니다.

테스트 역할: 7개
- 기안자 p_quality: 품질팀 직원
- 검토자 p_quality_manager: 품질팀 과장
- 승인자 p_quality_lead: 품질팀 팀장
- 구매 품목확인자 p_prod_director: 생산팀 이사
- 취합·보고 담당자 p_finance
- 대표 p_ceo: 품목별 구매허가·불허·보류
- 관리자 p_admin: 규정 및 직원 권한관리
비밀번호는 모두 처음에 직접 정한 공통 비밀번호입니다.

권장 테스트 순서
1. 기안자로 전환하고 구매요청서를 작성합니다.
   품목·구매처·수량·단가·구매사유를 입력합니다. 구매 링크는 선택입니다.
   검토자는 가상품질과장, 승인자는 가상품질팀장을 선택합니다.
   50000 또는 50,000을 입력하면 50,000원으로 저장·표시됩니다.
2. 검토자로 전환 → 결재함 → 문서를 열어 ‘검토 완료 · 승인자 전달’을 누릅니다.
3. 승인자로 전환 → 결재함 → ‘최종 승인’을 누릅니다.
   기존 결재 경로는 기안·검토·승인 3개 카드로 완료됩니다.
   구매 품목 확인을 기존 결재선에 추가하지 않습니다.
4. 구매 품목확인자로 전환 → ‘구매요청승인완료함’을 엽니다.
   부서에 관계없이 내부 결재가 완료된 구매요청서를 볼 수 있습니다.
   문서를 열어 ‘구매 품목 확인’을 누릅니다. 확인 전에는 취합 대상이 아닙니다.
   확인 후에만 기존 결재 경로 아래에 별도의 ‘구매 진행 현황’이 표시됩니다.
5. 취합·보고 담당자로 전환합니다.
   확인된 품목만 목록에 표시됩니다. 여러 품목 선택 → ‘선택 품목 요약·보고’를 누릅니다.
   요청 부서·요청자·품목·구매처·수량·금액·구매사유·원문 링크를 확인합니다.
   제목과 내용을 작성하고 ‘대표님께 구매허가 요청’을 누릅니다.
6. 대표로 전환 → 취합 구매허가 → 각 품목에 허가·불허·보류를 따로 지정합니다.
   불허·보류에는 사유가 필요합니다. 임시저장만으로는 허가되지 않습니다.
   모든 품목 결정 후 ‘품목별 결정 최종 확정’을 누릅니다.
7. 취합·보고 담당자는 허가된 품목의 실제 결제 완료를 기록합니다.
   이 기능은 카드·은행 결제를 실행하지 않고 결제 사실을 기록합니다.
8. 기안자가 물품을 받으면 ‘물품 수령 완료’를 누릅니다.

화면 공개 범위
- 기안자: 기존 결재 경로와 ‘구매 진행 중’ 등 간단한 상태만 봅니다. 구매불허·보류 사유와 수령 확인은 가능합니다.
- 일반 검토자·승인자: 기존 내부 결재 경로만 봅니다.
- 구매 품목확인자: 확인 후 본인이 시작한 구매 진행 라인을 봅니다.
- 해당 문서의 지정된 취합·보고 담당자와 보고받은 대표: 구매 진행 현황을 봅니다.
- 관리자는 규정·권한을 관리하더라도 별도 구매 담당 권한 없이는 구매 진행 현황을 볼 수 없습니다.
- 기안자가 별도 권한을 가지고 있어도 본인 요청의 구매 진행 현황은 표시하지 않고 직접 품목 확인할 수 없습니다.
- 원문 문서를 볼 권한만으로 여러 부서가 섞인 취합 보고서 전체를 볼 수는 없습니다.
구매 진행 현황: 구매 품목 확인 → 취합·보고 → 대표 구매허가 → 결제·수령
‘경리 취합·보고’라는 단계명은 사용하지 않습니다.

권한과 규정 설정
관리자 → 직원 권한관리: ‘구매요청승인완료함’을 직원별로 체크하고 저장합니다.
기본 가상 데이터는 생산팀 이사에게 부여합니다. 마지막 확인 담당자를 모두 해제할 수는 없습니다.
관리자 → 규정 관리:
① 직급별 내부 결재: 기안·검토·승인 / 검토 생략 / 본인 전결
② 구매 품목확인자는 직원 권한관리에서 지정
③ 취합·보고 담당자 및 대표 지정
④ 변경 사유 입력 후 저장
기본 내부 결재는 사원·주임·대리 검토·승인, 과장 이상 본인 전결입니다.
구매 품목 확인 시 취합·보고 담당자를 문서에 기록하며, 이후 규정 변경으로 진행 중인 문서의 담당자를 자동 교체하지 않습니다.
담당자 권한을 회수하면 해당 구매 처리 권한도 중단됩니다.
