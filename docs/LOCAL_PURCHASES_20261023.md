XENOSYS 구매요청 로컬 테스트 · 부서별 경로와 수령 현황 (2026-10-23)

새 폴더: xenosys-local-purchase-departments-20261023
기본 접속 주소: http://127.0.0.1:18115/purchase-lab/
이전 테스트와 별도의 폴더·주소·로그인 쿠키를 사용하며 빈 가상 데이터로 시작합니다.
NAS 업데이트 파일이 아닙니다. 실제 직원 정보·DB·.env·비밀번호·비밀키·업로드 자료는 포함하지 않았습니다.

처음 실행
1. Python 3.10 이상이 필요합니다. ZIP을 새 폴더에 압축 해제합니다.
2. SETUP_LOCAL_PURCHASES.bat을 실행합니다. 최초 준비에는 인터넷 연결이 필요합니다.
3. 가상 계정의 공통 비밀번호를 직접 정합니다. 입력하는 문자가 표시되지 않을 수 있습니다.
4. RUN_LOCAL_PURCHASES.bat을 실행하고 p_admin과 정한 비밀번호로 로그인합니다.
5. 상단 ‘역할별 테스트’에서 계정을 전환합니다. 개발팀 / 그 외 부서 / 공통 역할로 묶었습니다.
실행 창을 열어 두세요. 종료하려면 실행 창에서 Ctrl+C를 누릅니다.

테스트 역할 10개
그 외 부서: p_quality 기안자(사원), p_quality_manager 과장·검토자, p_quality_lead 승인자, p_prod_director 생산팀 이사
개발팀: p_dev_manager 과장·기안자, p_dev_lead 검토자, p_dev_director 개발팀 이사
공통: p_finance 구매담당자(경리), p_ceo 대표, p_admin 관리자
모두 처음에 정한 공통 비밀번호를 사용합니다.

규정관리에서 정하는 것
1. ‘구매담당자에게 요청’을 사용할 직급: 기본은 과장·팀장·부장·이사입니다.
   체크하지 않은 직급과 사원·주임·대리는 ‘검토 요청’으로 제출합니다. 화면과 서버 모두 권한을 검사합니다.
   검토 요청은 기본적으로 검토자 → 승인자입니다. ‘검토 요청 경로 설정’에서 승인자만 지정하도록 바꿀 수도 있습니다.
2. 부서별 구매 확인 담당 이사: 개발팀은 개발팀 이사, 그 외 모든 부서는 생산팀 이사입니다.
   담당자를 저장하면 구매 확인 권한도 함께 부여됩니다. 체크 권한만 있는 다른 직원이 모든 부서를 처리하지는 못합니다.
3. 중복 확인 예외: 기본적으로 두 항목 모두 사용합니다.
   - 최종 승인자와 지정된 구매 확인 담당 이사가 같으면 ‘승인하고 구매담당자에게 전달’ 한 번으로 함께 처리합니다.
     이력은 ‘승인 시 함께 확인’으로 남습니다. 다른 이사가 승인했다면 지정된 이사의 구매 확인을 거칩니다.
   - 지정된 담당 이사 본인이 ‘구매담당자에게 요청’하면 구매담당자에게 바로 전달합니다.
     이력은 ‘담당 이사 직접 요청’입니다. 본인이 본인을 확인한 기록을 만들지 않습니다.
     이 예외를 끄면 다른 부서 담당 이사가 대신 구매 내용을 확인합니다.
4. 구매담당자와 최종 구매승인 대표를 지정합니다. 대표님의 품목별 구매승인은 항상 거칩니다.
규정 아래에서 부서·직급·요청 방식을 골라 적용 경로를 미리 볼 수 있습니다.
변경한 규정은 새로 제출하는 문서부터 적용합니다. 이미 제출한 문서는 당시 담당자와 예외 설정을 유지합니다.
진행 문서가 남아 있는 담당자의 구매 확인 권한은 해제할 수 없습니다.

요청 방식 테스트
A. 과장급 이상의 직접 요청
- p_dev_manager → 구매요청서 작성 → ‘구매담당자에게 요청’ 선택 → 같은 이름의 제출 버튼.
- p_dev_director → 구매 확인함 → 해당 문서 → ‘구매 내용 확인’.
- p_finance → 구매 모아보기에서 문서 확인.
- 다른 부서 과장 p_quality_manager도 같은 방식으로 제출하되, p_prod_director가 구매 내용을 확인합니다.
  직접 요청은 검토·승인을 생략하지만 담당 이사의 구매 확인은 거칩니다.

B. 일반 검토 요청
- p_quality → 구매요청서 작성 → 검토자 p_quality_manager / 승인자 p_quality_lead 확인 → ‘검토 요청’.
- p_quality_manager → 검토 완료, p_quality_lead → 내부 승인 완료.
- p_prod_director → 구매 내용 확인 → p_finance에게 전달.

C. 이사의 중복 확인 통합
- p_dev_manager → ‘검토 요청’ 선택. 검토자는 p_dev_lead, 승인자는 p_dev_director로 미리 선택되어 있습니다.
- p_dev_lead → 검토 완료, p_dev_director → ‘승인하고 구매담당자에게 전달’.
- 개발팀 이사가 구매 확인함에서 다시 확인하지 않아도 p_finance에게 전달됩니다.

D. 담당 이사 본인 요청
- p_dev_director 또는 p_prod_director → 구매요청서 작성 → ‘구매담당자에게 요청’.
- 구매담당자에게 바로 전달되고 ‘담당 이사 직접 요청’으로 표시됩니다.
- 이 단계는 대표님의 구매승인이 아닙니다. 구매담당자가 대표님께 구매요청해야 합니다.

구매승인과 수령 결과 테스트
1. p_finance → 구매 모아보기 → 확인된 품목 선택 → ‘선택 품목으로 구매요청’.
2. 부서·요청자·품목·구매처·수량·금액·구매사유·원본을 확인하고 대표님께 구매요청합니다.
3. p_ceo → 구매요청함 → 품목별 구매승인·구매반려·구매보류 선택 → ‘선택한 결과 확정’.
   전체 승인으로 선택한 뒤 예외 품목만 반려·보류로 바꿀 수 있습니다. 반려·보류 사유는 필수입니다.
4. 승인된 품목은 기안자에게 바로 ‘구매 승인완료’ 알림이 갑니다. 경리의 별도 결제 확인 단계는 없습니다.
5. 기안자는 실제로 받은 수량을 ‘받은 수량 등록’에서 입력합니다.
   10개 중 6개를 먼저 받으면 6개만 등록합니다. 남은 4개를 등록해야 수령 완료가 됩니다.
6. p_finance → 구매 모아보기의 ‘받은 수량 / 수령 현황’에서 6/10개 · 일부 수령, 10/10개 · 수령 완료를 확인합니다.
   수령자·등록일도 표시합니다. ‘모든 수령 현황’ 필터로 대기·부분 수령·완료를 골라 조회할 수 있습니다.
   수령 완료 목록에는 구매요청 선택 버튼이 표시되지 않습니다.
7. 대표님께 올렸던 구매요청서를 다시 열면 품목별 최신 수령 결과와 전체 집계를 확인할 수 있습니다.
   예: 구매 결정은 승인 4건·반려 1건·보류 1건 / 수령은 승인된 4개 품목 중 2개 수령 완료.
   반려·보류·승인 전 품목은 수령 대기 건수에 포함하지 않습니다.
   승인 후 금액 변경으로 다시 요청하는 품목은 이전 보고서의 현재 수령 집계에서 제외하고 별도 안내합니다.
수령 결과는 원래 요청에서 읽어 표시하므로 기존 승인 금액·품목별 결정·승인 문서를 덮어쓰지 않습니다.
수령 등록 시 해당 구매담당자에게 알림이 남습니다. 목록을 조회하거나 구매요청서를 다시 열면 최신 결과가 표시됩니다.

함께 유지한 기능
- 필요한 날짜·긴급 요청, 구매처·구매사유, 유사 구매 안내와 사용 부서·보관 위치.
- 견적서·영수증 등 첨부: 파일당 최대 10MB, 문서당 10개. PDF·이미지·엑셀·워드·한글·텍스트.
- 자료 보완 요청과 보완 자료 추가. 구매 확인 담당자의 ‘추가 작업’에서 사용합니다.
- 구매보류함에서 보완 내용을 기록하고 다시 구매요청.
- 승인 후 금액 변경: 수령 전 ‘추가 작업 → 수량·금액 변경’. 증가하면 재승인 전까지 수령 등록을 막습니다.
  감소도 이력을 남깁니다. 일부라도 받았거나 이전 버전에서 결제 완료로 기록한 문서는 변경하지 못합니다.
- 기안자 ‘구매 승인완료 · 미확인’ 건수는 문서를 열면 줄어듭니다.
- 상태 색상: 진행은 파란색, 대기는 주황색, 완료는 녹색, 반려는 붉은색, 취소는 회색.
- 현재 주요 작업만 강조하며 보완·금액 변경·취소·처리 기록은 필요할 때 펼칩니다.
구매승인은 실제 카드·은행 결제 내역을 기록하는 의미가 아닙니다. 실제 수령 수량을 등록해야 수령 완료입니다.

문서 공개 범위
개발팀·그 외 부서 담당 이사는 자신에게 배정된 구매 확인 문서만 확인합니다.
기안자와 일반 검토·승인자는 기존 결재 경로와 간단한 구매 상태를 봅니다.
상세 구매 진행 경로와 구매 증빙은 해당 구매 처리 담당자만 봅니다. 일반 관리자도 별도 권한이 없으면 보이지 않습니다.
구매 모아 올린 문서는 해당 구매요청 담당자와 지정된 대표가 확인합니다.

초기화
실행 창 종료(Ctrl+C) → RESET_LOCAL_PURCHASES.bat → 새 공통 비밀번호 지정 → RUN_LOCAL_PURCHASES.bat.
이 폴더의 가상 계정·규정·문서·첨부파일만 초기화합니다. 다른 폴더나 NAS 자료는 변경하지 않습니다.
가상 계정 외 직원 자료·일반 결재문서·연차 자료가 있으면 초기화를 중단합니다.
