사내결재시스템 전체 기능 · 화면·용어 간소화 로컬 테스트

폴더: xenosys-local-simple-20261023
주소: http://127.0.0.1:18131/
로그인: admin / 설치할 때 직접 정한 테스트 비밀번호

기존 사내결재시스템 전체 기능과 새 구매요청을 유지하면서 이번에 요청한 1~11번 및 본인 전결 제거를 반영했습니다. 실제 NAS에는 접속하거나 업데이트하지 않았습니다.

실행 방법

1. Python 3.10 이상이 설치된 PC에서 ZIP 전체를 새 폴더에 풉니다. 이전 테스트 폴더에 덮어쓰지 마세요.
2. SETUP_LOCAL_FULL.bat 실행 → 가상 계정 공통 비밀번호를 직접 정합니다.
3. RUN_LOCAL_FULL.bat 실행 → 브라우저에서 admin으로 로그인합니다.
4. 상단 역할 전환으로 기안자·검토자·승인자·담당 이사·구매 담당자·대표를 확인합니다.
5. 종료는 실행 창에서 Ctrl+C. 초기화는 실행 종료 후 RESET_LOCAL_FULL.bat입니다.

새 설치는 가상 직원 12명, 표시 역할 10개, 문서 0건으로 시작합니다. 실제 직원 정보·DB·첨부·비밀번호·.env·비밀키는 포함하지 않습니다. 이전 테스트와 데이터 폴더·포트·로그인 쿠키를 분리했습니다. 데이터는 이 폴더의 var/full-nas-test-v2/purchase-test에만 저장됩니다.

반영 사항

1. 구매요청서 결재선: PC에서는 검토자 부서·검토자를 왼쪽, 승인자 부서·승인자를 오른쪽에 표시합니다. 모바일에서는 세로로 정렬합니다.
2. 구매 담당자의 구매요청함에 완료 탭을 추가했습니다. 대표 승인 후 수령까지 완료된 품목을 모아봅니다.
3. 구매 목록의 문서번호를 숨기고 품목명 아래에 기안자·구매처를 표시합니다. 문서번호는 내부 관리·원본 상세·엑셀에서 보존합니다.
4. 대표의 구매승인 대기는 기존 미결 건수와 결재함에 포함합니다. 별도 홈 구매승인 결정 카드와 대표용 구매요청함 메뉴를 없앴습니다.
5. 대표가 처리한 묶음 구매요청은 내 승인 내역에서 확인합니다. 결재함·내 문서함·내 승인 내역에서 전체 / 휴가원 / 구매요청 / 생산 재고 탭으로 분류합니다. 구매 담당자의 확인·취합·요청·수령 업무는 구매요청함에 유지합니다.
6. 수령 개수·부분 수령 집계·남은 수량 등 복잡한 표시를 없앴습니다.
7. 대표가 승인한 품목은 결재완료 상태를 고정하고 옆에 수령 대기 / 수령 완료를 표시합니다. 보류 품목이 남은 묶음 요청은 전체 결재완료로 표시하지 않습니다. 승인·반려가 섞인 완료 요청은 결재완료 · 일부 승인으로 구분합니다.
8. 기안자 알림은 누가 검토했는지, 누가 승인했는지, 대표의 최종 결재완료를 알립니다. 구매확인·취합·금액 변경 등 내부 처리만으로는 기안자에게 진행 알림을 반복해서 보내지 않습니다. 반려·보완 요청·보류 알림은 유지합니다.
9. 물품을 모두 받으면 수령 완료 버튼을 한 번 누릅니다. 수령 수량 입력은 없습니다. 사용·보관 위치와 메모는 남길 수 있습니다. 기존 부분 수령 기록은 보존하고, 완료 시 남은 수량을 내부적으로 반영하므로 중복 차감·중복 등록하지 않습니다.
10. 구매 규정의 구매확인 담당자 지정·변경 링크를 누르면 직원 권한관리 상단의 구매 업무 담당자·권한 설정이 펼쳐집니다. 직원 개별 카드의 연차·기존 문서 권한과 구분했습니다.
11. 휴가원 규정은 규정 이름·사용 여부 / 결재 가능한 직급 / 과장급 이상 요청 방식으로 정리했습니다. 검토자 전결, 부서·직원 예외·고정 결재선, 승인자의 대표 추가 결재 기준은 접힌 상세 설정으로 유지합니다. 실제 적용 조건이 겹치면 기존 우선순위·중복 검사를 적용합니다.

본인 전결 제거와 용어

- 휴가원의 과장·팀장·부장·이사: 검토·승인 요청 / 대표 결재 요청. 대표 결재는 규정에서 허용하고 결재 가능한 대표가 지정된 경우 선택합니다.
- 새 휴가원에서 기존 본인 전결과 승인자 본인 고정 설정은 사용하지 않습니다. 예전 본인 전결·검토 생략 규정은 대표 결재 요청 선택으로 연결하고, 규정을 저장하면 없어진 본인 전결 설정을 해제합니다.
- 일반 휴가원은 기존 단계별 결재처럼 검토자가 상위 승인자를 선택합니다. 지정한 검토자의 전결 권한은 유지하며, 본인 문서 전결은 허용하지 않습니다.
- 구매요청: 검토·승인 요청 / 구매담당자에게 요청. 직접 요청도 개발팀은 개발 이사, 그 외 부서는 생산 이사의 구매확인을 거친 뒤 구매 담당자에게 전달합니다. 구매 담당자가 취합하여 대표에게 요청합니다.
- 최종 승인자가 구매확인 담당자와 같으면 한 번에 승인·확인합니다. 담당 이사 본인의 직접 구매요청은 본인 승인 기록을 만들지 않고 구매 담당자에게 전달되며 대표 승인은 반드시 받습니다.
- 내부 검토·승인 완료는 승인완료, 대표의 구매 승인 이후는 결재완료로 구분합니다. 수령 상태는 별도로 표시합니다.

역할별 테스트 예시

- 그 외 부서 기안자 → 구매요청 작성 → 검토자 → 승인자 → 생산팀 이사 구매 내용 확인
- 개발팀 과장 → 구매담당자에게 요청 → 개발팀 이사 구매 내용 확인
- 구매 담당자 → 구매요청함 → 요청할 품목 선택 → 대표님께 구매요청
- 대표 → 기존 결재함 → 구매요청 열기 → 품목별 승인·반려·보류 → 결과 확정 → 내 승인 내역
- 기안자 → 내 문서함 → 결재완료 확인 → 물품을 모두 받으면 수령 완료
- 구매 담당자 → 구매요청함의 완료 탭 → 수령 완료 확인
- 관리자 → 규정 관리 → 휴가원 / 구매요청, 직원·권한 관리 → 구매 업무 담당자·권한

기존 기능과 데이터

휴가원·생산 재고·일정·복지·직원·연차·최종문서 정정·알림·백업 등의 기존 기능을 유지합니다. 기존 구매문서는 원래 경로로 보존하고 새 구매요청과 구분합니다. 기존 승인 문서·비밀번호·연차·규정 원본·승인 이력을 일괄 삭제하거나 새 구매 절차로 자동 전환하지 않습니다.

운영 NAS에서도 같은 소스를 사용합니다. 운영에서 가상 계정 생성과 역할 전환은 차단합니다. 이번 테스트 파일로 NAS를 업데이트하지 않았습니다. 실제 NAS 적용 시 구매 담당자와 권한을 지정하고 구매 규정을 켜는 절차가 필요합니다. DB와 견적서·증빙파일의 백업·복구는 유지합니다.

브라우저를 닫았을 때 웹 푸시는 앞서 합의한 대로 보류합니다. 화면 알림·알림함·미결·완료 미확인 집계는 유지합니다.

검증

SQLite 통합 39건과 NAS 방식의 MariaDB 통합·동시 처리 50건, 기존 workflow 호환 319건 중 298건 통과·환경별 21건 건너뜀. Chromium에서 구매 전 과정·알림·대표 공통 결재함/내역·완료 탭·수령 버튼·첨부 권한·엑셀·가로 결재선·휴가원 두 선택지·규정 저장·설정 바로가기·320~2560px 화면을 확인했습니다.

Windows BAT 명령과 줄바꿈을 검사했고 실행·브라우저 검증은 Linux Python/Chromium 및 MariaDB에서 수행했습니다. 실제 Windows PC 실행 검증은 남아 있습니다. 가상 화면 예시는 examples 폴더에 있습니다.
