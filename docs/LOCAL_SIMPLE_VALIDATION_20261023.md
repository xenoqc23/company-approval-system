# 화면·용어 간소화 검증 · 2026-10-23

기존 전체 기능을 유지하고 사용자가 정리한 1~11번 및 본인 전결 제거를 반영했다. 실제 NAS에는 접속하거나 업데이트하지 않았다.

- SQLite 통합 39건 통과: 대표 묶음 요청의 공통 미결/내역 합류, 화면 분류·권한, 문서번호 비노출, 수령 완료와 완료 탭, 기존 부분 수령 자료 보존, 기안자 이정표 알림·확인 합침, 보류 포함 요청의 상태, 규정·설정 위치, 모든 관리 직급의 두 결재 방식, 본인 전결 위조 차단, 대표 승인 시 연차 차감, 기존 백업 검증.
- MariaDB 10.11에서 위 검사와 중복 취합·승인·수령, 승인과 금액 변경 경쟁, 부서별 확인 경쟁을 포함한 50건 통과.
- 기존 workflow 호환 검사 319건: 298건 통과·환경별 21건 건너뜀. 호환 모드의 기존 기록 처리도 유지했다.
- Chromium 실제 6개 요청: 일반 검토·승인, 개발팀/그 외 직접 요청, 승인 시 구매확인 합침, 이사 본인 구매요청, 독립 검토자 도착 팝업, 대표 품목별 승인4/반려1/보류1, 대표 공통 승인 내역, 단순 수령 완료, 구매 담당자 완료 탭, 증빙파일 권한, 엑셀, 규정 변경, 기존 메뉴, 반응형 320/390/768/1366/2560px. JS 오류·누락 자산 없음.
- PC 검토·승인 좌우 배치를 실제 요소 좌표로 확인, 모바일 세로 배치와 넘침 없음 확인.
- 휴가원 관리 직급의 검토·승인 요청/대표 결재 요청, 대표 선택 시 일반 담당자 숨김, 본인 전결 미노출 확인.
- 실제 휴가원 규정 수정·저장 성공 및 담당자 설정 링크에서 접힌 설정이 열리는지 확인.
- 새 ZIP은 이전 배포물을 덮어쓰지 않고 새 이름·폴더·포트·데이터·쿠키로 격리한다. 설치 시 가상 직원 12명, 문서 0건.
- 개인키·비밀번호·실제 직원 데이터·DB·.env는 ZIP/저장소에 추가하지 않는다. 첨부 경로와 체크섬을 포함한 기존 백업을 유지한다.

기존 본인 전결 처리 내역을 변조하지 않는다. 새 제출에서는 기존 self/skip 선택과 기안자 자신의 검토·승인을 차단한다. 기존 직접 요청용 구매 모드 코드는 후속 구매확인·대표 승인이 필요한 경로이며 제출 즉시 결재완료가 되지 않는다.

규정 편집의 폐기된 필드는 표시하지 않고 새로 저장할 때 false로 해제한다. 기존 규정 원본의 본인 전결/검토 생략은 새 휴가원의 대표 결재 선택으로 연결한다. 새 구매정책은 기존대로 독립적이다.

검증은 Linux Python/Chromium과 MariaDB에서 수행했다. Windows BAT는 명령·CRLF 검사만 수행했고 실제 Windows 실행은 아직 수행하지 않았다. 닫힌 브라우저 웹 푸시는 보류한다.
