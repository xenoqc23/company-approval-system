# 구매요청 · 경리 구매 집계 로컬 테스트

폴더: xenosys-local-summary-20261026
주소: http://127.0.0.1:18171/
로그인: admin / 설치할 때 직접 정한 테스트 비밀번호

대표님은 품목 정보를 조회하고 실제 결제를 진행합니다. 결제 사실을 전달받은 경리 담당자가 결제 완료를 등록하면 해당 품목이 최종결재완료로 바뀝니다. 대표님의 시스템 승인 버튼은 새 결제 요청에서 사용하지 않습니다. 실제 이체·카드 결제를 실행하거나 은행 내역과 자동 연동하는 프로그램은 아닙니다.

## 구매 집계 사용법

경리 역할로 전환한 뒤 **구매요청함 → 구매 집계**를 엽니다.

1. 시작일·종료일을 지정합니다. 기본은 이번 달이며 이번 달 / 올해 버튼을 사용할 수 있습니다.
2. 전체 팀 또는 특정 팀을 선택합니다.
3. 필요한 직원을 여러 명 체크합니다. 아무도 선택하지 않으면 해당 팀의 전체 직원을 집계합니다.
4. 집계 보기를 누르면 총 구매금액·구매내역 건수와 팀별·직원별 합계를 확인합니다.
5. 구매내역에는 결제완료일·팀·기안자·품목·구매처·수량·금액·용도가 표시됩니다. 원본 문서도 열 수 있습니다.
6. 현재 조건으로 엑셀 다운로드를 누르면 **집계 요약 / 구매내역** 두 시트로 받습니다. 화면의 다음 페이지까지 모두 포함합니다.

집계는 **경리가 결제 완료를 등록한 날짜**를 기준으로 합니다. 반려·보류·결제 대기 품목은 제외하고 수령 여부와 관계없이 결제 완료된 품목을 포함합니다. 지급 기록이 없는 과거 문서는 지급을 추정해 집계하지 않습니다. 팀은 기안 당시 부서이므로 이후 인사 이동으로 과거 팀 합계가 달라지지 않습니다. 기존 구매 담당 권한 범위의 문서만 집계합니다.

집계 기능은 조회와 엑셀만 제공합니다. 집계 화면에서 결제 상태·수령 상태를 변경하지 않습니다.

## 앞선 수정도 유지

- 대표님 홈에 **새 구매요청 N건**, 기존 구매 진행현황 메뉴에 **새 N** 표시를 추가했습니다. 요청 묶음 기준으로 세며 품목 개수나 기존 미결 건수에 합산하지 않습니다.
- 홈의 새 구매요청 보기를 누르면 아직 열지 않은 요청만 표시합니다. 전체 목록에서도 해당 요청에 새 요청 표시가 보입니다.
- 대표님이 해당 요청 상세를 열면 새 표시가 해제됩니다. 목록을 보거나 알림을 모두 읽음 처리하거나 경리가 조회한 것만으로는 해제하지 않습니다. 열어본 뒤에도 결제 대기는 유지됩니다.
- 화면을 열어 둔 상태에서도 기존 알림 갱신으로 새 요청 표시를 갱신합니다.
- 구매요청 엑셀에서 **진행상황·처리 사유·수령 상태 세 열을 제거**했습니다. 구매 용도인 구매사유와 품목·기안자·구매처·수량·가격은 유지합니다. 대표와 경리 모두 같은 구매 내용 열을 받습니다.
- **대표님 승인 버튼은 보류**했습니다. 대표 조회 → 실제 결제 → 경리 결제 완료 등록 → 기안자 최종결재완료 흐름은 그대로입니다.

## 실행 방법

1. Python 3.10 이상이 설치된 PC에서 ZIP 전체를 새 폴더에 풉니다. 이전 테스트 폴더에 덮어쓰지 마세요.
2. `SETUP_LOCAL_FULL.bat` 실행 → 가상 직원 공통 테스트 비밀번호를 직접 정합니다.
3. `RUN_LOCAL_FULL.bat` 실행 → admin으로 로그인합니다.
4. 상단 역할 전환으로 기안자·검토자·이사·구매 담당자·대표를 테스트합니다.
5. 종료는 실행 창에서 Ctrl+C. 가상 데이터 초기화는 종료 후 `RESET_LOCAL_FULL.bat`입니다.

새 설치는 가상 직원 12명, 표시 역할 10개, 문서 0건으로 시작합니다. 이전 버전과 포트·쿠키·데이터·백업을 분리했습니다. 데이터는 이 폴더의 `var/full-nas-test-v6/purchase-test`에 저장됩니다. 실제 직원·DB·첨부·비밀번호·비밀키는 포함하지 않습니다.

## 달라진 구매 흐름

기안 → 내부 검토·승인 → 담당 이사 구매확인 → 경리 품목 취합·대표에게 결제 요청 → 대표가 내역을 확인하고 실제 결제 → 경리가 결제 완료 등록 → 문서 결재완료 → 기안자가 수령 완료.

- 대표: 메뉴의 **구매 진행현황**에서 기안자·품목·구매처·수량·가격·용도와 결제 진행상황을 조회합니다. 새 요청에는 승인·반려·보류나 결제 완료 처리 버튼이 없습니다. 수령 집계도 표시하지 않습니다.
- 경리: **구매요청함 → 요청할 품목**에서 확인된 품목을 선택해 대표에게 결제 요청합니다. **보낸 요청**에서 해당 요청을 열고 실제 결제된 품목을 선택해 **결제 완료**를 등록합니다.
- 품목별 반려·보류도 경리가 처리합니다. 사유는 필수입니다. 결제 완료·반려·보류는 선택한 품목과 합계금액을 다음 화면에서 확인한 뒤 확정합니다. 미선택 품목은 결제 대기로 남습니다.
- 경리는 대표에게 올리기 전의 확인된 품목도 원본 화면에서 반려할 수 있습니다.
- 기안자에게는 결제 내역 설명 없이 **최종결재가 완료되었습니다**라고 알립니다. 반려·보완 요청·보류처럼 후속 조치가 필요한 안내는 유지합니다.
- 결재완료 상태는 수령 이후에도 유지하고, 기안자·경리에게 수령 대기 / 수령 완료를 별도로 표시합니다. 기안자는 물품을 모두 받은 뒤 수령 완료를 한 번 누릅니다. 수량 집계 입력은 없습니다.
- 잘못 등록한 결제 완료는 경리가 사유를 남겨 결제 대기로 정정할 수 있습니다. 이전 등록자·등록 시각·정정 이력을 보존하고 기안자에게 정정을 알립니다. 이미 수령한 품목은 이 화면에서 되돌릴 수 없습니다. 이 정정 기능은 실제 송금을 취소하지 않습니다.
- 결제 전 수량·단가가 달라지면 경리가 원본의 수량·금액 변경에서 사유를 남겨 수정합니다. 기존 요청의 해당 품목은 보류로 남기고 변경된 전체 금액으로 다시 결제 요청합니다. 원본·이전 요청과 금액 변경 이력은 보존합니다. 결제 후 금액을 직접 덮어쓰지 않습니다.

## 작성·검토 화면

- 구매 링크는 추가 정보에서 꺼내 기본 화면의 **필수 항목**으로 옮겼습니다. 링크 없이 임시저장은 가능하며 기존에 링크가 없는 문서는 보존합니다.
- 기안자는 검토자만 지정합니다. 다음 승인자는 검토자가 정합니다.
- 검토 화면의 승인자 부서·직원 선택란을 처음부터 표시합니다. **승인 요청**이 주요 버튼입니다. 반려 등 추가 작업도 접지 않습니다.
- **승인완료**는 구매 규정에서 권한을 받은 검토자에게만 작은 보조 버튼으로 표시합니다. 직급만으로 자동 허용하지 않습니다. 이 동작은 내부 승인만 완료하며 구매확인과 대표의 실제 결제는 계속 필요합니다.
- 과장급 이상이 구매담당자에게 직접 요청하는 경로, 개발팀/그 외 부서의 구매확인 담당자 구분, 동일 이사의 승인·확인 중복 처리 방지, 본인 전결 제거는 유지합니다.

## 권한과 기존 자료

- 대표의 새 결제 요청은 결재함의 미결이나 내 승인 내역에 중복 표시하지 않습니다. 구매 진행현황에서 조회합니다. 휴가원 등 다른 문서의 대표 결재 권한은 바꾸지 않습니다.
- 결제 처리 권한은 요청을 올린 경리 담당자에게 있습니다. 계정 활성 상태와 현재 경리 권한, 해당 품목 담당 여부를 처리할 때 다시 검사합니다. 단순 조회 권한으로 처리할 수 없습니다.
- 이전 버전에서 이미 제출된 대표 승인 방식의 구매요청은 원래 결재 경로와 이력을 보존합니다. 새로 취합해 올리는 결제 요청부터 경리 등록 방식을 사용합니다.
- 휴가원·생산 재고·연차·일정·복지·직원·권한·기존 규정·첨부·엑셀·백업 등 기존 사내결재 기능은 유지합니다. 이번 변경 대상은 구매요청입니다.
- 동일 소스의 NAS 도구가 포함되지만 **실제 NAS에는 적용하지 않았습니다**. 운영에서 가상 직원 생성과 역할 전환은 차단합니다.

## 추천 테스트 순서

추가 확인: 대표 홈을 열어 둔 채 경리가 결제 요청을 올리면 새 요청 표시가 나타납니다. 대표가 요청 상세를 열면 표시만 해제되고 결제 대기는 남아야 합니다. 엑셀은 구매사유까지 10개 열이며 뒤의 세 열이 없어야 합니다.


1. 기안자: 구매 링크를 포함해 작성 → 검토 요청.
2. 검토자: 펼쳐진 선택란에서 승인자 지정 → 승인 요청. 다른 요청으로 권한 있는 검토자의 보조 승인완료도 확인합니다.
3. 내부 승인 후 담당 이사가 구매확인합니다. 개발팀과 다른 부서 경로를 각각 확인합니다.
4. 경리: 확인된 품목 2개 이상을 선택해 대표에게 결제 요청합니다.
5. 대표: 구매 진행현황에서 내용을 확인합니다. 처리 버튼과 구매 관련 미결 건수가 없는지 확인합니다.
6. 경리: 보낸 요청에서 한 품목만 결제 완료 → 다음 화면의 품목·금액 확인 → 확정합니다. 다른 품목은 결제 대기로 남습니다.
7. 경리: 나머지 품목을 반려하거나 보류하고 사유를 기록합니다.
8. 기안자: 최종결재완료 알림·반려 사유를 확인하고, 완료된 품목을 수령 완료 처리합니다.
9. 경리: 완료 탭과 원본 문서에서 수령 완료를 확인합니다. 별도 요청에서 잘못된 결제 등록 정정도 확인합니다.

Windows BAT 명령과 줄바꿈을 검사하고 실행·브라우저 검증은 Linux Python/Chromium 및 MariaDB에서 수행합니다. 실제 Windows PC 실행은 이 환경에서 직접 검증할 수 없습니다.
