# 경리 직접 연차 사용 등록 — NAS 업데이트

시스템 밖에서 신청한 휴가를 경리가 실제 사용 날짜와 사유로 등록한다.
기존 `사용연차` 수정은 누적 값을 대체하므로, 새 등록 기능은 별도 버튼으로 제공한다.
새 기능은 일수를 누적 사용량에 더하고 잔여연차를 같은 만큼 줄인다.

최종 사용자 지시에 따라 **기존 입사일·1월 1일 기준의 연차 산정은 유지**한다.
근무연수·총연차 산정 코드, 기존 데이터 재계산, 규정 변경은 이번 묶음에 없다.

## 사용 방법

1. 직원별 연차 관리 → 직원 행의 ‘연차 사용 직접 등록’. 사용 내역 화면에도 버튼이 있다.
2. 실제 사용 날짜, 휴가 종류, 등록 사유를 입력한다. 반차·외출은 실제 시간도 입력한다.
3. 연차 1일, 오전/오후반차 0.5일, 외출 0.25일을 해당 사용 연도에서 차감한다.
   여러 날의 연차는 날짜별로 등록한다. 기존 차감 규칙을 재사용한다.
4. 사용 내역에 승인 문서와 함께 ‘경리 직접 등록’으로 표시한다.
   등록자·등록일·실제 사용일·사유를 보관하며 결재완료 문서를 만들지 않는다.
5. 오입력은 행의 ‘등록 취소 · 연차 복원’에서 사유를 입력한다. 원래 일수만 복원한다.
   ‘전체 이력 · 취소 포함’에 원래 등록과 취소자·취소일·취소 사유가 남는다.

기존 잔액 정정은 유지한다. 과거 정정 이력은 실제 사용 날짜를 알 수 없으므로 변환하지 않는다.
기존 정정에 이미 포함한 사용분을 새 기능으로 다시 등록하면 중복 차감되므로 확인이 필요하다.
이번 기능은 직원별 연차 사용 내역에 표시하며 직원 일정 달력에 별도 이벤트를 추가하지 않는다.

## 처리 보장

- 웹과 서비스 모두 `manage_leave` 권한을 검사한다. 취소는 POST 전용이고 CSRF 검사를 유지한다.
- 등록·취소·잔액·감사 이력을 같은 DB 트랜잭션으로 저장한다.
- 기존 결재 차감과 같은 직원 Profile 행을 잠가 누적 사용량 갱신을 직렬화한다.
- 등록 요청 UUID를 보존해 동일 요청 재전송은 다시 차감하지 않는다. 취소 후 재전송도 재활성화하지 않는다.
- 취소 상태를 잠금 아래 검사해 중복 취소로 여러 번 복원하지 않는다.
- 결재 중/완료 문서 또는 취소하지 않은 직접 등록과 날짜/시간이 겹치면 등록을 거절한다.
  직접 등록이 있는 시간의 기안 제출·최종 승인도 거절한다. 오전/오후 등 비중첩 시간은 허용한다.
- 신청 당시 총연차 부족을 막지 않는 기존 동작을 유지한다. 실제 사용 기록은 남고 음수 잔여를 표시한다.
- 새 `ManualLeaveUsage` 테이블만 추가하는 `0010_manualleaveusage` 마이그레이션을 포함한다.
  기존 계정·문서·연차 값을 변환하는 데이터 마이그레이션은 없다.
- 기존 NAS의 전체 DB 논리 백업에 신규 테이블도 포함된다.

## NAS 적용

`releases/xenosys-manual-leave-20261016.zip`을 File Station의
`/docker/company-approval`에 업로드하고 ‘여기에 압축 풀기’를 실행한다.
Windows PowerShell에서 실행한다.

```powershell
ssh -t admin@192.168.1.46 "sudo sh /volume1/docker/company-approval/xenosys-manual-leave-20261016/APPLY_MANUAL_LEAVE.sh"
```

`MANUAL_LEAVE_READY` 후 기존 HTTPS 주소에서 새로고침한다.
실제 NAS에는 사용자가 적용한 뒤 이 완료 표시와 새 기능을 별도로 확인해야 한다.

묶음은 지정한 런타임 파일 13개와 적용 스크립트·안내·체크섬만 담는다.
체크섬 검증 후 기존 소스를 권한 0700의 `.manual-leave-backup.XXXXXX`에 먼저 보관한다.
기존 `nas.sh update`가 기존 이미지로 DB 백업 후 마이그레이션·웹 전환을 수행한다.
실패 시 완료 표시를 출력하지 않고 백업과 출력 내용을 남긴다. 기존 설치와 `.env`를 삭제하지 않는다.

## 검증 결과

- SQLite Django 전체: 151개 실행, 142개 통과, MariaDB 전용 9개 건너뜀.
- MariaDB 10.11.14: 직접 등록/취소 및 동시 처리 22개 모두 통과.
  같은 요청 동시 전송, 서로 다른 사용 등록, 중복 취소, 기안과 직접 등록 경합,
  기존 승인과 다른 날 직접 등록을 실제 별도 연결로 검증했다.
- Chromium: 320/390/768/1366px 등록·반차·재전송·중복 거절·취소·잔액 복원과
  JavaScript 없는 등록/취소를 포함한 9개 시나리오 통과. 페이지 가로 넘침 및 JS 오류 없음.
  DEBUG=0과 WhiteNoise 압축/해시 정적 파일을 사용했다.
- NAS 업데이트 묶음 5개 시험: 복사 대상/백업/설정 및 산정 코드 보존,
  손상된 파일·진행 중인 복구·설치 경로 누락 차단, 실패 시 백업 보존과 완료 표시 차단.
- `manage.py check`, `makemigrations --check --dry-run`, `git diff --check` 통과.

실제 운영 NAS의 이번 업데이트 및 운영 직원 데이터로의 처리는 아직 수행하지 않았다.
가상 직원만 있는 별도 DB와 클라우드의 격리된 MariaDB 테스트 DB에서 검증했다.
