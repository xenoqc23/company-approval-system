# NAS 운영 배포 계획 및 준비 현황

수정일: 2026-10-15. 후속 사용자 승인에 따라 운영 문구·NAS 설치 및 업데이트 구성을 구현했다. **클라우드 시험을 완료한 설치 파일을 제공하며 실제 NAS 설치는 다음 단계**다. 종전의 구현 보류 기록 이후 현재 상태는 본 문서를 따른다.

## 확인된 NAS

| 항목 | 확인 내용 |
| --- | --- |
| 모델·OS | Synology DS218+, DSM 7.1.1-42962 Update 9 |
| CPU·RAM | Intel Celeron J3355, amd64, 2코어, RAM 2GB |

## 확정 구성

직원 브라우저 → NAS HTTPS 역방향 프록시 → Gunicorn/Django → 전용 MariaDB 컨테이너.

기존 DB 접속 정보를 재설정하지 않고 별도 DB로 분리한다. DB에는 외부 포트를 열지 않는다. 내부 연결 확인은 NAS IP의 18080 포트로 시작하고, 정식 사용 전 HTTPS 프록시와 루프백 바인딩으로 전환한다. DSM 7.1의 Docker·Compose v1/v2 명령을 지원한다. 직원 PC에는 Python을 설치하지 않는다.

프로그램 원본 `app`, 운영 DB `data/mariadb`, 앱 자료 `data/app`, 백업 `backups`, 비밀 설정 `.env`를 분리한다. 업데이트 시 프로그램만 교체하고 데이터·비밀키·직원 암호·규정을 보존한다. DB 버전은 자동 업데이트하지 않는다.

## 구현한 내용

- 운영 문구 정리, 로그인 예시 계정 안내 제거. 역할·권한·계산 규칙은 유지.
- 운영 모드의 DEBUG·비밀키·허용 주소·MariaDB 설정 검증, 정적 파일 수집·해시·WhiteNoise, Gunicorn 및 상태 검사.
- 빈 DB에 실제 관리자 1명만 생성. 임시 비밀번호는 NAS에서 무작위 생성·최초 변경 강제. 샘플 직원·문서·PC DB 가져오기 금지. 기존 회사 연차·복지 기준은 시작값으로 유지하며 담당자가 확인·수정.
- 설치·시작·중지·상태·로그·업데이트·백업·복구·직전 업데이트 되돌리기 명령.
- 업데이트 전 DB 백업, 스키마 반영, 상태 확인. DB 변경 실패 시 서비스 중지와 시작 제한.
- MariaDB 일관된 논리 백업, SHA-256 포함 ZIP, 일별 30개·월별 12개 보관 명령. 실제 예약은 DSM 설정 후 동작.
- 복구는 서비스 중지 후 임시 DB에서 먼저 검증. 현재 DB 안전 백업 후 반영. 실패 시 복구 표식을 남겨 무조건 재시작 방지.

## 검증 결과와 한계

MariaDB 10.11.14의 기능·권한·결재·연차·규정·동시 처리 시험 123건 통과. SQLite에서는 119건 통과·행 잠금 전용 4건 제외. 새 설치·최초 관리자 변경·설치 재실행·일반 및 스키마 변경 업데이트·되돌리기·의도적 DB 변경 실패 복구·손상 백업 거부를 클라우드 Docker에서 확인했다. 직원·문서·연차·암호·결재 이력은 복구 전후 전체 업무 레코드로 비교했다.

PC 브라우저 1280×800·1366×900·1920×1080에서 관리자 주요 화면의 가로 넘침·JavaScript 오류가 없었다. 화면은 PC 가로 1080px 이상을 기준으로 하며 모바일 전용 화면은 별도 범위다. 클라우드의 Docker 빌드는 공개 CA 신뢰 및 프록시 설정을 추가한 시험 문맥에서 수행했고 TLS 검증은 유지했다.

**실제 NAS의 Docker 버전·자원·응답 속도, HTTPS 인증서·로그인/POST, DSM 자동 백업·외부 사본은 아직 확인 전**이다. 클라우드 검증은 NAS 운영 인수 완료를 뜻하지 않는다. 웹 384MB·DB 512MB 제한은 초기값이며 NAS에서 여러 PC 동시 사용·백업·Excel 때 확인한다.

## 남은 순서 — 처음 사용하는 사람 기준으로 한 단계씩

1. ZIP 다운로드·압축 해제 → app 폴더에 내용물 업로드.
2. SSH를 사내에서만 활성화 → 설치 명령 1회 실행 → 사내 연결 확인.
3. 관리자 첫 로그인·비밀번호 변경 → 실제 직원 가입 승인·부서·직급·업무 권한 설정.
4. 회사 규정·입사일·기초 연차·공용연차 및 전결규정 확인.
5. DHCP 주소 예약·HTTPS 프록시·인증서·보안 쿠키·CSRF 설정 및 실제 PC POST 시험.
6. DSM 일일 예약 백업·연초 산정·작업 실패 알림·NAS 외부 사본 설정·시험 복구.
7. 일반 직원·검토자·승인자·연차/구매 담당자가 여러 PC에서 인수 확인 후 정식 사용.

100만원 초과 전결 및 적격 결재자가 없는 경우의 별도 예외는 보류 상태를 유지한다. 10만원 초과~100만원 이하 규정은 기존 비활성 상태에서 담당자가 실제 직급을 확인한 뒤 사용한다. 사용자 확정 정책인 숫자만 포함한 4자 이상 비밀번호·본인 최종 승인 허용·같은 직급 이상 제한은 유지한다.
