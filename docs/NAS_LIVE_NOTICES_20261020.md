Xenosys 사내결재 — 화면 알림 강화 NAS 업데이트 (2026-10-20)

설치
1. ZIP을 File Station /docker/company-approval에 업로드합니다.
2. 우클릭 → 여기에 압축 풀기를 선택합니다. 기존 app·data·.env를 삭제하지 않습니다.
3. Windows PowerShell에서 아래 명령을 실행합니다.

ssh -t admin@192.168.1.46 "sudo sh /volume1/docker/company-approval/xenosys-live-notices-20261020/APPLY_LIVE_NOTICES.sh"

4. NAS 관리자 비밀번호를 입력합니다. 두 번 물을 수 있습니다.
5. 마지막 LIVE_NOTICES_READY 확인 후 PC·휴대폰 사이트를 새로고침합니다.

이번 반영
- 기존 종 아이콘·알림함·미결 결재함은 유지합니다.
- 브라우저를 열어둔 상태에서 새 검토·승인 요청과 최종 승인 소식을 최대 약15초 안에 팝업으로 알려줍니다.
- 다른 화면에서 돌아오면 즉시 새 알림을 확인합니다. 숨겨진 탭의 화면 조회는 쉽니다.
- 기안을 올린 뒤 검토자로 다시 로그인해도 이미 도착한 미결 문서를 안내합니다.
- 로그인 시 경리 담당자의 아직 확인하지 않은 최종 승인 문서도 알려줍니다.
- 새로고침 없이 알림함·미결·최종 승인 문서함의 미확인 숫자를 갱신합니다.
- 최종 승인 문서함의 종류별 탭에 주황색과 미확인 건수를 표시합니다.
- 각 문서에 NEW를 표시합니다. 문서별 확인 상태는 담당자별로 따로 보관합니다.
- 탭을 누르는 것만으로 확인 표시를 없애지 않습니다. 해당 문서를 열면 그 문서만 확인 처리합니다.
- 문서를 읽어도 미결 건수는 유지합니다. 실제 전결·상위 전달·승인·반려 등 처리 후 미결에서 빠집니다.
- 알림함의 모두 읽음은 최종 승인 문서함의 문서별 확인을 대신하지 않습니다.
- 내 계정 → 알림 설정에서 도착 팝업·알림음을 선택합니다. 알림음은 기본 꺼짐입니다.
- 알림음을 켜고 화면을 한 번 클릭하면 브라우저의 자동 재생 정책 안에서 사용할 수 있습니다.
- 화면 팝업 테스트 버튼을 추가했습니다. PC·모바일 브라우저에서 같은 방식으로 사용할 수 있습니다.
- 같은 브라우저의 다른 탭에서 계정이 바뀌면 안내를 표시합니다. 새 기안의 팝업은 현재 집중한 창에 표시합니다.

이번에 보류한 기능
- 브라우저를 닫은 뒤 받는 웹 푸시는 적용하지 않습니다.
- NAS 운영 모드에서는 웹 푸시 등록·발송·서비스워커 자동 등록을 사용하지 않습니다.
- 웹 푸시 켜기·10초 테스트·Windows 표시 테스트 버튼은 NAS 화면에서 숨깁니다.
- 별도 발송 프로그램·VAPID키·브라우저 알림 권한·외부 푸시 서비스 설정이 필요하지 않습니다.
- NAS 설치에 웹 푸시용 추가 패키지나 새 Docker 서비스를 요구하지 않습니다.

- 기존 직원·암호·문서·결재선·연차·입사일·생일·공용/개인 사용 내역·규정을 초기화하지 않습니다.

- 이미 확인한 문서를 일괄 미확인으로 되돌리지 않습니다. 이전 확인 기록도 남겨 둡니다.
- 재승인하여 승인 시각이 바뀐 문서는 다시 확인할 수 있도록 미확인으로 표시합니다.
- 실제 직원·계정·생일·.env·비밀번호·DB·푸시 키를 ZIP에 포함하지 않습니다.

- 이미 승인한 연차 산정·전결 규정은 그대로 유지합니다.

백업·설치 안전장치
- 체크섬 검증 → 기존 소스 .live-notices-backup.XXXXXX 보관 → 기존 nas.sh update 순서입니다.
- nas.sh가 새 이미지를 빌드하고 이전 이미지로 DB를 백업한 다음 마이그레이션과 웹 전환을 수행합니다.
- 기존 .env·HTTPS·쿠키·접속 주소·NAS 예약 백업과 Docker Compose는 덮어쓰지 않습니다.
- 예시 계정 생성·연차 초기화·DB 삭제·웹 푸시 키 생성은 실행하지 않습니다.
- 다른 업데이트·복구가 진행 중이면 소스 복사 전에 중단합니다.
- 업데이트 중 잠깐 접속이 중단될 수 있습니다. 실패 시 LIVE_NOTICES_READY를 출력하지 않습니다.
- 오류 시 출력과 백업 경로를 보관하고 app/data 삭제·재설치·임의 DB 복원을 하지 마세요.
