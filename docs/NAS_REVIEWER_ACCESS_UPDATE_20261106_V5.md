# NAS 문서별 검토 승인완료 권한 업데이트 v5 · 2026-11-06

## 바뀌는 내용

직원·권한 관리에 **검토 단계 승인완료 권한** 항목을 추가합니다. 아래 두 목록을 각각 체크하고 저장합니다.

- **휴가원 · 검토 단계에서 승인완료 가능한 직원**
- **구매요청서 · 검토 단계에서 승인완료 가능한 직원**

두 권한은 서로 영향을 주지 않습니다. 체크한 직원이 해당 문서의 현재 검토자인 경우에만 작업 영역 맨 위에 **승인완료** 버튼이 표시됩니다. 체크하지 않은 검토자는 기존 승인자에게 전달하는 절차를 사용합니다. 활성·가입 승인 및 부서 확인된 과장급 이상 직원만 선택하며, 관리용 계정·대표·기안자 본인의 승인은 허용하지 않습니다.

휴가원을 승인완료하면 최종 결재와 연차 반영을 함께 처리합니다. 구매요청서를 승인완료하면 내부 결재를 마칩니다. **승인한 검토자가 그 문서에 지정된 구매확인 담당자와 같으면 구매확인도 함께 완료되어 구매 담당자에게 전달됩니다.** 다른 직원이 내부 결재를 완료한 경우에는 지정된 구매확인 담당자가 확인합니다. 결제 요청·실제 결제·결제 결과 등록 절차는 유지합니다.

승인완료를 눌렀을 때 처리 내용을 확인하는 창을 표시합니다. 승인자 선택 영역은 그 아래에 펼쳐 두어 다른 승인자에게 전달하는 선택도 가능합니다. 기존 고정 결재선의 문서는 원래 승인자에게 전달하는 기존 동작을 유지하며, 허용된 현재 검토자에게 승인완료 선택을 추가합니다.

## 이미 요청한 문서

권한 저장은 **이미 요청된 검토 대기 문서에도 즉시 적용**됩니다. 문서를 취소하거나 다시 기안할 필요가 없습니다. 권한을 해제하면 이전에 열어 둔 화면에서 승인완료를 요청해도 서버가 거부합니다.

권한 저장만으로 문서를 자동 승인하지 않습니다. 기존 담당자·결재선·처리 이력을 일괄 변경하지 않습니다. 이미 다음 승인 단계로 넘어갔거나 완료된 문서를 검토 단계로 되돌리지 않습니다. 해당 문서에 저장된 구매확인 담당자와 현재 검토자가 같은지 검사하므로, 다른 부서의 구매확인 담당자라는 이유만으로 경리에게 바로 전달하지 않습니다.

## 기존 설정과 데이터 보존

업데이트는 기존 계정·암호·연차·규정·권한·문서·첨부파일을 유지합니다. 구매요청서의 기존 검토 승인완료 권한을 그대로 표시합니다. 휴가원은 처음 권한을 저장하기 전까지 기존 유효한 전결규정의 허용 직원을 유지하고, 직원·권한 관리에서 첫 저장할 때 선택한 목록을 휴가원 권한으로 사용합니다. 아무도 체크하지 않고 저장하면 해당 문서 종류의 검토 승인완료를 허용하지 않습니다.

기존 문서·직원 테이블을 변경하지 않고 휴가원 권한 저장용 테이블만 추가합니다. 새 계정이나 테스트 문서를 만들지 않습니다. 기존 데이터·첨부의 보존 비교를 통과해야 서비스를 다시 시작하는 업데이트 방식을 유지합니다. v4의 **생산 재고 요청: 검토자 확인 → 기록 보관**도 포함합니다. 생산 재고 요청에는 위 두 승인완료 권한을 적용하지 않습니다.

## NAS에 업로드하고 사전 점검

`xenosys-nas-reviewer-access-update-20261106-v5.zip`을 File Station의 `docker/company-approval/updates`에 올리고, **NAS에서 압축 해제**합니다. 해제한 폴더 안에 `app`, `README.md`, `RELEASE.json`, `SHA256SUMS`, `UPDATE_NAS.sh`가 있어야 합니다.

Windows PowerShell에서 NAS에 접속합니다.

```powershell
ssh admin@192.168.1.46
```

명령줄이 `admin@xenonas`로 바뀐 뒤 실행합니다.

```sh
cd /volume1/docker/company-approval/updates/xenosys-nas-reviewer-access-update-20261106-v5
sudo sh UPDATE_NAS.sh precheck --operator admin
```

`--operator admin`은 사내결재시스템의 관리자 아이디입니다. 기존 아이디가 다르면 해당 값으로 바꿉니다. 구매 담당자를 다시 지정하는 옵션은 넣지 않습니다.

다음 문구가 표시되면 사전 점검 성공입니다. 이 단계에서는 서비스가 계속 실행됩니다.

```text
Precheck complete. Existing web service is still running.
```

## 적용

직원들이 문서를 작성·저장하지 않는 시간에 같은 NAS SSH 창에서 실행합니다.

```sh
sudo sh UPDATE_NAS.sh update --operator admin
```

정상 완료 문구:

```text
Update complete. Staff can refresh their browser. Previous image and backup are retained.
```

파일 검증 오류가 나면 NAS에서 원본 ZIP을 다시 압축 해제합니다. 검증을 생략하지 않습니다. 적용 중 오류가 나면 서비스를 임의로 다시 시작하지 말고 오류 내용을 확인합니다.

## 적용 후 권한 지정

1. 기존 주소에 접속해 **Ctrl+F5**로 새로고침하고 관리자로 로그인합니다.
2. **직원·권한 관리 → 검토 단계 승인완료 권한**으로 이동합니다.
3. 휴가원과 구매요청서 목록에서 허용할 직원을 **각각** 체크합니다. 구매확인 담당자 지정만으로 이 권한이 생기지는 않습니다. 다른 검토자에게 버튼이 보이면 해당 문서 종류 목록에서 체크를 해제합니다.
4. 변경 사유를 입력하고 **검토 단계 승인완료 권한 저장**을 누릅니다.
5. 이미 요청된 검토 대기 문서를 허용된 검토자가 열어 맨 위의 **승인완료**와 아래의 승인자 선택을 확인합니다. 구매확인 담당자와 같은 검토자라면 승인완료 후 구매 담당자에게 확인된 품목으로 전달됩니다.
6. 허용하지 않은 검토자에게 승인완료 버튼이 표시되지 않는지, 기존 휴가원·구매요청서·생산 재고 기록이 유지되는지 확인합니다.

담당자·권한 설정을 저장하는 버튼은 각각 별도입니다. 구매 업무 담당자만 변경해서 저장하면 위 두 승인완료 권한은 바뀌지 않습니다.

## 복구

업데이트 직전 이미지와 백업은 유지합니다. 업무 재개 전에 복구해야 한다면 같은 업데이트 폴더에서 실행합니다. 백업 이후 입력한 내용도 되돌아갑니다.

```sh
sudo sh UPDATE_NAS.sh rollback
```

이 파일은 NAS 적용용 패키지입니다. 실제 NAS 반영은 위 순서로 관리자가 진행합니다.
