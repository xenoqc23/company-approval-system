# 검토자 화면 수정 v3 검증 기록

2026-10-28. NAS에서 사용 중인 v2 소스(`929cb07c11de9fcf38749ec9ec0c10e6a7138a87`)를 기준으로 검토자 화면 수정과 배포 파일을 준비했다. 실제 NAS에는 아직 v3를 적용하지 않았다.

## 범위

- 휴가원·구매요청의 승인자 선택을 접지 않고 표시한다.
- `선택한 승인자에게 전달`을 기본 버튼으로 표시한다.
- 전결은 반려 아래의 별도 영역에 배치하고 `전결로 승인완료`로 표시한다. 기존 권한 판정은 유지한다.
- 공통 문서 작업 양식을 별도 템플릿으로 분리하면서 삭제·취소·수령 확인과 사유 입력 조건을 유지한다.
- 새 배포의 사전 점검을 구분하도록 업데이트 버전 표식만 변경한다.

## 확인한 결과

- 통합 구매·휴가원 결재, 결제, 전결 권한, CSRF와 수령 관련 기존 검사 37건 통과.
- 기존 결재·전결 권한 검사 31건 통과.
- NAS 담당자·권한·복수 구매 담당자·규정 사용 상태·문서·첨부 보존 검사 8건 통과.
- 배포 안전 검사 5건 통과: 파일 목록과 해시, 변조 시 중단, 사전 점검 실패 시 기존 웹 유지, 보존 비교 실패 시 정지 및 복구 표식 유지, 정상 업데이트 실행 순서와 직전 이미지 유지. 이 실행 순서 검사는 가상 Docker 명령을 사용한 모의 검사다.
- v2 ZIP과 앱 파일을 비교하여 변경 파일이 6개로 한정됨을 확인했다. 기존 모델·마이그레이션·결재 및 구매 처리 서비스·Docker 설정은 동일하다.
- 실제 Chromium의 1440px·390px 화면에서 휴가원·구매요청의 승인자 선택이 처음부터 보이는지, 전달 → 반려 → 전결 순서인지, 전결 버튼의 강조가 낮은지 확인했다.
- 두 문서 종류 모두 실제 브라우저에서 부서와 승인자를 선택해 전달한 뒤 DB의 다음 담당자와 대기 단계가 변경되는지 확인했다. 자바스크립트 오류와 모바일 가로 넘침이 없었다.
- Django 시스템 검사, DB 모델 변경 누락 검사, diff 공백 검사 통과.
- ZIP을 풀어 배포용 소스에서 직접 실행한 앱 검사와 휴가원·구매요청 렌더링 검사 통과. 승인자 선택·작업 순서·권한 없는 검토자의 전결 버튼 숨김을 다시 확인했다. 가상 직원 생성 명령이 배포본에 없는 것도 확인했다.
- 최종 ZIP의 220개 파일이 위 압축 해제 검증에 사용한 파일과 모두 동일하다. ZIP CRC, 중복 항목 여부, 전체 파일 체크섬과 기존 v2 ZIP의 보존을 확인했다.

테스트에는 별도 로컬 가상 DB·계정·문서를 사용했다. 이 자료와 세션·암호·실제 직원 이름은 배포 ZIP에 넣지 않는다. Windows Defender를 이 실행 환경에서 직접 실행하지 않았으며 백신 검사 통과를 인증하지 않는다. 받은 ZIP은 최신 백신으로 확인한 뒤 NAS 사전 점검을 실행한다.

실제 NAS의 이미지 빌드·운영 DB 보존 비교·상태 확인은 `UPDATE_NAS.sh precheck`와 `update`에서 수행한다. 적용 후 관리자가 권한별 실제 화면을 확인한다.
