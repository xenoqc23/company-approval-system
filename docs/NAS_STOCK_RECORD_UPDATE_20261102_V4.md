# NAS 생산 재고 기록 업데이트 v4 · 2026-11-02

## 변경 내용

생산 재고 요청을 **기안 → 검토자 확인 → 기록 보관**으로 사용합니다.

- 새 생산 재고 요청은 검토자 한 명만 지정합니다. 공통 전결규정이나 단계별 결재 설정이 있어도 최종 승인자를 추가하지 않습니다.
- 검토자는 **확인 완료** 또는 **반려**를 선택합니다. 확인하면 기안자에게 결과를 알리고, 요청 내용·기안자·검토자·확인 일시·처리 이력을 보관합니다.
- 경리·구매 담당자 권한만으로 생산 재고 문서를 받지 않습니다. 최종 승인 문서함·경리 알림·수령 확인 목록에 생산 재고 요청을 넣지 않습니다.
- 생산 재고 기록에 발주 처리·입고 확인 버튼을 표시하지 않으며, 이전 주소로 해당 처리를 요청해도 거부합니다.
- **생산 재고 기록함**에서 전체·확인 대기·확인 완료·반려·취소 기록을 조회합니다.

경리 담당자가 직접 기안했거나 검토자로 지정된 경우에는 그 문서에 참여한 직원으로 조회·확인할 수 있습니다. 시스템 관리자는 기존의 전체 문서 조회 권한을 유지합니다.

## 기존 데이터와의 호환

2026-10-28 v3까지 적용한 NAS의 기존 담당자·권한·규정·문서·연차·구매집계·첨부를 유지합니다. DB 구조 변경 및 기존 문서 일괄 변환은 없습니다. 기존 계정이나 테스트 문서를 만들지 않습니다.

**이미 제출된 문서의 결재선과 과거 처리 이력은 변경하지 않습니다.** 예전에 최종 승인이 필요한 경로로 제출한 생산 재고 문서는 해당 결재선을 마친 뒤 기록으로 보관합니다. 기존 발주·입고 상태가 있으면 과거 기록으로 표시하며 추가 처리하지 않습니다. 업데이트 이후 새로 제출하는 생산 재고 요청부터 검토자 확인으로 종료합니다. 기존 진행 문서를 새 절차로 사용해야 한다면 원래 이력을 보존한 상태에서 해당 기안자가 취소·재기안 여부를 판단해야 합니다.

휴가원 및 구매요청서의 검토·승인·구매확인·결제 절차와 담당자 설정을 유지합니다.

## 1. NAS에 업로드

받은 `xenosys-nas-stock-record-update-20261102-v4.zip`을 File Station의 아래 폴더에 올립니다.

```text
docker/company-approval/updates
```

NAS File Station에서 ZIP을 직접 압축 해제합니다. 아래 폴더 안에 `app`, `README.md`, `RELEASE.json`, `SHA256SUMS`, `UPDATE_NAS.sh`가 있어야 합니다. 기존 운영 폴더에 직접 덮어쓰지 않습니다.

```text
/volume1/docker/company-approval/updates/xenosys-nas-stock-record-update-20261102-v4
```

## 2. PowerShell에서 NAS 접속

Windows에서 PowerShell을 열고 실행합니다.

```powershell
ssh admin@192.168.1.46
```

NAS admin 비밀번호를 입력합니다. 문자가 표시되지 않는 것은 정상입니다. 명령줄 앞이 `admin@xenonas`로 바뀐 다음부터 아래 NAS 명령을 실행합니다.

## 3. 사전 점검

```sh
cd /volume1/docker/company-approval/updates/xenosys-nas-stock-record-update-20261102-v4
sudo sh UPDATE_NAS.sh precheck --operator admin
```

`--operator admin`은 사내결재시스템 관리자 아이디입니다. 기존 관리자 아이디가 다르면 해당 값으로 바꿉니다. 구매 담당자 이름이나 계정을 다시 지정하지 않습니다.

정상적으로 끝나면 아래 문구가 표시됩니다. 이 단계에서는 현재 서비스가 계속 실행됩니다.

```text
Precheck complete. Existing web service is still running.
```

## 4. 적용

직원들이 문서를 작성·저장하지 않는 시간에 같은 NAS SSH 창에서 실행합니다.

```sh
sudo sh UPDATE_NAS.sh update --operator admin
```

현재 웹 중지 → 기존 데이터·첨부 기준값 저장 → 백업 → DB 변경 확인 → 보존 비교 → 기존 구매 설정 유지 → 시스템 검사 → 새 웹 기동 순서로 진행합니다. 오류가 나면 서비스를 임의로 다시 시작하지 말고 표시된 내용을 확인합니다.

정상 완료 문구:

```text
Update complete. Staff can refresh their browser. Previous image and backup are retained.
```

파일 검증 오류나 `No such file or directory`가 나오면 ZIP을 NAS에서 다시 압축 해제합니다. 검증 파일을 삭제하거나 검증을 생략하지 않습니다.

## 5. 적용 후 확인

기존 주소 `https://xenonas.synology.me:18443`에서 **Ctrl+F5**로 새로고침합니다.

1. 새 생산 재고 요청에서 품목·수량·검토자를 입력하고 제출합니다. 최종 승인자·수령자 입력은 표시하지 않습니다.
2. 검토자 결재함에서 **확인 완료**를 누릅니다. 다음 승인자를 선택하는 절차가 없어야 합니다.
3. 기안자와 검토자가 **생산 재고 기록함**에서 확인 완료 상태와 확인자·확인 일시·처리 이력을 조회합니다.
4. 문서에 참여하지 않은 경리 담당자의 최종 승인 문서함·알림·수령 확인에 해당 생산 재고 요청이 표시되지 않는지 확인합니다.
5. 기존 휴가원·구매요청서·연차·구매집계·담당자 설정이 유지되는지 확인합니다.

이 파일은 NAS에 적용할 준비가 된 업데이트입니다. 실제 NAS 반영과 현장 확인은 위 순서로 관리자가 수행합니다.

## 복구

같은 업데이트 폴더의 NAS SSH 창에서 실행하면 업데이트 직전 이미지와 백업으로 돌아갑니다. 백업 이후 새로 입력한 내용도 되돌아가므로 업무 재개 전에 판단합니다.

```sh
sudo sh UPDATE_NAS.sh rollback
```

정상 사용을 확인할 때까지 업데이트 폴더와 백업을 보관합니다.
