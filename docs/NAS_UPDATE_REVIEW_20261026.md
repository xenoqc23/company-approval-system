# 사내결재 NAS 업데이트 최종 검토

검토일: 2026-10-26. 운영용 보완과 가상 데이터 검증을 마쳤습니다. 실제 NAS에는 접속하거나 업데이트하지 않았습니다. 적용 파일과 명령은 [NAS 업데이트 안내](NAS_PURCHASE_UPDATE_20261026.md)를 사용합니다.

## 반영한 운영 보완

- 해당 문서의 지정 구매확인 담당자가 승인하면 구매확인도 한 번에 완료합니다. 이전에 저장된 `combine_confirmation=False`가 남아도 통합 운영에서는 같은 사람에게 재확인을 요구하지 않습니다. 내부 승인완료 권한을 받은 검토자에게도 같은 기준을 적용합니다. 다른 이사의 승인이나 본인 승인은 이 조건으로 우회하지 않습니다.
- 대표 화면은 진행 중/완료로 분리하고 새 요청 표시를 유지합니다. 보류·결제 대기·미결 품목은 진행 중에 남습니다. 다른 요청으로 다시 제출한 품목의 원래 요청은 이력으로 보존합니다. 수령량은 대표 화면과 완료 분류에서 제외합니다.
- 대표의 새 승인 버튼은 보류합니다. 구매 담당자가 실제 결제 후 결과를 등록하고 기안자는 최종결재완료를 확인하는 기존 합의를 유지합니다.
- 아이디 저장은 서명 쿠키, 비밀번호 자동입력은 브라우저 비밀번호 관리자를 사용합니다. 기존 로그인 세션·CSRF 검증·암호 변경을 유지하며 암호를 앱에 따로 저장하지 않습니다.
- 구매 업무 화면·알림·오류·새 처리 기록의 담당자 명칭을 구매 담당자로 정리했습니다. 기존 이력·문서번호·상태 코드는 변경하지 않습니다. 통합 구매 로그인도 기존 공통 로그인으로 연결합니다.

## 기존 시스템·데이터 보존

기준 소스 `53acbc9`의 기존 DB 구조에서 가상 계정·진행 문서·완료 문서·연차·규정·알림·결재 이력을 만든 뒤 새 버전으로 올렸습니다. DB 변경 전 존재하던 각 테이블의 기존 열·행 해시를 비교해 계정·암호·잔액·규정·문서·이력 보존을 확인했습니다. 새 필드와 신규 테이블을 추가하며 과거 구매 문서를 새 요청으로 자동 변환하지 않습니다.

실제 업데이트도 같은 비교 절차를 실행합니다. Django 내부 권한·문서 유형 테이블은 신규 앱의 항목 추가를 허용하면서 기존 행을 비교합니다. 첨부는 파일별 크기·해시를 비교합니다. 업데이트 중 연차 자동 재산정·초기 계정 생성은 실행하지 않습니다.

현재 운영 DB의 진행 문서가 기안자 본인에게 검토·승인으로 배정되어 있으면 사전 점검에서 해당 문서 ID를 표시하고 중단합니다. 신규 본인 승인 제한과 충돌할 수 있기 때문입니다. 기존 절차로 담당자를 정리한 뒤 다시 점검하며 임의 예외나 자동 담당자 교체를 하지 않습니다.

네 구매 역할은 이름 또는 명시한 기존 아이디로 정확히 일치하는 계정에 연결합니다. 계정이 없거나 동명이인이면 중단하고, 부서·직급·대표 지정·활성·가입 승인·관리자 권한을 확인합니다. 계정/암호를 새로 만들거나 기존 직원의 부서·직급을 변경하지 않습니다. 실제 직원 이름은 공개 소스와 배포 ZIP에 포함하지 않습니다. 검토자의 내부 승인완료 권한은 별도 규정의 기존 지정을 유지합니다.

## 배포·복구

전체 앱을 별도 업데이트 폴더에서 빌드합니다. 기존 앱·설정·DB·포트·첨부 폴더를 파일 복사로 덮어쓰지 않습니다. 기존 Docker 프로젝트와 볼륨을 사용하며 다른 NAS 서비스에는 작업하지 않습니다. 빌드·사전 점검은 기존 웹을 계속 실행한 채 수행하고, 통과한 뒤에만 웹 중지·백업·DB 변경·보존 비교·역할 연결·상태 검사를 진행합니다.

DB 변경 이후 실패 시 웹을 자동 재개하지 않으며 이전 이미지와 업데이트 직전 백업을 함께 복구할 수 있습니다. 배포 ZIP은 파일별 SHA256 목록을 포함하고 로컬 DB·가상 계정 생성기·테스트 화면·개인 자료·협업일지·실제 직원 명단을 제외했습니다.

실제 NAS의 실행 버전·계정 일치·남은 저장 공간·HTTPS·예약 작업은 아직 현장 확인 전입니다. 이를 무조건 호환된다고 단정하지 않고 업데이트 사전 점검과 적용 후 확인으로 검증합니다.
