# 신입 직원 입사 연도 월수 선부여

사용자 확인을 반영한 규칙:

| 대상 | 총연차 |
| --- | --- |
| 입사한 해 | 입사월부터 12월까지 매월 만근을 가정해 즉시 선부여: `13 − 입사월` |
| 입사 다음 해 | 1월 1일 입사자도 모두 0년차 기본값 **12일** |
| 그다음 해부터 | 기존 1월 1일 기준 근속표 적용 |

입사일의 일자는 월수 계산에 영향을 주지 않는다. 예를 들어 6월 1일은 7일,
4월 15일은 9일, 12월 31일은 1일이다. 달마다 1일을 새로 더하거나 실제 만근을 추적하는 기능이 아니다.

2026년 6월 1일 입사자의 예: 2026년 7일 → 2027년 12일 → 2028년 15일.
2026년 1월 1일 입사자도 2027년에는 12일을 적용한다.

## 계산과 기존 데이터

- `entitlement`를 사용하는 초기 산정·입사일 적용·재계산·연도 전환·승인/직접 등록 시 초기 잔액에 같은 규칙을 적용한다.
- 기본 0년차 구간을 11일에서 12일로 수정한다. 다른 근속 구간은 유지한다.
- `AnnualPolicy.hire_year_monthly`로 규칙을 연도별 보존한다. 이전 연도 정책에는 기존 계산 모드를 유지한다.
- `0011_hire_year_monthly`는 현재 연도 규정을 이전 최신 규정에서 복사하고,
  현재/이미 예약된 미래 규정의 0년차만 12일로 맞추고 새 규칙을 활성화한다.
  나머지 구간·안내문은 보존하고 버전과 감사 이력을 갱신한다.
- 현재 및 이미 초기화된 미래 자동 잔액 중 입사 연도·입사 다음 해에 해당하는 총연차만 보정한다.
  미래 승인분 때문에 이미 총연차가 초기화된 잔액도 새 규칙을 적용하되 사용량은 그대로 둔다.
- 과거 연도 잔액/규정, 장기근속자의 기존 총연차, 수동으로 지정한 총연차는 보존한다.
  사용연차·공용연차·휴가 문서·직접 등록/취소 기록도 유지한다.
- 수동 총연차에도 새 기준을 적용하려면 기존 총연차 재계산 미리보기에서
  직원과 ‘수동값 대체 확인’을 선택한다. 최신 사용량을 보존한 채 적용한다.
- 기존 전원 예약과 백업 예약을 변경하지 않으며 새 월별 작업은 필요 없다.

규정 관리·연차규정·직원복지·재계산 화면에 새 규칙을 설명한다.
직원별 연차 관리 화면의 설명은 조회 연도의 실제 규칙을 따른다.

## NAS 업데이트

묶음: `releases/xenosys-new-entrant-leave-20261016.zip`.
이전 직접 등록, 개인/공용 엑셀 내역 분리까지 포함한 런타임 파일 23개이다.

1. File Station `/docker/company-approval`에 ZIP 업로드 → ‘여기에 압축 풀기’.
2. Windows PowerShell에서 실행한다.

```powershell
ssh -t admin@192.168.1.46 "sudo sh /volume1/docker/company-approval/xenosys-new-entrant-leave-20261016/APPLY_NEW_ENTRANT_LEAVE.sh"
```

3. `NEW_ENTRANT_LEAVE_READY` 확인 후 새로고침한다.
4. 규정 관리에서 0년차 12일 및 새 안내를 확인하고, 신입 직원의 총연차를 확인한다.

적용 스크립트가 체크섬 검증 후 기존 소스를 `.new-entrant-leave-backup.XXXXXX`에 보관한다.
기존 `nas.sh update`가 이전 이미지로 DB 백업을 만든 뒤 마이그레이션과 웹 전환을 수행한다.
`.env`, 비밀번호, HTTPS 설정은 교체하지 않는다. 업데이트 중 잠시 서비스가 중단된다.
실패하면 출력과 백업 경로를 보관하고 기존 app/data 삭제나 임의 복원을 실행하지 않는다.

## 검증

- SQLite 전체 Django 165개 실행: 156개 통과, MariaDB 전용 9개 건너뜀.
- MariaDB 10.11.14에서 신규 규칙·실제 마이그레이션·기존 동시 차감/복원 17개 모두 통과.
- 12개 월의 입사일별 계산, 1월 1일 다음 해 12일, 기존 장기근속표/25일 상한 확인.
- 기존 0010 DB를 실제 0011로 올려 과거 규정/잔액·수동값·사용량 보존과 미래 초기화 잔액 보정을 확인.
- 규정 안내문/다른 근속 구간 보존, 재실행 시 추가 감사/버전 변경 없는 동작 확인.
- 입사 연도 최초 부여 후 월이 바뀌어도 중복 적립하지 않음, 연도 전환 시 미리 사용한 양 보존 확인.
- 직접 등록/취소, 수동값 재계산 확인란, 화면 렌더링 및 새 안내 확인.
- NAS 묶음 3개 시험: 정확한 복사와 이전 규칙 백업, 비공개 설정 보존,
  손상 파일/진행 중 복구 차단, 실패 시 완료 표시 차단과 백업 보존.
- 시스템 검사, 마이그레이션 일치 검사, diff 공백 검사 통과.

실제 직원 데이터와 운영 NAS에는 이 검증을 실행하지 않았다. 실제 NAS 적용은 별도이다.
