# 구매요청서 수정 계획서

작성일: 2026-10-23
목적: 기존 사내결재 화면을 유지하면서 구매요청의 작성·검토·구매 결재를 직관적으로 정리한다.
범위: 구매요청서와 관련 결재함·구매요청함·권한·규정·알림. 휴가원 수정은 이 계획에서 제외한다.
문서 상태: 대표님이 실제 결제하고 경리가 결제 완료를 등록하는 최신 흐름으로 변경한다. 구현·검증 내용은 LOCAL_PAYMENT_20261023.md 및 LOCAL_PAYMENT_VALIDATION_20261023.md를 참고한다. 실제 NAS에는 적용하지 않는다.

## 1. 기본 방향

- 기존 홈·결재함·내 문서함·내 승인 내역의 틀을 유지한다.
- 기안자는 구매 내용과 검토자만 입력한다. 다음 승인자는 검토자가 정한다.
- 자주 하는 행동을 먼저 보여주고, 권한이 없는 행동은 표시하지 않는다.
- 검토 화면에서 승인자 선택과 처리 버튼을 접거나 별도 창에 숨기지 않는다.
- 내부 승인과 대표의 실제 결제·경리의 완료 등록을 구분한다. 수령 여부는 결재 상태와 별도로 관리한다.
- 기존 문서·첨부·결재 이력을 보존한다. 새 방식은 새로 제출하는 문서부터 적용한다.

## 2. 역할별 처리 흐름

| 역할 | 할 일 |
| --- | --- |
| 기안자 | 구매 내용을 작성하고 검토자를 지정해 검토 요청 |
| 검토자 | 내용을 검토하고 다음 승인자를 지정해 승인 요청. 규정상 권한이 있을 때만 내부 승인완료 가능 |
| 승인자 | 검토자가 요청한 문서를 확인하고 내부 승인 처리 |
| 구매확인 담당자 | 소관 부서의 구매 내용을 확인 |
| 구매 담당자·경리 | 확인된 품목을 취합해 결제 요청. 실제 결제 사실을 전달받으면 결제 완료 등록. 품목별 반려·보류 처리 |
| 대표 | 품목·기안자·구매처·수량·가격·용도·진행상황 조회 후 실제 결제. 시스템 승인 버튼 없음 |
| 기안자 | 결재완료 확인 후 물품을 모두 받으면 수령 완료 처리 |

일반 흐름: 기안 → 검토 → 내부 승인 → 구매확인 → 경리의 결제 요청 → 대표 실제 결제 → 경리 결제 완료 등록 → 수령 확인.

예외는 다음과 같이 유지한다.

- 규정에서 허용한 과장·팀장·부장·이사는 ‘검토 요청’과 ‘구매담당자에게 요청’ 중 선택한다. 후자는 내부 검토·승인을 생략하되 구매확인과 대표의 실제 결제 및 경리 완료 등록은 거친다.
- 개발팀 기안 건은 개발팀 이사, 그 외 부서는 생산팀 이사가 구매확인을 담당한다. 기준은 기안자의 부서다.
- 내부 승인을 완료한 사람이 구매확인 담당자와 같으면 설정에 따라 한 번에 처리한다.
- 구매확인 담당 이사 본인의 직접 요청은 본인이 확인한 기록을 만들지 않고 구매 담당자에게 전달한다. 대표의 실제 결제 및 경리 완료 등록은 유지한다.
- 기안자가 본인 문서를 승인하는 ‘본인 전결’ 선택은 제공하지 않는다.

## 3. 구매요청서 작성 화면

다음 항목을 기본 화면에 보여준다.

| 항목 | 입력 방식 |
| --- | --- |
| 품목명·모델·규격 | 필수 |
| 구매처 | 필수 |
| 수량·개당 금액 | 필수, 총액 자동 계산 |
| 구매 링크 | **필수, 추가 정보에서 기본 입력 영역으로 이동** |
| 구매 사유 | 필수 |
| 첨부파일 | 견적서·참고자료 등을 첨부 가능 |
| 검토자 | 검토 요청 방식을 선택했을 때 지정 |

- 구매 링크가 없거나 주소 형식이 맞지 않으면 제출할 수 없도록 해당 입력란에서 안내한다.
- 임시저장은 구매 링크가 없어도 가능하게 한다. 기존에 링크 없이 제출된 문서는 보존한다.
- 필요일·사용 부서·보관 위치 등은 보조 정보로 구분한다. 구매 링크를 선택 사항처럼 표시하지 않는다.
- 기안자는 승인자를 미리 지정하지 않는다.
- 글자나 버튼이 잘리지 않도록 긴 이름·작은 화면에서도 줄바꿈과 배치를 확인한다.

## 4. 검토 화면 — 최신 추가 변경

검토 화면의 기본 행동은 **승인자 지정 후 승인 요청**으로 배치한다.

표시 예시:

```text
지금 할 일
구매 내용을 검토한 뒤 승인자를 지정해 요청해 주세요.

승인자 부서  [부서 선택 ▼]
승인자       [직원 선택 ▼]
[승인 요청]                    ← 주요 버튼

내부 승인 완료                 ← 해당 권한이 있는 검토자에게만 표시
다음 승인 없이 내부 승인을 완료합니다.
이후 구매확인과 대표의 실제 결제 및 경리 완료 등록은 계속 진행됩니다.
[승인완료]                     ← 보조 버튼

반려·보완 요청 등 추가 작업      ← 접지 않고 표시
```

- ‘승인자에게 전달’을 눌러야 선택란이 나타나는 방식은 제거한다. 부서·직원 선택란은 처음부터 펼쳐 둔다.
- 주요 버튼 문구는 ‘승인 요청’으로 통일한다. 클릭 후에는 누구에게 요청했는지 안내한다.
- ‘승인완료’는 구매 규정에서 권한을 부여받은 현재 검토자에게만 표시한다. 직급만으로 자동 허용하지 않는다.
- ‘승인완료’를 큰 강조 버튼으로 배치하지 않는다. 승인 요청 아래의 별도 보조 영역에 둔다.
- 승인완료 권한이 없는 검토자에게는 해당 버튼과 관련 설명을 모두 숨긴다.
- 승인 요청 시에는 승인자 지정이 필수다. 직접 승인완료할 때에는 승인자 선택이 필요하지 않다.
- 기안자와 현재 검토자 본인은 다음 승인자로 선택할 수 없다. 규정상 승인 가능한 직원만 선택할 수 있다.
- 화면 표시뿐 아니라 실제 처리 시점에도 권한을 다시 검사한다. 권한 해제 후 이전 화면으로 승인할 수 없게 한다.
- 반려·보완 요청은 사유를 입력한다. 단순 승인 요청의 메모는 선택 사항으로 둔다.

## 5. 구매확인·대표 조회·경리 결제 처리

- 구매확인 담당자는 확인해야 할 내용과 처리 동작을 먼저 본다. 완료 후에는 확인완료 표시와 처리자를 남긴다.
- 대표에게는 품목별 **구매처 / 수량 / 단가 / 총액 / 구매 사유**를 각각 분리해 보여준다.
- 구매 링크·첨부·직원이 작성한 원본을 바로 확인할 수 있게 한다.
- 대표에게 승인·반려·보류 버튼을 제공하지 않는다. 대표는 구매 내역과 결제 진행상황만 조회한다.
- 경리가 실제 결제된 품목을 선택해 결제 완료를 등록하며 이때 문서를 결재완료로 처리한다.
- 품목별 반려·보류도 경리가 처리한다. 사유는 필수다. 결제된 품목을 바로 반려하지 않는다.
- 선택 품목과 합계금액을 확인한 후 확정하며 다른 품목은 결제 대기로 유지한다.
- 잘못 등록한 결제 완료는 미수령 상태에서 사유를 남겨 정정한다. 이전 등록·정정 이력을 보존한다.
- 대표 화면에서는 수령 현황·수령 개수 집계를 표시하지 않는다.

## 6. 문서함과 진행 상태

- 새 결제 요청은 대표의 결재함 미결·내 승인 내역에서 제외한다. 대표는 구매 진행현황에서 조회하며 기존 결재 방식으로 제출된 과거 문서는 보존한다.
- 결재함·내 문서함·내 승인 내역에서는 구매요청 유형으로 분류해 찾는다. 대표에게 별도 구매승인 메뉴를 중복 제공하지 않는다.
- 구매 담당자의 구매요청함은 품목 선택·결제 요청·보류·완료를 관리하는 업무 화면으로 유지한다. 구매 모아보기는 별도 메뉴로 나누지 않는다.
- 동일한 요청을 별도 문서로 복제하지 않는다. 원본 구매요청과 대표에게 보낸 묶음 요청은 연결해 추적한다.
- 구매요청함에는 수령까지 끝난 품목을 확인하는 ‘완료’ 탭을 둔다.
- 목록에서는 품목명·기안자·구매처를 중심으로 보여준다. 문서번호는 목록에서 숨기고 내부 관리·원본·출력에 보존한다.
- 세부 내부 상태를 긴 드롭다운에 전부 나열하지 않는다. 사용자가 찾는 진행·완료·보류 등의 구분과 현재 할 일을 중심으로 표시한다.
- 경리가 결제 완료를 등록한 품목은 **결재완료**를 유지한다. 기안자·구매 담당자 화면에는 옆에 **수령 대기 / 수령 완료**를 별도로 표시한다.
- 보류 품목이 남은 묶음 요청 전체를 결재완료로 표시하지 않는다. 각 품목의 결제 완료·반려·보류를 구분한다.

## 7. 수령 확인과 알림

- 기안자는 물품을 모두 받았을 때 ‘수령 완료’를 한 번 누른다.
- 받은 수량·남은 수량·부분 수령 개수 입력과 집계는 표시하지 않는다. 사용·보관 위치와 메모는 선택 사항으로 남긴다.
- 수령 완료 결과는 구매 담당자의 해당 구매문서와 구매요청함에도 반영한다.
- 수령 완료를 눌러도 결재완료 상태나 승인 이력은 바꾸지 않는다.
- 완료 알림은 “최종결재가 완료되었습니다.”로 표시한다. 기안자에게 결제 상세를 알리지 않는다. 검토·내부 승인 등 기존 안내와 반려·보완 요청·보류 안내는 유지한다.
- 반려·보완 요청·보류처럼 기안자가 알아야 하는 결과는 유지한다. 내부 구매확인·취합 등으로 비슷한 알림을 반복하지 않는다.

## 8. 구매 규정과 권한 설정

- 구매 규정과 휴가원 규정은 분리한다. 규정의 사용 여부와 적용 내용을 쉽게 확인하도록 한다.
- 구매 규정에서는 직접 요청 가능 직급, 내부 승인완료 가능한 검토자, 승인·구매확인 중복 처리 기준을 설정한다.
- 직원·권한관리에서는 개발팀 구매확인 담당자, 그 외 부서 구매확인 담당자, 구매 담당자, 결제 내역을 조회할 대표를 지정한다.
- 규정 화면에는 현재 담당자를 보여주고 담당자 설정 화면으로 바로 연결한다. 담당자를 규정과 직원 화면에서 각각 다르게 지정하지 않는다.
- 규정을 꺼도 이미 제출된 문서와 처리 이력은 보존한다. 현재 처리자의 유효한 권한은 별도로 확인한다.
- 실제 직원에게 검토 단계 승인완료 권한을 자동 부여하지 않는다. 관리자가 대상자를 지정한다.

## 9. 유지할 기능과 적용 확인

첨부파일과 열람 권한, 보완 요청, 보류 후 재요청, 금액 증가 시 재승인, 기존 승인 금액과 원본 보존, 엑셀, 유사 구매 안내, 백업·복구는 유지한다.

다음 로컬 테스트에서는 다음 항목을 확인한다. 이 목록은 향후 확인 기준이며 최신 추가 변경의 테스트 완료 기록이 아니다.

1. 구매 링크가 기본 화면에 보이고 제출 시 필수이며, 링크 없이 임시저장은 가능하다.
2. 검토자가 화면을 열자마자 승인자 부서·직원을 선택할 수 있다. 추가 작업도 접혀 있지 않다.
3. 일반 검토자에게는 승인완료가 보이지 않고, 권한 있는 검토자에게만 보조 버튼으로 표시된다.
4. 승인 요청은 승인자 미지정 시 막히고, 권한 있는 승인완료는 승인자 미지정 상태에서도 처리된다.
5. 본인 승인·부적격 승인자 지정·권한 해제 후 승인·같은 문서 중복 처리를 막는다.
6. 두 요청 방식 모두 올바른 구매확인 담당자와 구매 담당자를 거쳐 대표에게 도달한다.
7. 대표는 필요한 구매 정보를 분리해서 조회하고, 경리가 결제 완료·반려·보류를 처리한다. 수령 집계는 보이지 않는다.
8. 새 요청은 대표의 미결·내 승인 내역에 중복되지 않고, 경리 결제 완료가 기안자의 결재완료로 연결된다.
9. 기안자의 수령 완료가 구매 담당자 문서와 완료 탭에 반영된다.
10. 기존 문서·첨부·이력과 구매 이외의 사내결재 기능을 보존하고 작은 화면에서도 내용이 잘리지 않는다.

진행 순서: 계획 기준으로 화면·입력 검증 수정 → 권한과 처리 흐름 확인 → 새 로컬 테스트 파일 제공. 실제 NAS 적용은 별도 단계로 진행한다.
