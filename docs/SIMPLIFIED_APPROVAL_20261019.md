# 과장급 이상 간소 결재와 직원별 전결규정

과장·팀장·부장·이사 중 규정에서 허용한 직원은 기안 화면에서 **규정 기본 / 검토 생략 / 본인 전결**을 선택할 수 있습니다. 사원·주임·대리, 비활성·미승인 직원, 미확정 부서, 시스템 관리자 계정은 새 간소결재 선택 권한을 사용할 수 없습니다. 화면을 거치지 않는 제출 요청도 같은 권한 검사를 받습니다.

기존 금액별 기본 경로와 기본 경로의 검토 생략 설정은 유지합니다. 이번에 추가한 본인 전결 권한은 자동 부여하지 않습니다.

## 규정관리에서 설정

1. **규정 관리 → 전결규정**에서 새 규정을 만들거나 기존 규정을 수정합니다.
2. 문서 종류와 적용 직급·부서·특정 직원을 지정합니다. 비어 있는 대상 조건은 전체를 뜻하며, 지정한 조건을 모두 만족해야 합니다.
3. **과장급 이상에게 검토 생략 선택 허용**, **과장급 이상에게 본인 전결 선택 허용** 중 필요한 권한을 체크합니다.
4. 검토·승인 가능 직급을 지정합니다. 담당자를 고정하거나 최종 승인자를 기안자 본인으로 지정할 수도 있습니다. 기존 직급 순서·적격 담당자 조건도 충족해야 합니다.
5. **규정 사용**을 체크해 저장합니다. 오른쪽 미리보기에서 **특정 기안자**와 결재방식을 선택하면 해당 직원에게 적용되는 결과를 볼 수 있습니다. 직급만으로 확인하는 미리보기에는 직원·부서 예외를 적용하지 않습니다.

적용 우선순위는 **특정 직원 → 부서 → 직급 → 회사 공통**입니다. 같은 우선순위에서 문서·대상·금액 조건이 겹치면 저장을 막습니다. 관리 화면을 통하지 않고 겹치는 규정이 만들어져도 실제 제출을 차단합니다.

## 기안과 완료

| 결재방식 | 동작 |
| --- | --- |
| 규정 기본 | 기존 규정의 검토·최종 승인 경로를 사용합니다. 동일인이 여러 단계 담당자여도 단계별로 처리합니다. |
| 검토 생략 | 검토자를 생략하고 최종 승인자만 표시합니다. 별도 최종 승인을 기다립니다. |
| 본인 전결 | 검토자·승인자 선택을 생략하고 **전결로 제출·완료**를 누르면 즉시 최종 완료됩니다. |

임시저장은 전결하거나 연차를 차감하지 않습니다. 제출 시 최신 직급·권한·규정·금액과 휴가 중복 여부를 다시 확인합니다. 규정 변경과 제출은 기존 규정 잠금으로 직렬화하며, 문서 처리·차감·이력·알림은 하나의 트랜잭션으로 처리합니다.

본인 전결 휴가는 제출 시 기존 최종 승인과 동일하게 차감되어 사용내역과 직원 일정에 표시됩니다. 문서에는 본인 전결 표시, 전결자, 처리 시각, 적용 규정·버전·결재선이 남습니다. 승인 취소는 기존 절차와 같은 권한·사유·중복 방지 조건으로 실제 차감량을 한 번 복원합니다.

구매요청서는 전결 후 기존 구매·배송·수령 절차를 유지합니다. 생산 재고는 기존 검토·발주·입고 경로를 유지하며 이번 간소결재 선택 대상에 포함하지 않습니다.

## 기존 자료 보존

- 이미 제출한 문서는 저장된 결재선으로 계속 처리합니다. 규정 수정으로 경로·차감·완료 이력을 소급 변경하지 않습니다.
- 마이그레이션 0012는 규정의 대상·권한·담당자 필드, 직원 연결 테이블, 문서의 결재방식 필드만 추가합니다. 기존 문서는 `base`, 새 선택 권한은 `False`입니다. 기존 업무 데이터를 변환하는 작업은 없습니다.
- 기존 직원·암호·문서·임시저장·잔액·수동 조정·직접 사용·공용연차·규정·감사 이력을 삭제하거나 초기화하지 않습니다. 연차 산정 방식은 변경하지 않습니다.
- NAS 패치는 `.env`, DB 파일, 연차 산정 코드와 이전 연차 변경 마이그레이션을 포함하지 않습니다. 이전 마이그레이션 0011 소스가 없는 설치는 복사하기 전에 중단합니다.
- 앞선 미결·개인 사용연차·직접 등록 휴가 달력 표시도 포함합니다.

## NAS 업데이트

ZIP을 File Station **/docker/company-approval**에 업로드하고 **여기에 압축 풀기**를 선택합니다. Windows PowerShell에서 실행합니다.

```powershell
ssh -t admin@192.168.1.46 "sudo sh /volume1/docker/company-approval/xenosys-simplified-approval-20261019/APPLY_SIMPLIFIED_APPROVAL.sh"
```

`SIMPLIFIED_APPROVAL_READY` 확인 후 PC·휴대폰 사이트를 새로고침하고 규정관리에서 필요한 대상과 권한을 지정합니다. 실제 NAS에는 사용자가 이 명령을 실행한 후 적용됩니다.

체크섬·선행 기능·진행 중 업데이트를 확인하고 기존 파일을 `.simplified-approval-backup.*`에 보관합니다. 기존 `nas.sh update`는 이미지를 빌드한 후 웹을 잠시 중단하고, 이전 이미지로 DB 백업을 완료한 다음 마이그레이션과 새 이미지 전환을 수행합니다. 기존 일반 미초기화 연차 동기화 절차도 유지합니다. 실패하면 READY를 출력하지 않고 소스 보관본을 남깁니다. 오류 후 app/data 삭제·재설치·임의 DB 복원은 하지 않습니다.

## 검증

- SQLite 전체 188개 실행: 177개 통과, 실제 DB 잠금 전용 11개 제외.
- 별도 MariaDB 10.11.14: 전체 188개 통과, 제외 없음.
- 실제 0011→0012 업그레이드에서 기존 직원 암호, 모든 문서 상태·결재선, 연차 총량·사용량·수동 지정, 직접 사용내역, 기존 규정·연차 정책·이력 보존 확인.
- 같은 임시저장 문서 동시 전결은 한 번만 차감하며, 경리 직접 등록과 동일 날짜 동시 전결은 중복 사용을 거부.
- 권한 위조, 하위 직급·비활성·미승인·미확정 부서, 직원/부서/직급 우선순위, 중복 규정, 고정 담당자, 기안자 본인 최종 승인, 금액 경계, 임시저장·권한 회수·완료·취소 및 트랜잭션 롤백 검증.
- 설치기 7개: 허용 파일만 교체·원본/데이터 보존, 손상 파일, 진행 중 작업, 선행 기능/스키마 누락, 백업 없는 설치기, 업데이트 실패 처리.
- Chromium 320·390·768·1366px: 담당자 자동 지정, 허용된 선택지만 표시, 검토 생략, 본인 전결 임시저장/완료/취소, 실제 차감·복원, 하위 직급 제한, 규정 미리보기, 가로 넘침·JS 오류·정적 파일 실패 없음.

테스트와 브라우저 확인에는 분리된 가상 데이터만 사용했습니다. 실제 NAS 데이터는 접근하거나 개발 환경으로 가져오지 않았습니다.
