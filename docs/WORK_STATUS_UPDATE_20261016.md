# 홈 미결·개인 사용연차·직원 일정

홈의 ‘결재 진행 상태’에 현재 로그인 직원이 검토하거나 승인해야 하는 문서를
**미결 N건**으로 표시하고 결재함으로 연결합니다. 기존 결재함과 동일한 집계를
재사용하며, 열람만으로 건수를 줄이지 않습니다. 본인이 제출한 문서의 진행 중
건수·기안 선택·진행 단계는 별도로 유지합니다.

직원별 연차 관리에는 **개인 사용연차** 열을 추가합니다. 저장된 전체 사용연차에서
활성 공용연차 차감분을 뺀 값으로 표시하므로 승인 휴가·경리 직접 등록과 기존
잔액 정정을 반영합니다. 기존 정정으로 음수가 생긴 경우에도 원래 값을 숨기거나
변경하지 않습니다. 잔여 = 사용가능 − 개인 사용 관계를 유지합니다.

직원 일정에는 승인된 휴가와 함께 취소되지 않은 직접 등록 휴가의 직원·종류·날짜·시간을
표시합니다. 등록 사유는 공용 달력에 노출하지 않습니다. 연차 관리 권한이 있는
직원에게만 사용내역 링크를 제공합니다. 오늘 일정도 같은 달력 데이터를 사용합니다.

공용연차 날짜 숫자와 회사 휴무 범례·표시선을 같은 주황색으로 맞춥니다.
모바일 일정 목록에도 적용하며 공용연차 삭제·비활성화·일반 휴무로 변경하면
해당 날짜의 표시가 원래대로 돌아갑니다. 휴가 차감 규칙은 달력 색상과 독립적입니다.

## NAS 적용

직접 등록 기능이 설치된 NAS에 `releases/xenosys-work-status-20261016.zip`을 사용합니다.
File Station `/docker/company-approval`에 업로드하고 ‘여기에 압축 풀기’를 선택한 후
Windows PowerShell에서 실행합니다.

```powershell
ssh -t admin@192.168.1.46 "sudo sh /volume1/docker/company-approval/xenosys-work-status-20261016/APPLY_WORK_STATUS.sh"
```

마지막 `WORK_STATUS_READY`를 확인한 후 PC·휴대폰을 새로고침합니다.
서비스가 잠시 중단되며 실제 NAS 적용 여부는 해당 출력과 접속으로 확인해야 합니다.

## 데이터 보존 범위

ZIP은 화면 조회 코드·템플릿·CSS 7개만 복사합니다. 연차 산정 코드, 모델,
마이그레이션, 엑셀 내보내기, 환경 설정·비밀번호는 포함하지 않습니다.
기존 직원·문서·직접 사용·공용연차·수정 사유·취소 이력을 삭제하거나 변환하지 않습니다.
연차 계산 방식 추가 변경과 기존 총량 재계산은 이 업데이트의 범위에 없습니다.

설치 스크립트는 체크섬을 확인하고 이전 소스를 `.work-status-backup.*`에 보관합니다.
기존 NAS 업데이트 절차의 DB 백업 지원을 확인한 다음 `nas.sh update`를 호출합니다.
이 절차는 이미지 빌드 후 기존 이미지로 DB 백업을 완료하고 새 이미지를 적용합니다.
기존 설치의 일반 마이그레이션 및 미초기화 연차 동기화는 유지합니다.
실패 시 READY를 출력하지 않으며 이전 소스 보관본을 남깁니다.

기존 연차·문서·일정이 있는 테스트 데이터에서 세 화면을 조회한 전후로 사용자,
프로필, 연차 잔액, 문서, 직접 등록·취소, 공용연차·차감, 수정 이력이 동일함을 검증했습니다.
실제 NAS 데이터는 개발 환경에서 접근하거나 사용하지 않았습니다.

## 검증

- Django 전체 173개 실행: 164개 통과, MariaDB 전용 9개 제외.
- 별도 MariaDB: 신규 화면·직접 등록·달력/연차 기존 동작 42개 통과.
- 설치기 6개: 복사 허용 목록·원본 보관·설정/데이터 보존, 손상 ZIP,
  진행 중 작업, 선행 기능 누락, DB 백업 미지원, 업데이트 실패 처리 검증.
- Chromium 320·390·768·1366px: 미결 0/존재 및 결재함 연결, 개인/공용 값,
  직접 등록 일정·사유 비공개·링크 권한, 날짜 색상 일치, 화면 가로 넘침 확인.
- 정적 파일은 운영과 동일한 WhiteNoise manifest 방식으로 제공하여 확인.
- 모델 변경 검사: 신규 마이그레이션 없음.
