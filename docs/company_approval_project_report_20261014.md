## 01. 목적과 현황

휴가·구매·재고 요청을 한곳에서 작성하고 처리하여, 문서 전달과 진행 확인에 드는 수고를 줄인다.

### 1.1 추진 배경

현재 구매 업무는 직원이 요청한 품목을 경리 직원이 Excel로 정리하여 사장님께 구매를 요청하는 방식이다. 새로운 시스템은 문서 작성, 검토·승인, 경리 확인 및 Excel 정리를 연결하여 반복 전달과 수기 취합을 줄이는 것을 목표로 한다.

휴가원은 본인의 잔여 연차를 확인한 뒤 신청하고, 최종 승인 시 연차에 반영하도록 한다. 생산 재고 요청은 부족한 재고를 검토자에게 확인받아 발주 담당자에게 전달하는 별도의 간단한 업무로 운영한다.

### 1.2 목표와 기대 효과

| 개선 목표 | 시스템 제공 내용 | 기대 효과 |
| --- | --- | --- |
| 진행상황 확인 | 본인 문서 및 단계별 담당자·처리 일시 표시 | 구두 문의와 누락 감소 |
| 연차 관리 | 승인 시 차감, 취소 시 복원, 경리 수동 수정 | 계산 일관성 및 수정 근거 확보 |
| 구매 취합 | 선택한 승인 문서를 Excel로 출력 | 기존 구매 요청 방식과 연결 |
| 재고 발주 전달 | 검토만 거치는 생산 재고 전용 요청함 | 생산 재고 업무의 처리 단순화 |
| 업무 기록 보존 | 문서·처리 이력·알림·백업 | 누가 언제 처리했는지 확인 |

### 1.3 적용 범위

| --- | --- |
| 사용 대상 | 생산팀·품질팀·개발팀·영업팀·전략기획팀·인사팀의 전 직원 |
| 이용 환경 | PC 웹브라우저 / 실운영 서버는 사내 NAS / 실운영 DB는 MariaDB |

| 제외 범위 | 모바일 전용 화면, 외부 메일·메신저 알림, 파일 첨부, 공휴일 달력, 자동 연차 부여·연말 초기화·이월 |
| 추가 확인 자료 | 직원 수, 월 처리 건수, 기존 소요 시간 및 익명화한 실제 완료 문서 |

**문서 작성 기준**

2026년 10월 14일까지의 사용자 결정사항과 현재 시안 소스를 기준으로 정리한다. 과거 계획서보다 이후에 변경된 업무 규칙을 우선 반영한다. 정량적인 개선 목표는 실제 업무 자료 확보 후 설정한다.

## 02. 시스템 전체 구성

계정·기안, 검토·승인, 경리·운영의 세 영역을 연결한다. 생산 재고는 별도의 검토 경로를 사용한다.

### 2.1 업무 구성

| 영역 | 핵심 기능 | 다음 업무와의 연결 |
| --- | --- | --- |
| 계정·기안 | 가입 승인, 직원 정보, 권한, 임시저장, 문서 작성 | 제출 후 지정 검토자에게 전달 |
| 검토·승인 | 검토·최종 승인, 반려·취소, 처리 내역 | 휴가는 연차 반영 / 구매는 경리 확인 / 재고는 발주 대기 |
| 경리·운영 | 연차 관리, 구매·발주, 수령 확인, Excel, 알림·이력 | 직원에게 처리 결과 제공 및 기록 보관 |

**휴가원·구매요청서**: 기안자 → 검토자 → 최종 승인자

**생산 재고 요청**: 요청자 → 검토자 → 발주 담당자

### 2.2 기술 구성

| 계층 | 현재 시안 | 실운영 목표 |
| --- | --- | --- |
| 화면 | HTML · CSS · JavaScript / PC 웹 | 같은 화면을 사내 PC에서 접속 |
| 업무 처리 | Python · Django | NAS에서 실행하는 웹 애플리케이션 |
| 데이터베이스 | SQLite 시연 DB | 프로젝트 전용 MariaDB DB |
| Excel 출력 | openpyxl / .xlsx | 승인된 구매 문서 및 직원별 연차 현황 |
| 실행·배포 | 개발 서버 및 Windows 단독 시연 패키지 | NAS 실행 방식·접속 주소·운영 설정 확정 필요 |

### 2.3 현재 상태와 구분

현재는 가상 직원과 예시 문서를 저장하는 기능 시안이 준비되어 있다. 문서 제출·결재, 연차 차감·복원, 물품 상태, 권한, 알림 및 Excel 출력을 시연할 수 있다. 실제 회사 데이터 및 기존 MariaDB에는 연결하지 않았다.

**실운영 전환**

MariaDB가 NAS에 설치되어 있다는 조건을 활용한다. 기존 DB 설치를 새로 과제로 포함하지 않으며, 프로젝트 전용 DB 연결·동시 처리·서버 운영·백업 복구는 별도로 검증한다. Windows 단독 시연과 사내 공유 운영은 서로 다른 실행 방식이다.

## 03. 직원 계정과 권한

직급·부서 정보와 업무 권한을 분리한다. 관리자 지정에 따라 메뉴를 표시하고 서버에서도 같은 권한을 확인한다.

### 3.1 가입·직원 관리

회원가입 필수 정보는 성명, 아이디, 비밀번호·확인, 부서, 직급이다. 새 가입자는 관리자 승인 전 업무를 사용할 수 없으며 직원 관리의 “미분류 계정”에 표시한다. admin이 승인하고 부서 분류를 확정하면 해당 부서 탭으로 이동한다.

| 항목 | 기준 |
| --- | --- |
| 부서 | 생산팀 / 품질팀 / 개발팀 / 영업팀 / 전략기획팀 / 인사팀 |
| 직급 | 사원 / 주임 / 대리 / 과장 / 팀장 / 부장 / 이사 |
| 직원 표시 순서 | 이사 → 부장 → 팀장 → 과장 → 대리 → 주임 → 사원. 같은 직급은 이름순 |
| 직원 관리 화면 | 미분류 계정 및 부서별 탭. 가입 승인·활성/비활성·부서·직급·업무 권한 변경 |
| 내 계정 | 현재 비밀번호 확인 후 본인 비밀번호 변경. 변경 후 로그인 상태 유지 |
| 비밀번호 | 4자 이상, 숫자만 입력해도 허용. 초기·임시 비밀번호는 첫 로그인 시 변경 |

### 3.2 권한 구성

| 권한 | 허용 업무 |
| --- | --- |
| 기본 직원 | 기안·임시저장·본인 문서·잔여 연차·알림·규정 조회. 지정된 단계의 결재와 본인 수령 확인 |
| 연차 관리 | 직원별 연차 조회·수정·사용 내역·현황 Excel·연차규정 수정 |
| 경리 문서 조회 | 완료 문서함의 휴가원·구매요청서·생산 재고 요청 조회 및 구매 문서 Excel |
| 구매·발주 처리 | 완료된 구매의 구매 처리, 검토가 끝난 재고의 발주 처리 |
| 시스템 관리 | 가입·직원·권한 관리, 전체·삭제 문서 조회, 대기 담당자 변경, 시안 백업·복구 |

권한은 함께 부여할 수 있으며 부서나 직급만으로 자동 부여하지 않는다. 경리 직원도 기본 기안 권한을 사용한다. 일반 직원에게 직원별 연차 관리·경리 완료 문서·관리자 메뉴가 보이지 않도록 한다.

**초기 관리자**

최초 관리자 아이디는 admin으로 한다. 초기 비밀번호는 설치 단계에서 설정하고 첫 로그인에 변경한다. 계정별 실제 비밀번호는 본 보고서에 기재하지 않는다. 관리자 전체 조회 권한이 모든 문서의 결재·취소 권한을 뜻하지는 않는다.

## 04. 입력 항목과 문서 작성

문서 종류에 따라 필요한 항목만 보여 준다. 한 기안에는 한 품목 또는 한 번의 연속 휴가 기간을 입력한다.

### 4.1 공통 작성 기준

새 기안에서 문서 종류를 선택한 뒤 내용을 작성하고 결재선을 지정한다. 임시저장 단계에서는 다시 열어 수정할 수 있다. 제출 시 필수값과 결재자 자격을 확인하고, 문서 제목 및 문서번호를 자동 생성한다.

| 문서 | 입력 항목 | 입력 기준 |
| --- | --- | --- |
| 휴가원 | 연차·오전반차·오후반차·외출, 시작/종료 날짜, 해당 시간, 사유, 검토자·승인자 | 연차는 연속 기간. 반차·외출은 하루의 시간 구간. 사유 필수 |
| 구매요청서 | 품명, 수량, 개당 가격, 구매 링크, 긴급도, 신청사유, 필요 날짜, 수령자, 검토자·승인자 | 한 품목만 입력. 수량은 1 이상 정수, 단가는 0원 초과. 사유·필요 날짜는 선택 |
| 생산 재고 요청 | 품명, 수량, 긴급도, 신청사유, 필요 날짜, 수령자, 검토자 | 가격·총금액·구매 링크·최종 승인자 없음. 사유·필요 날짜는 선택 |

### 4.2 결재선 지정

**선택 순서**: 부서 선택 → 부서 내 직원 선택 → 결재선 확인

검토자·승인자는 활성 상태이면서 가입 승인과 부서 분류가 끝난 주임 이상 직원만 선택한다. admin 및 시스템 관리 권한 계정은 제외한다. 기안자 본인도 자격을 만족하면 선택할 수 있다. 같은 사람이 검토자와 승인자여도 두 단계를 각각 처리한다.

### 4.3 번호·수령자·긴급도

| 항목 | 처리 방식 |
| --- | --- |
| 문서번호 | 제출일별 일련번호: DOC-YYYYMMDD-0001. 예: DOC-20261014-0001 |
| 제목 | 휴가: 종류·성명·기간 / 구매·재고: 문서 유형·성명·품명으로 자동 생성 |
| 수령자 | 구매·재고 요청에서 지정. 지정하지 않으면 기안자 본인을 기본 수령자로 설정 |
| 긴급도 | 일반 / 긴급. 긴급 사유는 필수가 아닌 선택 |
| 가격 | 사무·사내용품만 부가세 포함 단가 입력. 배송비 별도 입력 없음 |

**실제 업무 자료**

기존 Excel을 자동으로 가져오는 기능은 현재 범위에 포함하지 않는다. 기존 서식·시트·열과 완료된 업무 기록의 익명화 사본은 검토 및 비교 시험 자료로 확보한다.

## 05. 결재·반려·취소 규칙

제출된 문서는 내용을 고정하고, 지정된 담당자와 현재 단계에 맞는 처리만 허용한다.

### 5.1 공통 상태와 처리

| 상태·행동 | 처리 규칙 |
| --- | --- |
| 임시저장 | 기안자만 수정·재열기·제출 가능. 결재 시작 전이며 연차 차감 없음 |
| 기안 제출 | 검토대기로 전환. 이후 내용 수정 불가 |
| 검토확인 | 지정 검토자가 처리. 휴가·구매는 최종승인대기, 재고는 발주대기로 전환 |
| 승인확인 | 휴가·구매의 지정 최종 승인자가 처리. 휴가는 이 시점에 연차 차감 |
| 검토 전 삭제 | 기안자만 가능. 일반 목록에서는 숨기고 관리자 원문·변경 이력 보존 |
| 반려 | 현재 단계 담당자가 반려. 반려함으로 이동하고 사유 기록 |
| 복사 재기안 | 반려·취소 문서를 복사해 새 임시저장 문서 작성. 새 제출 번호 부여 |

### 5.2 승인 취소 권한

| 대상 | 취소할 수 있는 사람 | 취소 결과 |
| --- | --- | --- |
| 휴가·구매 검토 | 검토한 본인 / 최종 승인 전만 | 취소 상태로 반려함 이동 |
| 휴가·구매 최종 승인 | 최종 승인한 본인만 | 취소 상태 / 휴가는 차감 연차 복원 |
| 생산 재고 검토 완료 | 검토한 본인만 | 취소 상태 / 후속 발주·입고 처리 차단 |
| 최종 승인 후 검토 취소 | 허용하지 않음 | 최종 승인자가 취소해야 함 |

취소에는 별도의 추가 결재가 필요하지 않다. 실행 전 영향과 사유를 확인하는 팝업을 제공한다. 취소된 구매·재고는 후속 구매·발주·배송·입고 완료를 처리할 수 없다. 이미 진행된 외부 주문의 취소·반품은 시스템 밖에서 담당자가 별도로 처리한다.

### 5.3 조회와 기록

기안자는 본인 문서와 진행상황을, 검토자·승인자는 자신이 처리한 내역을 확인한다. 경리는 완료 문서함을 사용하며 다른 직원의 취소 문서는 조회 대상에서 제외한다. admin은 전체 문서와 삭제 기록을 확인한다.

**중복 처리 방지**

반복 클릭 및 동시 요청에서도 승인·연차 차감·복원·수령 확인은 한 번만 반영한다. 대기 담당자 변경은 관리자만 미처리 단계에 수행하며 사유와 이력을 남긴다. 기존에 완료한 단계의 기록은 유지한다.

## 06. 휴가원 신청과 연차 계산

신청은 허용하되 실제 차감은 최종 승인 시점에 반영한다. 날짜와 시간 중복은 제출 시 확인한다.

### 6.1 종류별 차감

| 휴가 종류 | 입력 | 차감량 |
| --- | --- | --- |
| 연차 | 시작일 ~ 종료일의 연속 기간 | 토·일을 제외한 날짜 수 × 1일 |
| 오전·오후 반차 | 하루의 날짜와 시작·종료 시간 | 건당 0.5일 |
| 외출 | 하루의 날짜와 시작·종료 시간 | 건당 0.25일 |

한 기안에서 10/07~10/09처럼 연속 기간을 선택할 수 있다. 10/07과 10/09처럼 떨어진 날짜를 묶어 신청할 수 없으며 두 기안으로 제출한다. 토요일·일요일은 모두 휴무로 계산에서 제외한다. 공휴일 달력 기능은 제공하지 않으므로 기안자가 공휴일을 피해 작성한다.

### 6.2 잔여 연차와 차감 시점

**연차 반영**: 제출: 차감 없음 → 검토: 차감 없음 → 최종 승인: 차감

작성 화면에는 현재 잔여 연차, 신청 차감량, 최종 승인 후 예상 잔여를 함께 표시한다. 잔여가 부족해도 제출할 수 있고, 승인 후 부족한 잔여는 음수로 표시한다. 반차·외출의 차감량은 선택한 시간 길이에 비례하여 바뀌지 않는다.

**계산 예시**

현재 잔여 0.5일에서 연차 1일을 최종 승인하면 잔여는 -0.5일이다. 이후 해당 최종 승인을 취소하면 실제 차감한 1일이 복원된다. 작성 중의 예상 잔여는 참고값이며 실제 값은 최종 승인 시 재확인한다.

### 6.3 날짜·시간 중복 검사

| 상황 | 처리 |
| --- | --- |
| 검사 대상 | 본인의 검토대기·최종승인대기·승인 완료 휴가 |
| 겹치는 시간 | 기존 09:00~12:30에 11:00~13:00 신청: 중복으로 제출 차단 |
| 맞닿은 시간 | 기존 09:00~12:30에 12:30~14:00 신청: 허용 |
| 연차와 부분 휴가 | 연차의 같은 근무일에 반차·외출 신청: 중복으로 차단 |
| 검사 제외 | 임시저장·반려·취소·삭제 문서는 중복 계산에서 제외 |
| 취소·연도 경계 | 최종 승인 취소 시 원래 차감 연도와 금액을 기준으로 한 번만 복원 |

## 07. 직원별 연차 관리와 사용 내역

경리의 연차 관리 권한으로 직원 현황을 조회·수정하고, 실제 신청 이력과 수동 조정 내역을 구분한다.

### 7.1 관리 화면과 수정 규칙

직원별 연차 관리에 연도·부서 선택을 제공한다. 직원은 높은 직급순으로 표시하며 총연차·사용연차·잔여연차를 확인할 수 있다. 문서함 목록에는 같은 부서 선택 필터를 넣지 않는다. 결재선의 부서 선택과 관리자 부서 탭은 유지한다.

| 수정 항목 | 자동 반영 | 공통 조건 |
| --- | --- | --- |
| 총연차 | 사용연차 유지 / 잔여 = 총연차 - 사용연차 | 수정 사유 입력 및 변경 이력 저장 |
| 사용연차 | 총연차 유지 / 잔여 재계산 | 급히 사용한 미기안 연차도 수동 반영 |
| 잔여연차 | 총연차 유지 / 사용연차 역산 | 음수 잔여 허용 |

**연말 운영**

자동 초기화·자동 근속연수 산정·자동 연차 부여·이월은 제공하지 않는다. 경리가 필요한 시점에 직접 수정한다. 연도별 기록은 과거 차감·복원을 추적하기 위한 용도다.

### 7.2 직원 선택 시 사용 내역

| 표시 영역 | 조회 내용 |
| --- | --- |
| 승인된 휴가 | 선택 연도의 승인된 날짜·시간·종류·차감량·문서번호. 미래 사용 예정 휴가는 예정으로 표시 |
| 전체 신청 이력 | 대기·승인·반려·취소 이력. 임시저장과 삭제는 제외 |
| 차감 합계 | 현재 승인된 휴가의 해당 연도 실제 차감량만 합산 |
| 수동 수정 이력 | 수정한 항목, 이전·이후 값, 사유, 담당자, 수정 시점 |
| 문서 상세 연결 | 해당 문서를 볼 기존 권한이 있는 경우에만 상세 링크 제공 |

수동 수정 시점은 실제 휴가 사용일이 아니다. 문서 없이 사용한 연차의 날짜를 추정해서 만들지 않는다. 따라서 관리 화면의 사용연차와 승인 문서 차감 합계는 수동 조정에 따라 다를 수 있다.

### 7.3 Excel 다운로드

선택한 연도·부서에 해당하는 직원 현황을 직급순으로 .xlsx 파일에 저장한다. 출력 항목은 연도, 성명, 부서, 직급, 총연차, 사용연차, 잔여연차다. 0.5·0.25 등 소수 연차와 음수 잔여를 유지한다. 연차 관리 권한을 서버에서 확인하고 다운로드 이력을 남긴다.

## 08. 구매요청서와 구매 Excel

사무·사내용품은 한 품목씩 승인받고, 경리가 선택한 문서를 Excel로 취합하여 기존 구매 요청 업무에 사용한다.

### 8.1 요청·금액·배송 흐름

품명, 수량, 부가세 포함 개당 가격, 구매 사이트 링크를 입력한다. 총가격은 수량 × 개당 가격으로 즉시 계산한다. 긴급도는 일반·긴급으로 선택하고 신청사유와 필요 날짜는 선택 입력한다. 배송비는 별도로 입력하지 않는다.

**금액 계산 예시**

수량 10개 × 개당 가격 1,200원 = 총가격 12,000원. 수량을 3개로 바꾸면 총가격은 3,600원으로 갱신된다. 최종 승인 전에는 구매 처리할 수 없다.

**후속 처리**: 결재완료 → 구매 처리·배송중 → 수령자 배송완료

구매·발주 처리 권한자가 링크와 금액을 확인하여 구매를 처리한다. 물품을 받은 지정 수령자가 배송완료를 확인한다. 결재 상태와 배송 상태는 별도로 표시한다. 구매 Excel 다운로드는 배송 상태를 변경하지 않는다.

### 8.2 선택 문서 Excel 다운로드

| 구성 | 동작 |
| --- | --- |
| 선택 대상 | 현재 승인 완료 상태의 사무·사내용품 구매요청서만 |
| 문서 선택 | 행별 체크박스 / 화면에 표시된 행 전체 선택 / 선택 행 강조 및 선택 건수 |
| 출력 열 | 성명 · 품명 · 수량 · 단가 · 총가격 · 신청사유 |
| 금액 표시 | 천 단위 쉼표, 소수점 없는 표시. 예: 111,000.00 → 111,000 |
| 실제 데이터 | 금액은 숫자 셀로 저장하며 내부 값의 정밀도는 유지 |
| 제출 검증 | 빈 선택·다른 종류·미승인·취소·권한 밖의 문서가 포함되면 전체 다운로드 거부 |
| 기록 | 다운로드한 문서와 실행자를 변경 이력에 보관 |

### 8.3 수령·취소 예외

수령 확인은 지정 수령자만 가능하며 반복 확인을 막는다. 승인 취소 후에는 경리 완료 문서함에서 제외하고 구매·배송완료 처리를 차단한다. 취소 전 구매·배송 기록은 남기며 실제 쇼핑몰 주문을 자동 취소하지 않는다.

**기존 업무와의 연결**

Excel 파일은 경리가 승인된 구매 품목을 모아 사장님께 구매를 요청하는 자료로 사용할 수 있다. Excel 작성·다운로드 자체는 최종 승인이나 실제 구매를 대신하지 않는다.

## 09. 생산 재고 요청과 발주·입고

“재고가 부족하므로 발주를 진행해 주세요”라는 요청에 맞춰 금액과 최종 승인 단계를 제거한다.

### 9.1 전용 요청함과 입력

왼쪽 메뉴에 “생산 재고 요청함”을 제공한다. 자사 제품 사용자 매뉴얼, 제품 보관함 등 생산에 필요한 부족 재고의 품명·수량을 요청한다. 구매요청서와 분리하여 담당자가 발주 대상과 입고 상태를 쉽게 확인하도록 한다.

| 항목 | 기준 |
| --- | --- |
| 필수 입력 | 품명, 1개 이상의 정수 수량, 검토자 |
| 추가 입력 | 일반·긴급, 선택 사유, 필요 날짜, 수령자 |
| 제거 항목 | 개당 가격, 총가격, 구매 사이트 링크, 최종 승인자 |
| 기안 단위 | 한 기안에 한 품목 |
| 결재 경로 | 요청자 → 검토자. 별도의 최종 승인 단계 없음 |

### 9.2 상태와 담당자

**처리 순서**: 검토대기 → 검토완료·발주대기 → 발주·입고대기 → 입고완료

| 상태 | 담당 | 처리 |
| --- | --- | --- |
| 검토대기 | 지정 검토자 | 내용 확인 후 검토확인 또는 반려 |
| 발주대기 | 구매·발주 처리 권한자 | 검토가 끝난 요청을 확인하여 발주 처리 |
| 발주완료·입고대기 | 지정 수령자 | 물품 도착 시 입고완료 확인 |
| 입고완료 | 요청자·담당자 | 처리 결과와 발주·수령 이력 확인 |
| 취소 | 검토한 본인 | 검토 취소 가능. 이후 발주·입고 완료 차단 |

### 9.3 경리 업무와의 관계

경리의 완료 문서함에는 생산 재고 요청 탭을 유지한다. 검토가 완료된 생산 재고 문서를 확인할 수 있으며 새 문서가 있으면 해당 탭을 주황색으로 표시한다. 경리의 알림함에는 생산 재고 관련 알림을 보내지 않는다.

**담당자 접근**

경리 문서 조회 권한이 없어도 구매·발주 처리 권한이 있는 발주 담당자는 완료된 생산 재고 요청함을 사용할 수 있다. 경리 권한이 없는 요청자·검토자·발주 담당자의 필요한 재고 알림은 유지한다.

## 10. 시스템 내부 알림

알림함과 홈의 최근 알림은 기안자의 이름·직급·문서 종류·처리 상태를 함께 보여 준다.

### 10.1 표시 형식

**표시 예시**

홍길동 - 과장 - 휴가원 - 검토대기  
홍길동 - 과장 - 구매요청서 - 승인완료

상태명은 검토대기, 검토완료, 승인대기, 승인완료, 배송중, 배송완료, 입고대기, 입고완료 등을 사용한다. 반려·취소 사유는 별도 줄로 표시한다. 이름·직급·종류·처리 상태는 알림 생성 시점에 저장하여 이후 문서 상태나 직원 정보 변경으로 과거 알림의 의미가 바뀌지 않도록 한다.

### 10.2 일반 직원·업무 담당자 수신 기준

| 발생 시점 | 기본 수신 대상 | 표시 |
| --- | --- | --- |
| 기안 제출 | 지정 검토자 | 검토대기 |
| 검토 완료: 휴가·구매 | 기안자 / 지정 최종 승인자 | 검토완료 / 승인대기 |
| 최종 승인: 휴가·구매 | 기안자 / 해당 업무의 완료 확인 대상 | 승인완료 |
| 구매 처리·수령 | 기안자·수령자 / 업무 담당자 | 배송중 / 배송완료 |
| 재고 검토·발주·수령 | 기안자·발주 담당자·수령자 중 해당 대상 | 검토완료 / 입고대기 / 입고완료 |
| 반려·취소·담당자 변경 | 기안자·새 담당자 등 관련 대상 | 반려·취소·담당자 변경 |

기안자와 최종 승인자가 같으면 검토완료·승인대기를 한 알림에 함께 표시한다. 실제 수신에는 역할별 제한을 적용하며 경리 수신 기준이 우선한다. 알림을 읽으면 미확인 건수가 줄고, 문서 열기에는 현재 조회 권한을 다시 확인한다.

### 10.3 경리 수신 제한

| 문서 관계 | 경리에게 표시하는 알림 |
| --- | --- |
| 본인 휴가·구매 기안 | 본인 문서의 진행 알림 유지 |
| 다른 직원의 휴가원 | 승인완료만 |
| 다른 직원의 구매요청서 | 승인완료 및 배송완료만 |
| 생산 재고 요청 | 본인 기안을 포함하여 모든 단계의 알림 제외 |
| 다른 직원의 취소 문서 | 기존 완료 알림도 화면·미확인 건수에서 제외 |

경리 여부는 경리 문서 조회 권한으로 판단한다. 다른 직원의 검토대기·승인대기·배송중·취소 알림은 경리가 해당 담당자로 지정되어 있어도 표시하지 않는다. 생산 재고를 완료 문서함에서 보는 기능과 알림 제외는 별개로 적용한다.

### 11.1 주요 화면

| 문서 상세·반려함 | 단계별 성명·직급·상태·처리 시각, 이력, 본인 취소, 복사 재기안 |
| 직원별 연차 관리 | 연도·부서 필터, 직급순 현황, 직원별 사용 내역, 수동 수정, Excel |
| 최종 승인 문서함 | 전체·휴가원·구매요청서·생산 재고 요청 탭, 새 문서 색상, 구매 Excel |
| 생산 재고 요청함 | 검토 완료 재고의 발주·입고 상태 |
| 알림함·연차규정 | 이름·직급·문서·상태 알림, 사내 연차규정 열람 |
| 내 계정·관리자 | 본인 비밀번호 변경 / 미분류·부서별 직원 관리·권한·전체 문서·백업 |

### 11.2 가독성과 처리 피드백

글자 크기는 처음 화면과 확대 화면의 중간 수준으로 조정한다. 현재 시안은 본문 약 14.5px, 입력 약 14px와 어두운 글자색을 사용한다. 단계 상태는 “처리기록 있음” 대신 “검토확인”·“승인확인”으로 표시한다.

확인한 단계에는 녹색 체크와 “내가 확인함”을 표시한다. 버튼 처리 중 중복 클릭을 막고 완료 후 결과 팝업을 보여 준다. 삭제·승인 취소·수령 확인 전에는 영향 또는 실행 의사를 확인하는 팝업을 제공한다.

### 11.3 완료 문서함의 새 문서 표시

**주황색 표시 규칙**

기본 탭은 “전체”다. 새 완료 문서가 생기면 전체 탭과 해당 유형 탭의 배경을 주황색으로 강조한다. “새 문서”라는 글자는 붙이지 않는다. 해당 유형 탭을 눌러 확인하면 그 유형만 원래 색으로, 전체 탭을 확인하면 모든 유형을 원래 색으로 되돌린다.

확인 상태는 직원 계정별로 저장한다. 문서함을 처음 열 때 바로 확인 처리하지 않으며, 화면을 보고 있는 동안 새 문서 상태를 갱신한다. 일반 문서 목록은 문서번호·제목·기안자·품명·종류·결재 상태·날짜·물품 상태로 검색·필터한다.

직원은 “연차규정” 메뉴에서 회사가 제공한 표와 규정을 열람한다. 규정은 안내 자료로 관리한다.

| --- | --- | --- | --- |
| 0~1년 | 11일 | 11~12년 | 20일 |
| 1~2년 | 15일 | 13~14년 | 21일 |

제공받은 표를 그대로 안내한다. 구간 경계값이나 22년 초과의 연차를 자동 계산하지 않는다. 실제 직원별 총연차는 경리의 수동 관리값을 사용한다.

### 12.2 잔여 연차·휴가 안내

제공 규정의 잔여 연차 사용 기한은 2026년 12월 31일이다. 잔여 연차 외 휴가의 무급 처리 및 대표이사 사전 허가, 사전 허가 없는 결근과 무단결근 관련 규정도 원문에 따라 안내한다. 이 사용 기한은 자동 연말 초기화를 의미하지 않는다.

위 예외는 규정 열람용이며 경조휴가 자동 면제·자동 일수 부여 기능은 현재 범위에 포함하지 않는다. 일반 연차 신청은 확정된 음수 허용 규칙을 적용한다. 연차 관리 권한자가 규정 내용을 수정하며 수정자·수정일·이력을 남긴다.

### 13.3 접근과 운영 설정

비밀번호는 평문이 아닌 해시로 저장한다. 로그인·직원 활성 상태·업무 권한·문서 관련자를 서버에서 확인한다. 상태 변경과 다운로드 요청에는 위조 요청 방지 기능을 적용한다. 업무 이력은 일반 직원이 임의 수정·삭제할 수 없도록 한다.

실운영 DB 계정과 접속 설정은 소스 및 보고서에 저장하지 않고 실행 환경에서 관리한다. 사내 접속 주소, HTTPS, 서비스 계정, 백업 접근권한, 문서·이력 보관 기간은 NAS 운영 단계에서 확정한다.

**자료 사용**

현재 시안은 가상 직원과 예시 문서를 사용한다. 실제 시험은 개인정보와 회사의 민감한 내용을 제거하거나 바꾼 사본으로 수행한다. 퇴사자 관련 별도 자동 처리 기능과 사후 휴가 기안은 이번 범위에서 다루지 않는다.

## 14. 백업·복구와 배포·시연

시안은 간단히 실행할 수 있게 제공하고, 실운영은 별도의 백업 정책과 복구 시험을 거쳐 NAS에 연결한다.

### 14.1 확정한 백업 운영 권고안

| 항목 | 운영 계획 | 현재 상태 |
| --- | --- | --- |
| 자동 백업 | 매일 업무 종료 후 MariaDB 데이터와 설정 백업 | NAS 예약 작업 연결 전 |
| 보관 기간 | 일별 30일 / 월별 12개월 | 정책 확정, 자동 보관 미구현 |
| 보관 위치 | NAS 저장 + NAS 외부의 별도 장치에 복사 | 장치·경로·접근권한 결정 필요 |
| 복구 절차 | 서비스 중지 → 현재 데이터 백업 → 복원 → 검증 → 재시작 | MariaDB 실복구 시험 전 |
| 점검 | 구축 시 최초 복구 시험, 이후 분기별 점검 권고 | 운영 담당자·일정 확정 필요 |
| 시안 기능 | 관리자 SQLite 수동 백업·복구, 복구 전 현재 DB 보존 | 현재 시안 제공 |

복구하면 백업 시점 이후 변경 내용이 사라질 수 있으므로 복구 범위와 날짜를 확인한다. “백업 파일이 존재함”만으로 복구 가능하다고 판단하지 않고 문서·연차·이력·권한을 실제로 복원하여 비교한다.

### 14.2 Windows 단독 시연

**실행 순서**: ZIP 다운로드 → 폴더 전체 압축 해제 → CompanyApproval.exe 실행

Windows 64비트 PC에서 시스템 Python을 설치하지 않고 실행하는 패키지를 제공한다. 실행에 필요한 구성요소가 폴더에 포함되므로 EXE만 떼어 복사하지 않고 폴더 전체를 옮긴다. 첫 실행에 초기 계정 비밀번호를 설정하고 admin은 첫 로그인에 변경한다.

기존 시안 계정·문서를 유지하려면 실행 전 데이터 폴더 var를 EXE 옆으로 함께 복사한다. 복사한 PC의 데이터는 독립적이며 다른 PC와 자동 동기화하지 않는다. 현재 자료는 시연용이며 실운영 회사 데이터와 연결되어 있지 않다.

### 14.3 NAS 실운영 전환

프로젝트 전용 MariaDB 연결, NAS의 Python·Django 실행 방식, 서비스 시작·재시작, 사내 접속·HTTPS, 백업 예약·별도 복사 및 복구 시험을 순서대로 확인한다. 다수 PC가 하나의 NAS 서버에 접속하여 같은 데이터베이스를 사용하는 것이 최종 운영 목표다.

**검증 한계**

현재 기능 및 단독 실행은 개발 환경과 Wine 환경에서 확인했다. 실제 대상 Windows PC와 NAS·MariaDB에서의 운영 검증은 남아 있다. Windows 단독 시연용 개발 서버를 실운영 서버 구성으로 확정하지 않는다.

### 15.3 현재 검증과 남은 시험

기존 기능 시험 54건이 통과했다. Windows용 실행 구성의 시험 로그도 54건 통과로 확인되며 Chromium 브라우저에서 주요 화면·권한·Excel·이력 흐름을 검증했다. Windows 실행 검증은 Wine을 사용한 결과이며 실제 Windows PC 시험과 구분한다.

실제 업무 인수 시험은 담당자와 익명화된 완료 기록·과거 오류 사례를 비교한다. 결과는 통과·실패·보류·미실행으로 나누어 기록한다. 현재 보고서 작성 과정에서 기능 시험을 다시 실행하지 않았으며, NAS·MariaDB 복구 및 실제 직원 사용성 시험은 아직 수행하지 않았다.

## 17. 추가 변경 계획 — 다음 일괄 반영 대상

### 17.1 홈 오른쪽 결재 진행 상태: 진행 중인 기안만 선택

- 요청일: 2026년 10월 15일.
- 상태: 요구사항 확정 · 계획서 기록만 완료. 코드 수정·실행 패키지 갱신·시연은 보류하고, 이후 요청사항과 함께 일괄 반영한다.
- 목적: 홈의 결재 진행 상태에서 아직 결재가 끝나지 않은 본인 기안을 빠르게 확인한다.

| 구분 | 확정 요구사항 |
| --- | --- |
| 선택 목록 | 본인이 제출한 기안 중 검토대기·최종승인대기 상태만 표시한다. |
| 제외 대상 | 결재완료·반려·취소·임시저장·삭제 기안과 다른 직원의 기안은 표시하지 않는다. 생산 재고의 검토 이후 발주·입고 상태도 결재 진행 중 건수와 선택 목록에서 제외한다. |
| 진행 중 건수 | 선택 목록에 포함된 기안 수와 동일하게 ‘진행 중 N건’으로 표시한다. |
| 기본 표시 | 진행 중인 기안 중 최신 제출 건을 기본으로 선택한다. 목록에서 다른 기안을 선택하면 해당 문서의 결재 단계·상태·상세보기 링크로 바뀐다. |
| 진행 중 0건 | ‘진행 중 0건’과 ‘진행 중인 기안이 없습니다’를 표시한다. 선택 목록·문서 카드·단계·상세보기 링크는 숨기며 완료된 최신 기안을 대신 표시하지 않는다. |
| 선택한 기안의 처리 완료 | 다음 조회 시 진행 중인 다른 기안으로 전환한다. 남은 기안이 없으면 0건 안내를 표시한다. |
| 종료 문서 확인 | 완료·반려·취소 문서는 기존 최근 문서함·내 문서함 등에서 확인한다. 이 변경은 오른쪽 진행 상태 영역에만 적용한다. |

향후 구현 확인 기준: 진행 중 3건이면 목록·건수 모두 3건이어야 하며, 기안 선택 시 단계가 일치해야 한다. 선택한 문서가 최종 승인·반려·취소되면 다음 조회에서 목록에서 빠져야 한다. 진행 중 0건일 때 완료 문서가 표시되지 않아야 한다.

### 17.2 전결규정 관리 — 설계 초안

- 요청일: 2026년 10월 15일.
- 상태: 계획 수립 중. 아래 사용자 방향과 예시는 기록하되, 추천 설계와 미확정 항목은 승인된 규정으로 취급하지 않는다. 코드 수정·실행 패키지 갱신·시연은 진행하지 않는다.
- 목적: 문서 종류, 구매 금액, 기안자 직급에 따라 필요한 결재 단계와 단계별 담당자 자격을 달리 적용한다.

#### 가. 사용자 요청 방향

| 항목 | 요청 내용 |
| --- | --- |
| 규정 관리 | 경리 계정과 admin 계정에서 전결 범위와 직급·금액 조건을 수정할 수 있어야 한다. |
| 구매 금액별 경로 | 소액은 기안→승인, 그보다 큰 금액은 기안→검토→승인 등으로 구분한다. |
| 구매 예시 1 | 10만원 이하: 기안→승인. 사용자가 선택한 3번에 따라 승인자는 주임·대리·과장·팀장·부장 중 선택하며 사원·이사는 제외한다. |
| 구매 예시 2 | 10~100만원: 기안→검토→승인, 이사급까지의 결재선에서 종료하는 방향. 경계 금액과 검토자·승인자 자격은 추가 확정한다. |
| 휴가원 예시 | 부장이 기안하는 휴가원은 검토자를 생략하고, 지정 승인자의 승인으로 완료한다. 승인자의 자격은 추가 확정한다. |
| 후속 작업 | 규정을 계획서에서 계속 정리한 뒤, 추후 사용자 요청 시 여러 변경사항을 함께 구현·시연한다. |

#### 나. 추천 설계 — 아직 확정하지 않은 제안

메뉴명은 ‘전결규정 관리’를 추천한다. 하나의 규정은 ‘적용 조건’과 ‘결재 경로’를 한 행으로 구성하며 금액·직급 조건을 코드에 고정하지 않는다.

| 설정 영역 | 추천 입력 항목 |
| --- | --- |
| 기본 정보 | 규정명, 사용 여부, 적용 문서 종류 |
| 적용 조건 | 구매 총금액의 하한·상한, 기안자 직급(전체 또는 지정 직급) |
| 결재 단계 | 기안→승인 또는 기안→검토→승인 |
| 단계별 자격 | 검토 가능 직급, 최종 승인 가능 직급을 각각 선택 |
| 허용 범위 표현 | ‘부장만’, ‘부장 이상’, ‘주임~부장 중 선택’처럼 실제 허용 직급이 명확하게 보이도록 설정 |
| 확인 | 적용 결과 예시, 등록·변경자와 변경 일시·변경 내용 |

규정 관리 권한과 결재 권한은 분리하는 것을 추천한다. 경리나 admin이 규정을 변경할 수 있어도 해당 문서의 결재자로 자동 지정되는 것은 아니다. 기존 admin의 결재선 제외 원칙은 유지하는 방향이며, 경리 업무 권한은 기존 admin의 직원 권한 관리에서 관리한다.

구매 기준 금액은 기존 구매요청서의 수량×단가인 제품 총가격을 사용하고 배송비를 추가하지 않는 방향을 추천한다. 중복을 피하는 금액 예시는 ‘100,000원 이하’, ‘100,000원 초과~1,000,000원 이하’이다. 이는 경계값 표현에 대한 제안이며 최종 확정 전이다.

직원이 기안을 작성하면 적용될 규정과 결재 단계를 먼저 보여주는 방식을 추천한다. 기안자가 부서를 선택한 다음 규정에 맞는 담당자 후보 중에서 검토자·승인자를 선택한다. 검토 생략 규정이면 검토자 입력을 숨기고, 승인자가 최종 승인해야 완료된다. 규정에 해당한다고 문서 자체가 자동 승인되는 방식은 아니다.

규정 변경은 새 제출 기안부터 적용하고, 제출 시 적용 규정과 결재선을 문서에 보관하는 방식을 추천한다. 이미 진행 중인 문서의 경로는 변경하지 않으며, 임시저장 문서는 제출 시 최신 규정으로 다시 확인한다. 기본 규정과 예외 규정을 명시하고, 예외에 해당하지 않으면 기존 결재 경로의 기본 규정을 적용하는 방향을 추천한다. 유효한 기본·예외 규정이 모두 없거나 여러 예외가 충돌하면 제출 전에 안내하고 경리/admin이 정리하도록 한다. 금액 구간 중복은 등록 단계에서 차단하는 방향을 추천한다.

본인 최종 승인은 검토 생략 경로를 포함해 허용한다. 본인도 전결 허용 직급과 기존 결재자 자격을 충족해야 하며, 기안 제출과 최종 승인 처리는 분리한다. 기존의 선택 자격 제한과 신규 규정이 충돌하는 경우는 별도 설계한다.

검토 생략 휴가원도 최종 승인 시에만 연차를 차감하고, 기존 최종 승인자 취소 시 차감량을 복원하는 방향을 유지한다. 생략된 검토 단계는 대기 상태로 표시하지 않으며 결재 진행 상태·알림·상세 화면도 실제 경로와 일치시키는 것을 추천한다.

#### 다. 다음 논의에서 확정할 항목

1. 부장급까지는 주임~부장 중 선택하는 것으로 확정했다. 이사급까지의 정확한 허용 범위는 후속 확인한다.
2. 구매 10만원 경계의 포함 구간과 중간 구간의 검토자 직급은 후속 확인한다. 100만원 초과 구매의 결재 경로는 사용자 요청으로 보류한다.
3. 휴가원 검토 생략 대상이 부장만인지 부장 이상인지, 이때 최종 승인 가능한 직급은 무엇인지.
4. 검토 생략 시에도 본인 최종 승인을 허용하는 것으로 확정했다. 전결 허용 직급과 기존 결재자 자격은 충족해야 한다.
5. 생산 재고 요청에 새 전결규정을 적용할지, 기존 검토→발주→입고 경로를 유지할지.
6. 추천한 새 제출부터 적용, 규정 충돌·미등록 시 제출 안내, 변경 이력 및 관리 권한 분리 방식을 채택할지.

향후 구현 확인 기준(초안): 금액 경계별 규정 선택, 기안자 직급별 검토 생략, 담당자 자격과 직접 요청에 대한 서버 검증, 규정 변경 전후 진행 문서의 경로 보존, 생략 단계의 화면·알림 일치, 최종 승인 차감·취소 복원을 확인한다. 실제 구현과 시험은 규정 확정 후 별도 수행한다.

### 17.3 기존 결재와 전결규정의 통합 계획 — 설계 제안

- 목적: 별도의 결재 시스템을 중복 구축하지 않고, 기존 문서·결재·연차·권한 처리에서 문서별 결재 경로를 선택하도록 확장한다.
- 상태: 계획서 작성 단계. 다음 내용은 구현 기준을 정리한 설계 제안이며, 미확정 운영 규칙은 별도로 확정한다. 구현·시연은 계속 보류한다.

#### 가. 유지할 기본 흐름과 적용 범위

| 구분 | 통합 원칙 |
| --- | --- |
| 기본 경로 | 휴가원·사무용품 구매의 기존 기안→검토→승인을 기본 규정으로 명시한다. 해당 전결 조건이 있으면 그 경로로 대체한다. |
| 생산 재고 | 기존 기안→검토→발주→입고 경로를 별도로 유지한다. 생산 재고에 전결 적용 여부를 확정하기 전에는 구매 금액 규정을 적용하지 않는다. |
| 규정 선택 | 문서 종류·총금액·기안자 직급으로 적용 규정을 결정한다. 서로 충돌하는 예외 규정은 저장 단계에서 안내·차단하는 방향으로 설계한다. |
| 규정 누락 | 예외에 해당하지 않을 때 명시된 기본 규정을 사용하는 설계 방향이다. 단, 100만원 초과 구매와 적격 승인자 부재 시 처리 방식은 보류 상태이므로 기본 경로 대체나 제출 차단을 확정하지 않는다. 무조건 자동 승인하거나 임의로 단계를 줄이지 않는다. |
| 관리 권한 | 경리·admin의 전결규정 수정 권한과 문서 결재 권한은 구분한다. 규정 관리 권한으로 자기 직급 제한을 우회해 결재할 수 없도록 한다. |

#### 나. 제출 시 경로 확정과 기존 문서 보존

1. 임시저장은 최신 규정의 예상 경로를 보여주되, 제출 시 금액·직급·담당자 자격을 다시 확인한다.
2. 제출 시 적용 규정의 버전, 단계 구성, 담당자와 적용 조건을 문서에 보관한다. 이후 규정·직급 변경만으로 제출 문서의 경로를 다시 계산하지 않는다.
3. 이미 제출된 기존 문서는 기존 담당자·상태·검토 및 승인 기록·연차 차감 기록을 유지한다. 완료 문서를 다시 승인 대기로 돌리거나 연차를 재차 차감하지 않는다.
4. 기존 문서의 경로를 새 구조로 옮길 경우 당시의 경로를 보존하는 전환 계획과 전환 전 백업·검증을 마련한다. 아직 개발·DB 변경은 수행하지 않는다.
5. 담당자 퇴사·비활성 등으로 재지정이 필요한 경우는 기존의 명시적인 담당자 재지정 절차와 구분한다. 규정 변경을 이유로 자동 교체하지 않는다.

### 17.4 승인자의 직급 하한 — 확정 사항

- 요청일: 2026년 10월 15일.
- 확정 내용: 승인자는 기안자와 같은 직급 이상으로 제한한다. 해당 전결규정의 승인 가능 직급 범위와 기존 결재자 자격 조건도 동시에 충족해야 한다.
- 상태: 계획서에만 반영. 코드 수정·실행 패키지 갱신·시연은 보류한다.

승인자 후보는 ‘전결규정에서 허용한 직급’과 ‘기안자와 같은 직급 이상’의 교집합으로 결정한다. 직급 순서는 기존 사원→주임→대리→과장→팀장→부장→이사를 사용한다. 부서 선택 후에도 이 조건을 충족하는 직원만 후보로 표시하며, 향후 구현 시 제출 요청에서도 검증한다.

부장급까지 허용하는 규정(주임~부장)의 예시:

| 기안자 직급 | 승인 가능 직급 |
| --- | --- |
| 사원 | 주임·대리·과장·팀장·부장 — 기존 주임 이상 자격도 적용 |
| 대리 | 대리·과장·팀장·부장 |
| 과장 | 과장·팀장·부장 |
| 부장 | 부장 |
| 이사 | 두 조건을 만족하는 직급 없음 — 예외 처리 방식 추가 확정 필요 |

이 조건은 승인자에 대해 확정한 것이다. 검토자의 직급 하한과 이사급까지의 허용 범위는 별도로 확정한다. 후속 결정에 따라 검토 생략 경로에서도 자격을 충족하면 본인 최종 승인을 허용한다. 후보가 없을 때의 구체적인 처리 방식은 사용자 요청으로 보류한다. 임의로 낮은 직급을 허용하거나 전결 상한을 넘기는 것으로 해석하지 않는다.

향후 확인 기준: 낮은 직급 승인자는 후보에서 제외하고 직접 지정 요청도 거부한다. 같은 직급과 높은 직급은 전결 허용 범위 내일 때만 선택할 수 있어야 한다. 기존에 제출된 문서의 경로를 보존하는 통합 설계 방향은 유지한다.

- 상태: 계획서와 Word만 갱신한다. 구현·실행 패키지 갱신·시연은 계속 보류한다.

| 보완 항목 | 최신 결정 |

| 2. 본인 최종 승인 | 허용한다. 검토 생략 경로에서도 기안자가 전결규정과 기존 결재자 자격을 충족하면 본인을 승인자로 선택할 수 있다. 제출과 최종 승인 동작은 분리한다. |

#### 본인 승인 허용의 범위

본인도 전결규정에서 허용한 직급이어야 하며 admin의 결재선 제외 등 기존 자격을 우회할 수 없다. 예를 들어 주임~부장 허용 규정에 대리가 기안하면 본인 대리를 승인자로 선택할 수 있다. 본인 승인 허용만으로 이사 기안자가 부장 상한 규정을 우회할 수는 없다. 기안 제출만으로 자동 완료하지 않고 본인이 별도로 승인 처리한 시점에 최종 완료하며, 휴가원도 이 시점에만 연차를 차감한다.

검토 생략 경로는 승인 완료 여부를 기준으로 기안자 삭제 가능 여부를 판단하도록 설계한다. 검토 처리 기록이 없다는 이유로 최종 승인된 문서를 삭제할 수 있게 해서는 안 된다. 기존 삭제 방식은 일반 목록에서 숨기고 기록을 보관하는 흐름을 유지하는 방향이다.

#### 규정 적용 미리보기의 의미 — 제안 설명

경리·admin이 규정을 설정하면서 가상의 문서 종류·금액·기안자 직급을 넣어 예상 결과를 확인하는 기능이다. 테스트 결과만 표시하며 실제 기안 제출·결재·연차 차감·알림 발송은 수행하지 않는다.

예시 입력: 구매요청서 / 총금액 80,000원 / 기안자 대리.
전제: 해당 규정이 10만원 이하·주임~부장 허용·검토 생략으로 설정되어 있는 경우.
예상 출력: 기안→승인 / 검토 생략 / 승인 가능 직급 대리·과장·팀장·부장 / 자격을 충족한 본인 승인 허용.

목적은 규정 저장 전에 잘못된 금액 구간·직급 설정을 알아보기 쉽게 하는 것이다. 적용 규정이 충돌하거나 아직 정하지 않은 범위라면 이를 결과에 명시하는 방향을 제안한다. 후속 사용자 결정으로 도입을 확정했으며 구현은 보류한다.

#### 나. 현재 구현과 추가 개발 범위

현재 연차규정 안내와 표시용 근속기간 표에는 경리의 편집 기능이 있지만, 직원별 총연차 자동 산정은 별도 계산식으로 작성되어 있다. 직원복지의 근속기간 표와 경조사비 표에도 고정된 자료를 사용하는 부분이 있다. 따라서 이번 요구사항은 이 화면과 계산을 하나의 편집 가능한 규정 자료에 연결하는 추가 개발이 필요하다. 현재 프로그램에 이미 연동된 것으로 안내하지 않는다.

| 연결 대상 | 설계 방향 |
| --- | --- |
| 근속기간별 산정표 | 기간의 시작·종료와 연차일수를 항목별로 관리하고 구간의 중복·누락을 확인한다. 안내 문장의 자연어를 자동 해석하여 계산하지 않는다. |
| 직원 연차 산정 | 기존 입사일과 해당 연도 1월 1일 기준 근속기간 산정 원칙을 유지하며, 해당 연도에 적용할 산정표에서 총연차를 가져온다. |
| 직원 조회 화면 | 연차규정·직원복지·총연차 계산이 동일한 적용 기준을 참조한다. 적용 연도 또는 적용일 표시를 추천한다. |
| 경조사비 | 입력한 경조사 구분·대상·금액·비고를 직원복지 표에 반영한다. 이번 요구만으로 지급 신청·자동 지급·회계 처리를 추가하지 않는다. |
| 변경 관리 | 변경자·일시·변경 전후 내용과 규정 버전을 보관하는 방향을 추천한다. 일반 직원의 편집 요청은 서버에서도 제한한다. |

#### 다. 기존 직원 연차에 적용하는 방식 — 후속 확정 반영

규정 변경과 기존 직원의 연차 재산정을 구분한다. 아래 미리보기 후 적용 흐름은 후속 사용자 결정으로 확정했다.

1. 경리가 근속기간별 일수표와 적용 시점 또는 적용 연도를 등록한다.
2. 이후 신규 총연차 산정과 매년 1월 1일의 연차 자동 산정은 해당 연도에 유효한 규정을 사용한다.
3. 이미 산정된 올해 연차는 ‘변경 전후 미리보기 → 대상 직원 선택 → 총연차 재계산 적용’ 흐름으로 확정했다. 규정 저장만으로 전체 직원의 올해 총연차를 덮어쓰지 않는다.
4. 재산정 시 기존 사용연차·공용연차 차감·휴가 승인 및 취소 기록을 초기화하지 않는 방향을 유지한다. 잔여연차는 변경된 총연차에서 기존 사용연차를 빼서 계산하며 음수도 기존 원칙대로 허용한다.
5. 경리가 수동 수정한 총연차는 미리보기에서 구분해 표시하고 유지할지 새 규정 값으로 대체할지 확인한 뒤 적용한다.
6. 과거 연도 자료와 종료 문서의 차감 이력을 규정 변경만으로 다시 계산하지 않는 방향을 추천한다. 다음 해부터 적용할지 올해에도 소급할지는 별도 확인한다.

예시: 근속 3년 이상~5년 미만의 총연차 기준을 16일에서 17일로 변경한 경우, 해당 규정이 적용되는 산정은 17일을 사용한다. 이미 올해 총연차 16일·사용 4일인 직원에게 경리가 새 기준을 적용하면 총연차 17일·사용 4일·잔여 13일이 된다. 이는 적용 방식을 설명하기 위한 예시이며 실제 직원 데이터는 변경하지 않았다.

추가 확정할 내용은 규정 적용 시점(올해/다음 해/지정일)과 경조사비 규정 편집 권한을 admin에게도 줄지 여부이다. 올해 기존 연차의 재산정 실행과 수동 수정값 확인 방식은 17.7의 확정 사항을 따른다. 기존 전결규정 관리의 경리·admin 권한과 이번 경리의 연차·복지 편집 권한은 혼동하지 않고 구분한다.

향후 확인 기준: 전결 미리보기와 실제 제출의 규정 판정 일치, 규정 화면과 자동 산정 일수 일치, 기간 경계·적용 연도·수동 수정값 처리, 기존 사용연차 및 취소 복원 보존, 경조사비 저장 후 직원 조회 반영, 일반 직원 편집 차단을 검증한다.

### 17.7 올해 총연차 재산정 방식 — 확정

- 요청일: 2026년 10월 15일.
- 확정: 규정 변경 후 이미 입력된 올해 연차는 경리가 ‘변경 전후 미리보기 → 대상 직원 선택 → 총연차 재계산 적용’ 순서로 적용한다. 규정 저장만으로 올해 직원 전체의 총연차를 일괄 덮어쓰지 않는다.
- 수동 조정된 직원은 미리보기에서 구분하여 보여주고, 경리가 유지할지 새 규정 값으로 바꿀지 확인하여 적용한다.
- 기존 사용연차·공용연차 차감·승인 및 취소 기록을 유지하고, 잔여연차는 적용 후 총연차와 사용연차로 계산한다. 경리의 직원별 총연차·사용연차·잔여연차 수동 조정 권한은 계속 유지한다.
- 실제 규정 적용 연도·지정일과 과거 연도에 대한 적용 범위 등은 별도로 정한다. 이번 결정만으로 모든 과거 연차를 재산정하지 않는다.
- 계획서와 Word만 수정하며 구현·시연은 보류한다.

### 17.8 전체 요구사항 검토 후 보완안 — 도입 확정

아래 네 가지 보완안은 후속 사용자 동의로 도입 방향을 확정했다. 실제 구현과 시연은 계속 보류한다. 보류된 100만원 초과 구매와 적격 승인자 부재 시 처리 방식도 계속 보류한다.

| 권고 항목 | 제안 내용과 이유 |
| --- | --- |
| 규정 적용 연도 표시 | 연차규정에 올해 적용·다음 해 적용을 명확히 표시한다. 직원 조회와 계산에서 어느 기준을 쓰는지 확인하고 과거 연도 자료에 뜻하지 않은 영향을 주지 않도록 한다. |
| 규정 관리 메뉴 정리 | 경리의 규정 관리 화면에서 전결규정·연차규정·경조사비를 구분된 탭으로 제공한다. 일반 직원은 기존 직원복지 화면에서 읽기 전용으로 확인한다. 수정 권한은 항목별로 검사하며, admin의 연차·경조사비 편집 권한은 별도 확정 사항을 따른다. |
| 장기근속 포상 기준 편집 | 장기근속 포상표의 근속연수와 포상 내용을 경리가 수정할 수 있게 한다. 직원복지 안내 표와 해당 연도 포상 대상자 안내가 같은 기준을 사용하도록 한다. |
| 공용연차와 개인 휴가 겹침 안내 | 회사 공용연차 등록 또는 개인 휴가 조회 시 같은 날짜의 승인 휴가를 안내한다. 기존 결정대로 최종 승인자가 개인 휴가를 취소하는 절차는 유지한다. 안내만으로 문서를 자동 취소하거나 연차를 임의로 복원하지 않는다. |

추가로 향후 재산정 설계에서는 미리보기 이후 새 휴가 승인·취소가 발생했을 때 최신 사용연차를 유지해야 한다. 미리보기의 오래된 사용연차로 덮어쓰지 않고 총연차 변경만 반영하도록 검증하는 방안을 권고한다. 실제 적용 기록에는 선택한 직원, 기준 규정, 총연차 변경 전후, 적용자·시점을 남기는 방향이다.

### 17.9 추가 운영 기준 권고 — 아직 미확정

- 앞서 17.8의 네 가지 보완안은 사용자 동의로 도입 방향을 확정했다. 다음 세 항목은 새로운 제안이며 도입을 확정하지 않는다.
- 기존 보류 항목(100만원 초과 구매, 적격 승인자 부재 시 처리)은 그대로 유지한다. 지금은 계획서만 수정하며 코드·실행 패키지·데이터를 변경하거나 시연하지 않는다.

| 추가 제안 | 권장 기준과 확인할 점 |
| --- | --- |
| 검토자와 승인자 사이의 직급 관계 | 검토가 있는 문서는 ‘기안자 직급 ≤ 검토자 직급 ≤ 승인자 직급’을 추천한다. 같은 직급을 허용하고 전결규정의 단계별 허용 직급과 기존 자격도 동시에 만족해야 한다. 검토 생략 문서는 이미 확정한 기안자≤승인자 조건을 사용한다. 검토자가 이사인데 승인자가 부장인 경로 등을 예방하려는 제안이다. 후보 부재 시의 대체 처리 방식은 이번 제안으로 확정하지 않는다. |
| 입사일 미등록 직원 구분 | 입사일이 없는 직원은 ‘입사일 미등록·자동산정 대기’로 표시하고 경리 화면에서 확인할 수 있게 한다. 임의의 입사일이나 0년차로 총연차를 자동 계산하지 않고 기존 수동 입력값은 유지하는 방향을 추천한다. 신규 휴가 제출 제한을 이번 제안만으로 추가하지 않는다. |
| 중도 입사자의 공용연차 대상 기준 | 공용연차 휴무일이 입사일보다 앞서면 해당 직원의 차감 대상에서 제외하는 방향을 추천한다. 예를 들어 7월 1일 입사 직원에게 5월 회사 휴무를 차감하지 않는다. 입사일 이후 이미 등록된 휴무의 반영과 입사일 변경 시 기존 차감의 조정 방법은 별도로 정해야 한다. 기존 등록 즉시 차감·삭제 시 복원 원칙과의 일치 여부도 함께 설계한다. |

이 제안들은 실제 결재 자격과 연차 계산에 영향을 주므로 사용자 확정 후 상세 규칙과 시험 기준을 정한다. 현재 계획의 미확정 사항을 임의로 메우거나 실제 시스템에 적용하지 않는다.
