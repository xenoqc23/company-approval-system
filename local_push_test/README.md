# 로컬 PC 알림 테스트 v4 · Chrome / Edge / PC 로그인 미결 알림

NAS 업데이트 파일이 아닙니다. 이 폴더를 NAS에 올리거나 실제 결재시스템에 덮어쓰지 않습니다. 실제 계정·문서·DB·NAS 설정을 사용하지 않습니다.

## 확인할 때까지 유지하는 알림

4번의 **PC 켜기 알림 지금 시험**과 Windows 로그인 알림은 `reminder` 형식과 **확인** 버튼을 사용합니다. 자동으로 사라지는 일반 배너 대신, 사용자가 확인 또는 닫기를 누를 때까지 유지하도록 구성합니다. 소리는 내지 않습니다. Windows 버전·알림 설정·정책에 따라 표시가 제한될 수 있어 실제 PC에서 확인해야 합니다.

**확인은 알림만 닫습니다. 문서를 승인하거나 처리완료로 바꾸지 않습니다.** 미결 문서는 별도로 처리완료해야 다음 로그인 알림에서 제외됩니다.

2~3번 Chrome·Edge 알림에도 ‘확인’ 버튼과 `requireInteraction` 유지 요청을 전달합니다. 이 요청은 브라우저·Windows가 무시할 수 있으므로, 브라우저 알림에 무조건적인 유지 시간을 보장하지 않습니다. 알림 본문을 누르면 테스트 화면을 열고, 확인 버튼을 누르면 알림만 닫습니다.

## 알림이 보이지 않을 때

기존 검은 실행 창을 닫고 v4를 새 폴더에 압축 해제해 실행합니다. 이전 폴더에서 자동 알림을 등록했다면 기존 `DISABLE_AUTO_START.bat`으로 해제합니다. 즉시 표시 시험을 확인한 뒤 새 폴더에서 자동 실행을 등록합니다.

실패하면 **runtime / payload / notifier / settings / xml / show** 단계와 Windows 오류 코드를 표시합니다. **Windows 알림 상태 확인**은 현재 설정과 API 응답을 읽으며 알림·정책·자동 실행 설정을 변경하지 않습니다.

1. 4번의 **가상 미결 2건 만들기 → PC 켜기 알림 지금 시험**을 누릅니다.
2. 팝업과 알림 센터에 모두 없으면 **Windows 알림 상태 확인**을 누릅니다.
3. **확인 결과 복사**를 눌러 결과를 전달합니다. 최근 PC 로그인 알림 실패 메시지도 함께 포함합니다.

브라우저 알림 목록에 등록됐다는 것은 실제 Windows 배너 표시 확인과 다릅니다. 화면에서 이 상태를 구분해 보여 줍니다.

## 시작

1. ZIP을 PC의 새 폴더에 **모두 압축 해제**합니다. ZIP 안에서 바로 실행하지 않습니다.
2. `START_TEST.bat`을 더블클릭합니다. 처음에는 이 폴더 안에 테스트용 `.venv`를 만들고 `pywebpush`를 설치하므로 인터넷 연결과 잠시 기다리는 시간이 필요합니다.
3. 브라우저가 열리면 화면의 1~3번은 웹 푸시, **4번은 PC 로그인 미결 알림**을 시험합니다. 주소는 **http://127.0.0.1:18110/** 입니다.
4. 브라우저가 안 열리면 Chrome 또는 Edge 주소창에 위 주소를 직접 붙여넣습니다.

Python이 없으면 [Python 공식 Windows 설치 페이지](https://www.python.org/downloads/windows/)에서 **Python 3.12**를 설치합니다. 설치할 때 **Add python.exe to PATH**를 체크하고 실행 파일을 다시 엽니다. Python 3.10 이상을 지원하며 관리자 권한으로 실행할 필요가 없습니다.

## Chrome 설정

주소창에 `chrome://settings/system`을 붙여넣고 **Chrome 종료 후에도 백그라운드 앱을 계속 실행**을 켭니다.

## Edge 설정

주소창에 `edge://settings/system`을 붙여넣고 **Microsoft Edge가 닫혀 있을 때 백그라운드 확장과 앱을 계속 실행**을 켭니다.

버전에 따라 항목 이름이나 위치가 다르면 설정에서 ‘백그라운드’를 검색합니다. 윈도우 **설정 → 시스템 → 알림**에서 알림을 켜고 **방해 금지**는 끕니다. **Win + N**으로 알림 센터도 확인할 수 있습니다. Chrome과 Edge는 알림 권한과 연결을 각각 설정해야 합니다.

## 테스트 순서

1. **알림 허용하고 연결 → 허용**을 선택합니다.
2. **지금 윈도우 표시 확인**을 눌러 PC가 알림을 표시하는지 확인합니다. 이 버튼은 인터넷 푸시 수신을 시험하는 버튼은 아닙니다.
3. **30초 뒤 결재 요청 알림**을 누르고 먼저 브라우저를 켜 둔 상태에서 확인합니다.
4. 다시 시험할 때는 버튼을 누른 뒤 **해당 브라우저의 모든 창을 닫고** 30초 정도 기다립니다. **검은 실행 창은 계속 켜 둡니다.** 실행 창이 로컬 발송 서버입니다.
5. 다시 테스트 주소를 열면 발송 상태를 볼 수 있습니다. 결재 완료 예시도 같은 방법으로 시험합니다.
6. 다른 브라우저에서도 같은 주소를 열고 별도로 허용·연결해 시험합니다. 테스트를 누른 브라우저에만 발송합니다.

표시하는 직원과 문서는 가상 예시입니다. 서버가 켜져 있으면 브라우저 페이지를 닫아도 30초 후에 서버가 Google 또는 Microsoft의 해당 브라우저 푸시 서비스로 실제 암호화 알림을 보냅니다. 서비스에 전달됐다는 결과는 PC에 표시됐다는 확인과 다릅니다. 실제 표시 여부는 사용 중인 PC에서 직접 확인해야 합니다.

**모든 창 닫기**, **브라우저 프로세스 완전 종료**, **PC 종료**는 서로 다릅니다. 백그라운드 설정을 켜도 브라우저 버전·기업 정책·윈도우 상태에 따라 창을 닫은 뒤 수신이 제한될 수 있습니다. 작업 관리자에서 브라우저 프로세스를 종료했거나 PC가 꺼져 있으면 즉시 수신을 보장하지 않습니다. 창을 켰을 때와 닫았을 때를 비교하는 것이 이 테스트의 목적입니다.

## 안 보이면

- 먼저 ‘지금 윈도우 표시 확인’, 알림 허용, 방해 금지, 알림 센터를 확인합니다.
- ‘결과 확인’에서 **연결 실패 / 발송 실패**라면 인터넷과 회사 보안 프로그램의 푸시 연결 제한을 확인합니다. 보안 기능을 끄지 않고 오류 내용을 확인합니다.
- **푸시 서비스에 전달**인데 PC 팝업이 없으면 브라우저·윈도우 표시 설정을 확인합니다. **창을 열 때만 표시**되면 브라우저 백그라운드 수신 조건을 확인해야 합니다.
- ‘확인 결과 복사’를 눌러 브라우저·권한·연결·발송 결과를 전달할 수 있습니다. 이 결과에는 구독 주소나 암호화 키를 넣지 않습니다.

## 종료와 보관

검은 실행 창에서 **Ctrl+C**로 종료합니다. 이때 대기 중이던 테스트와 메모리의 구독 정보는 사라집니다. 다시 실행하면 기존 브라우저 알림 권한과 구독으로 재연결할 수 있습니다. 완전히 해제하려면 화면의 **이 브라우저 연결 해제**를 누릅니다.

이 폴더 안의 `.local-test-data`에는 테스트용 비밀키와 가상 미결 문서·알림 요청 이력, `.venv`에는 실행에 필요한 라이브러리가 보관됩니다. 이 두 폴더를 공유하지 않습니다. 배포 ZIP에는 이 파일들을 포함하지 않습니다. 기존 NAS·결재 프로그램 파일은 변경하지 않습니다.

## 추가: PC를 켰을 때 미결 문서 알림

날짜가 아니라 **아직 처리하지 않은 문서가 있는지** 확인하는 테스트입니다. 같은 날 PC를 껐다 켜도 Windows에 로그인하면 다시 알려줍니다. 전날·며칠 전 문서도 미결이면 포함하고, 처리완료한 문서는 제외합니다. 알림을 보여줬다는 이유만으로 문서를 처리완료로 바꾸지 않습니다.

4번만 시험할 때는 Chrome·Edge의 웹 푸시 연결이나 백그라운드 설정을 먼저 할 필요가 없습니다. Windows의 이 테스트 앱 알림 허용만 확인합니다.

1. 테스트 폴더를 계속 보관할 위치에 압축 해제하고 `START_TEST.bat`을 실행합니다.
2. 화면의 **4번 PC를 켰을 때 미결 문서 알림**으로 이동합니다.
3. **가상 미결 2건 만들기**를 누릅니다. 홍길동 대리의 휴가원, 김가영 과장의 구매요청서 두 건을 PC에 저장합니다. 이 버튼을 다시 누르면 두 가상 문서를 미결 상태로 다시 만듭니다.
4. **PC 켜기 알림 지금 시험**을 눌러 재부팅 없이 같은 알림을 시험합니다. Windows 알림에서 **사내결재 PC 알림 테스트**가 허용되어 있어야 하며 방해 금지도 확인합니다.
5. **Windows 로그인 자동 알림 켜기**를 한 번 누릅니다. 현재 Windows 사용자에게만 자동 실행을 등록합니다. 관리자 권한이나 브라우저 실행이 필요하지 않습니다. Windows **설정 → 앱 → 시작 프로그램**에서도 사용 상태를 확인합니다.
6. 작업을 저장한 뒤 브라우저와 검은 실행 창을 닫고 PC를 재시작해 Windows에 로그인합니다. 약 **15~30초 뒤** 오른쪽 아래 또는 알림 센터(Win + N)를 확인합니다.
7. 다시 `START_TEST.bat`을 열고 목록에서 한 문서를 **처리완료**합니다. 다음 알림은 남은 한 건만 포함해야 합니다. 두 문서를 모두 처리완료하면 로그인 알림을 띄우지 않습니다.

로그인 알림은 브라우저·검은 실행 창이 없어도 별도의 짧은 프로그램이 실행되어 Windows에 표시를 요청하고 종료합니다. 인터넷·NAS·로컬 HTTP 서버를 사용하지 않고, **이 PC에 저장한 가상 문서**만 읽습니다. 실제 NAS의 미결 문서를 읽는 기능은 이 로컬 테스트에 포함되지 않습니다. PC가 꺼져 있을 때 팝업이 뜨는 것이 아니라, **PC를 켜서 사용자 계정에 로그인한 뒤** 알려줍니다.

등록 위치는 현재 사용자의 Windows 시작 프로그램(`HKCU\Software\Microsoft\Windows\CurrentVersion\Run`의 `XenosysLocalPendingTrial`) 한 항목입니다. 알림 표시 이름도 현재 사용자에게 등록합니다. 다른 앱의 시작 항목이나 브라우저 설정·보안 정책을 변경하지 않습니다. 폴더를 옮기거나 이름을 바꾸면 자동 실행 경로가 달라지므로 먼저 끄고 새 위치에서 다시 등록합니다.

### 자동 알림 끄기

화면의 **자동 알림 끄기** 또는 폴더의 **DISABLE_AUTO_START.bat**을 실행합니다. 브라우저나 테스트 서버가 닫혀 있어도 해제 파일을 실행할 수 있습니다. 현재 사용자의 이 테스트 시작 항목만 지우며 가상 문서는 유지합니다.

Windows에 표시를 요청했다는 기록은 실제 배너가 화면에 떴다는 확인과 다릅니다. Windows가 시작 앱을 차단했거나 알림·방해 금지·회사 정책으로 표시를 제한하면 결과 화면에서 확인해야 합니다. 자동 검증은 문서 저장·재실행·완료 제외·요청 전달을 확인하며, 실제 Windows 로그인과 팝업은 테스트할 PC에서 확인합니다.
